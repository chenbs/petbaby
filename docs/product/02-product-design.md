# 产品设计文档

版本：v3.1 ｜ 更新：2026-07-21

## 1. 产品定位

> 上传宠物照片，一分钟生成好玩、好看、值得珍藏的宠物创意作品。

- 对用户：最低门槛的宠物内容创作工具（拍完就能玩，玩完就能晒）。
- 对产品：以"玩法"为获客钩子，以"宠物档案 + 照片库"为长期资产。
- 对商业：单次付费为主（高清/无水印/高级玩法），纪念线走高客单，后期叠加会员与实体。

## 2. 目标用户

### 用户 A：晒宠用户（走量，获客基本盘）

- 20-35 岁女性为主，小红书/朋友圈活跃，日常拍猫狗。
- 触发场景：刷到爆款玩法（"我也想给我家猫做一个"）、宠物生日、节日。
- 付费能力：9.9-29.9 元/次，冲动消费，决策时间 < 1 分钟。

### 用户 B：宠物离世/晚年用户（走客单价，利润基本盘）

- 强烈需要体面的纪念载体，付费意愿极强、几乎不比价。
- 付费能力：39.9-299 元，决策靠情绪共鸣而非功能对比。
- 设计要求：入口克制（不在首页强曝光），流程安静，无营销打扰。

不服务：B 端商家（阶段 4 前）、泛社交用户。

## 3. 产品形态

- **微信小程序**（主体：个体工商户；类目：工具-图片处理，避开社交/社区类目）——承载完整流程：上传、生成、支付、作品管理。
- **H5 分享页**——作品对外展示 + 互动类玩法的体验载体 + 转化入口（"给我的宠物也做一个"）。无需登录可浏览。
- 不做 App、不做 PC 网站。

## 4. 核心架构：壳 + 玩法插件

这是本产品最重要的设计决策。平台 = 一个稳定的壳 + 可热插拔的玩法插件。

### 4.1 壳（不变部分，详见 03-features-shell.md）

登录、宠物档案、照片上传、生成任务框架、支付、作品库、H5 分享页、埋点、免费额度与防刷。

### 4.2 玩法插件（可变部分，详见 04-plugins-playbook.md）

每个玩法用统一的插件描述定义，新玩法上架不改壳代码：

```yaml
plugin:
  id: pet-id-card                # 唯一标识
  code: PL-01                    # 运营编号
  name: 宠物身份证               # 展示名
  category: layout               # layout / ai-image / interactive / video / memorial / report
  input:
    photos: {min: 1, max: 1}     # 需要几张照片
    profileFields: [name, species, birthday]  # 需要的档案字段
  generator:
    type: html-template          # html-template / image-api / h5-theme / ffmpeg / report
    template: id-card-v1         # 模板或管线标识
  pricing:
    unlockPrice: 9.9             # 单次解锁价
    label: 高清无水印
  output:
    formats: [image]             # image / pdf / h5 / video
  status: idea | testing | live | archived   # 赛马状态
```

### 4.3 五类执行管线（后增第六类，见表下）

| 类型            | 实现                                              | 边际成本        | 输出       | 典型玩法         |
| ------------- | ----------------------------------------------- | ----------- | -------- | ------------ |
| html-template | 当前以 SVG + Sharp 生成图，pdf-lib 生成 PDF；类型名为兼容既有清单保留 | ≈0          | 图/PDF    | 证件、海报、画册、纪念册 |
| image-api     | 主备 HTTP Image Provider + 模型/成本快照                | 0.1-0.5 元/次 | 图        | AI 宠物肖像      |
| h5-theme      | 前端互动页面 + 服务端 15 秒导出                             | ≈0          | H5 链接/视频 | 星尘互动页、星尘纪念页  |
| ffmpeg        | 独立 Worker 按冻结项目快照合成                             | 机器资源成本      | 视频       | 宠物记忆短片、纪念视频  |
| report        | 服务端聚合宠物年度数据并版本化渲染                               | ≈0          | 图/分享页    | 年度铲屎官报告      |

**第六类：健康分诊线**（`health_sessions`，不走玩法 manifest）。产出不是作品：不进 `works`、不可分享、额度独立。定位是「症状记录 + 紧急度分级 + 就医准备」，**做分诊不做诊断**——这是法律要求不是产品选择（《动物诊疗机构管理办法》要求线上诊疗须由持证机构的备案执业兽医师开展）。十条红线见 `16-竞品分析与产品复盘.md` 3.8。

设计约束：

- image-api 类必须"生成 4 选 1"+ 付费前预览，翻车成本留在免费层。
- h5-theme 类必须提供服务端 15 秒展示视频出口，否则无法在小红书传播。
- 所有输出带产品水印与小程序码，付费去除。**免费玩法（`unlockPrice: 0`）的正式产物也带水印** —— 水印在那里不是付费墙而是传播载体，不覆写会让免费玩法拿到比付费更干净的图。
- **AI 生成标识与营销水印命运相反**：前者付费也必须保留（《人工智能生成合成内容标识办法》第四条要求导出文件也带），后者付费移除。标识只对 `image-api` 类打——排版类与视频类不是生成合成内容，打标属错误标注。

## 5. 信息架构

小程序底部导航（3 tab，保持极简）：

- **玩法**（首页）：玩法卡片瀑布流，按热度/节日排序；顶部轮播当季主推。
- **作品**：我的作品库（可重新编辑、分享、购买高清）、宠物档案入口。
- **我的**：订单、免费额度、客服、设置与隐私。

纪念线入口：宠物档案页内"纪念空间"入口 + 玩法页不置顶的独立分区，不做首页强曝光。

核心用户流程：

```
首页选玩法 → (首次)建宠物档案30秒 → 上传照片 → 生成(<60秒,排队可见)
→ 免费预览(低清水印) → 付费解锁 → 下载/分享H5 → 分享页访客 → "我也做一个"
```

## 6. 定价体系

> 本节是阶段一的原始定价设想，**已被后续改造大幅修正**。当前实际定价见 `15-功能入口清单.md` 第四章（玩法解锁价与分档规则）与 `domain/pricing.ts`、`domain/membership.ts`。主要偏离：PL-01 与 PL-15/PL-23 转免费（免费玩法承担传播载体职责，产物仍带水印）；PL-03/PL-19 改为**按积累量三档**而非按主题定价；会员改为年度 ¥128 单档（v4），月度已下架。

| 层级              | 内容                     | 定价（原始设想）        |
| --------------- | ---------------------- | --------------- |
| 免费层             | 每天 1 次低清带水印生成（全玩法通用额度） | 0               |
| 基础解锁            | 排版类玩法高清无水印             | 9.9-12.9 元/次    |
| 溢价解锁            | 生日/节日主题、生图类玩法          | 19.9-29.9 元/次   |
| 纪念线             | 粒子纪念页 / 纪念册 PDF        | 39.9-69 元       |
| 实体（阶段3）         | 精装画册、台历（代发）            | 129-299 元       |
| 会员（阶段3，复购数据支撑后） | 模板全解锁 + 每月 N 次高清       | 19 元/月 或 98 元/年 |

定价原则（仍然适用）：先做高单次付费转化（目标 ≥ 5%），不提前用低价会员稀释；生图类定价必须 ≥ 10 倍 API 成本。

后续加的两条原则：**积累免费、交付物付费**（凡「单次输入 → 单次输出 → 结束」的功能都在抖音射程内，不能作主付费点）；**会员只卖已实现兑付的权益** —— `domain/membership.ts` 的 `describeEntitlements` 是权益白名单，加权益必须同时补文案，否则会建出「可售但零可兑付」的套餐。

## 7. 设计原则

1. **一分钟出结果**：任何玩法从选中到预览 ≤ 60 秒，超时必须有进度感知。
2. **晒图优先**：输出物的第一形态是"适合发小红书的图/视频"，其次才是保存。
3. **私密默认**：档案与作品默认仅自己可见，分享由用户主动触发，分享链接可关闭。
4. **照片不整容**：排版类玩法照片原样使用（滤镜边框除外），规避"不像"投诉；生图类明确标注 AI 生成。
5. **尊重悲伤**：纪念线无弹窗、无推销、无热度榜（全局约束，见 roadmap 第 3 节）。
