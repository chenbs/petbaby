### 2.1 素材已到齐（2026-08-06 完成）

7 张必需素材全部就位，**A2/A3/A4 已清**。实测记录：

| 槽位                                      | 来源                       | 产物                    | 备注                                    |
| --------------------------------------- | ------------------------ | --------------------- | ------------------------------------- |
| `scene-yard`                            | 用户提供 2496×3744 PNG       | 1.56MB JPEG           | **spec 从 1200×1800 上调到 2496×3744**，见下 |
| `prop-grass` / `prop-bowl` / `prop-bed` | 用户提供 1024×1024 透明 PNG    | 各 0.68–0.80MB         | spec 从 512 上调到 1024（底图变大后物件跟着放大）      |
| `item-set`                              | 用户提供 2048×880 透明 PNG     | 0.73MB                | spec 改 **2046×880** —— 宽必须能被 3 整除     |
| `pet-sample`                            | 用户提供 1200×1600 品红底       | 1.35MB，抠图后透明 85.9%    | 残留 0.034%，叠草地无色环                      |
| `hero-island`                           | **图生图**从 `scene-yard` 派生 | 0.32MB JPEG 1600×1000 | 见下                                    |

合计 **6.19MB**：无单张超端上 `MAX_ENTRY_BYTES`（2MB），总量在 `BUDGET_BYTES`（8MB）内。

**`hero-island` 走图生图而不是文生图**（用户判断，实施采纳）：入口卡与进岛后的画面
紧挨着看（点卡片即进岛），而同一句风格提示词两次调用的笔触、描边粗细、色相都会漂移 ——
这批素材的判据是人眼比对，靠文字复述风格拿不到「同一个地方」。实现是
`prompts.mjs` 的 `fromScene: true` + `generate.mjs` 走 `edit()`，
并开 `inputFidelity: "high"`。生成 3 张候选取第 2 张（细节还原度与第 3 张接近，
但顶部天空留白更足 —— 卡片上要压文字）。**底图缺失时直接失败不回落文生图**：
静默回落会产出风格接近但不同源的卡图，而那种偏差只有并排看才发现。

**三处 spec 修正**（都会静默出错，所以记下来）：

1. **`scene-yard` 1200 → 2496。** 原值在最苛刻机型上偏软：Pro Max 是 430 CSS 宽 ×
   dpr3 = 1290 物理像素，底图铺满时密度只有 **0.93 < 1**。而 `fitTo()` 会
   `.resize(spec.width, ...)`，**不改 spec 的话用户给的 2496 会被缩回 1200**，等于白给。
2. **`item-set` 1536×512 → 2046×880。** 宽度必须能被 3 整除（端上按 1/3 切取
   `spriteIndex`）：`2048/3 = 682.67`，切片边界落在半像素上，表现是每格边缘糊一条
   或串进隔壁道具。高度保留 880 不压成正方 —— 原图每格比例 0.776，按 512（格比 1.0）
   裁会**切掉道具上下各约 11%**。
3. **三张 prop 512 → 1024。** `propRect()` 按 `sizeRatio × 底图宽` 定尺寸，
   底图翻倍后物件的实际绘制尺寸跟着翻倍，512 会被放大到糊。

**抠图判据的口径也修了一处。** 原先算「全部前景里品红度 >10 的占比」，
而这套画风有闭合描边，描边与背景之间必然有一圈抗锯齿像素（品红度 10–29，
既不够进羽化带又高于可见下限），于是全被记成残留 —— 实测 858 个残留里
**856 个（99.8%）贴在边缘 3px 内**，内部只有 2 个且是中性灰粉。
排除 1px 一圈后从 **0.319% 降到 0.034%**，而产物叠在真实草地色上目视无粉边。
**没有靠调低 `KEY_OPAQUE_BELOW` 去凑这个数** —— 那是实测定的抠除阈值，
降它能让残留归零，但代价是把描边像素改成半透明（实测降到 10 时如此）。
判据错了就修判据。两份实现（`cutout.ts` ↔ `upload-island.mjs`）已同步，比对测试通过。

**另记一条踩坑**：`sharp` 的 `png({ effort: 10 })` 与 `palette: true` **都是有损的**
（会做调色板量化）。实测立绘的 alpha 层级从 81 级掉到 23/10/8 级、最大色差 113 ——
那正好毁掉抠图羽化的过渡带，边缘会变硬出现贴纸感。体积再紧也不能用它们压这批图。
`effort` 这个参数名听起来像「更努力地无损压」，实际会启用量化 —— **按参数名推断行为会踩坑，
必须逐像素比对验证**。

### 2.3 关于「生图接口支持透明底直出」

用户提出接口支持直出透明 PNG。**工具链已经优先走这条路**（`generate.mjs` 的
`transparent` 分支：先试 `background: "transparent"`，拿不到 alpha 才回落品红底），
所以这个能力一旦可用会自动生效，不需要改代码。

但**当前模型上它不成立**，且失败方式是最坏的那种 —— 代码注释已记录两种实测表现：

- packy：以 4xx 直接拒绝 `background=transparent`（**这种是安全的**，能被 catch 住）；
- lingsuan（当前在用的 `gpt-image-2`）：**返 200 却不给 alpha**。

第二种危险得多：只 try/catch 的话它静默通过，抠图阶段面对一张不透明的图无从下手，
端上表现是立绘带一块底色方块。所以 `generate.mjs` 在拿到成功响应后**还要再验一次
`hasAlpha()`**，不达标才回落品红 —— 本轮跑 `pet-sample` 的三张候选时，
三次全部打印了「接口接受 background=transparent 但产物无 alpha，回落品红底」。

**结论**：品红抠图仍是主路径，不能撤。等模型侧真能直出 alpha 时这条链路会自动短路，
届时 `residuePercent` 会恒为 0、`keyed: false`（走「已带 alpha 跳过抠图」分支）。

### 2.4 顺带修掉的一处「测试超时假象」

回填素材后 `pnpm check` 挂了 3–4 条，而 `pnpm test` 全过 —— 差别在 `--coverage`。

根因：这几条用例（立绘四选一、纪念册多页 PDF、定价分档端到端）走真实 PGlite +
真实 sharp 光栅化，本身就要 1.5–6 秒，而 v8 插桩再放大约 3 倍，于是越过默认上限。
`vitest.config.ts` 已加 `testTimeout: 30_000` 与 **`hookTimeout: 30_000`**。

**两个都要加**：`testTimeout` 管不到 `beforeEach`，而那几条的 `beforeEach` 要
`resetDatabaseForTest()`（TRUNCATE 三十余张表 + 重跑迁移）—— 只加前者时失败会从
「用例超时」变成 `Hook timed out in 10000ms`，看起来像是修了一个又冒出一个。

**这类失败最容易误判**：报的是 5000ms/10000ms 超时，完全不提插桩，
读起来像死锁或真实缺陷。判据是「`pnpm test` 过而 `pnpm test:coverage` 挂」。
另外实测确认**不是我把抠图挪到生成时造成的**：`cutoutSprite` + `applyAiLabel`
单张约 60ms，4 张候选合计 240ms，与秒级超时不在一个量级。

## 3. 未验证项（代码已完成，真实条件下没跑过）

细项在 `../operations/05-release-checklist.md` 的「宠物小岛验收」，不在此复写。
**最容易被误认为「已经验过」的四条：**

- **抠图端到端跑的是降级分支。** 集成测试里 `LocalImageProvider` 输出纯色 SVG 不是品红底，
  于是走「覆盖率不够 → 原样透传」。真抠图只在单测里成立（单测已用真品红图覆盖，见 26 号文缺陷 1）。
  **样板宠物那张已用真实产物验过**（2026-08-06：残留 0.034%、叠真实草地色目视无粉边、
  白胸兜与耳内绒毛完整），但那是**离线工具**的产物；**运行时 `cutout.ts` 处理用户上传的立绘
  仍未在真实生图产物上跑过** —— 配真实凭据后要专门看一次色环与绒毛。
- **立绘相似度没人看过。** 判据与 PL-10 相同：拿到「某只橘猫」而不是「我家那只」，这个玩法就是坏的。
  只能人眼判断。样板宠物摩奇的画风已定（`pet-sample.png`），它是提示词的风格靶子 ——
  用户宠物的产物要长成同一画风，否则引导页示意与实际产物不是一套东西。
- **雨/雪档帧率没实测。** 测试只能证明排帧行为（静止不排、天气档持续排、上限 30fps、
  降级档过渡期间不多画一层），证不出低端安卓实际跑到多少帧。**跨档过渡的 2.4 秒是全功能里最重的一帧**
  （两档粒子同时在场，基准机型峰值 120+80），要在**基准机型**上看而不是低端机。
- **16 种昼夜×天气的观感没人看过。** 门禁 16 算的是对比度（一个数字），读起来舒不舒服是另一回事。
  重点看「雪+昼」（最亮）与「雨+夜」（最暗）两端。过渡只能在段边界（05/09/13/17/21）前后真机停留 ——
  改系统时间能凑档位但凑不出过渡。

## 4. 本轮复核结论（2026-08-06 第二轮）

第一轮复核（22 号文 11.13）之后又做了一轮，**查出 6 处「不报错但功能错」的缺陷，全部已修**。
逐条的现象、根因、验证方法在 26 号文。这里只留结论性的一句：

**「代码写完了」「测试全绿」与「按判据逐条核过了」是三件事。** 这 6 处缺陷全部发生在
测试全绿的代码里 —— 其中最严重的一处（立绘被打两次 AI 标识、第一个标识被抠成半透明脏块）
连抠图自己的判据都是干净的：`clearedPercent` 72.6%、`keyed: true`、残留统计正常，
因为脏块落在羽化带里、不进任何一项统计。

**这一轮的教训与上一轮同源，但更进一步**：上一轮是「判据能自动化验却没验到那一层」，
这一轮是「判据本身通过了，而判据没覆盖那个后果」。所以本轮每修一处都补了能拦回归的门禁，
并逐个实测「回退到旧实现会失败」—— 不能只验修好了，还要验门禁真的拦得住。

## 5. 岛的 E2E（本轮新增）

`apps/platform/tests/e2e/island-flow.spec.ts`，3 条，走 API 而不是页面
（岛只有小程序端，9.4 第 10 项拍板不做 Web 端同步实现）。

覆盖的是**单测拿不到的那一层**：真实 HTTP + 真实会话 + 路由守卫 + envelope 包装。
单测直接调服务层函数，`assertTrustedMutation`、`requireUserId`、`enforceRateLimit`、
`routeError` 这四样根本没跑，而端上看到的正是这一层。

| 用例                          | 守什么                                                                                                                                          |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 建岛 → 入岛 → 快照 → 采集 → 摸摸 → 日记 | 整链通，且快照的 8 个关键键齐备（`serverDate` / `limits` / `today` / `anchors` / `assets` / `milestones` / `pet.createdAt` / 日记游标）。**`petId` 被真的读到**（原缺陷所在） |
| `memorial` 宠物不进岛            | 三个入口（入岛 / 立绘 / 可选列表）都拦，且错误码经 envelope 后端上收到的是 `ISLAND_UNAVAILABLE_MEMORIAL`                                                                  |
| 拒绝非 JSON 写入                 | 三条写路由都返回 415 —— 表单提交是 CSRF 的主要入口形态                                                                                                           |

**刻意不测立绘生成**：本地走 `LocalImageProvider`（纯色 SVG、非品红底），抠图必然落到降级分支，
而那条路径的断言在 `island/avatar.test.ts` 里更严格（含产物 alpha 与 AI 标识底衬的逐像素检查）。

**写 E2E 时踩到一个自己造成的坑，记下来免得重犯**：全站共用一个 demo 用户，而 `createPet`
只在「该用户还没有宠物」时置 `is_default`。本文件名字母序在 `main-flow` 之前，于是它建的宠物
顶掉了主链路那只，Web 时间线页按 `isDefault || pets[0]` 取宠物，就显示了一只没有照片的 ——
表现是「陪伴第 N 天」在而「第 N 天」那条不见。**已改为有则复用、建了就删**，并连跑两次确认可重复。
