| # | 问题 | 结论 |
| --- | --- | --- |
| D1 | 「年度健康记录」原先只能靠会员权益获得 | **6 颗/份**，与健康档案 PDF 同价 |

### 1.3 关于「签约」

不做会员，**不需要的是自动续费（连续包月）的签约**。但**虚拟支付本身仍要开通**：微信规定小程序内售卖任何虚拟商品都必须走虚拟支付，冻干充值就是售卖虚拟商品。所以下面几步省不掉：

1. 已认证的企业或个体工商户主体；
2. 公众平台开通虚拟支付：签协议 → 提交商户资料 → 审核（1–7 个工作日）→ 扫码签约（1–2 个工作日）→ 下发子商户号；
3. iOS 端单独开启 Apple 支付，并通过小程序简称审核；
4. 上架 6 个充值道具（第 6 章）。

需要向微信确认的场景从原来的五类（会员、作品解锁、AI 候选、年度报告、健康档案）**收敛为一项**：道具直购能否售卖「冻干 N 颗」这类站内货币包。

## 2. 扣费模型

### 2.1 一条规则：先扣冻干，再执行任务

| 类别 | 规则 | 涉及玩法 |
| --- | --- | --- |
| **付费** | 创建任务时扣冻干，扣费与任务入队在同一事务；产物入库即正式版，没有预览、没有二次解锁 | AI 单张（艺术写真、人化、人宠）、写真套餐、电影海报、时光画册、记忆短片、年度短片、年度报告、纪念短片、健康档案 PDF、年度健康记录 |
| **免费** | 不扣冻干；免费玩法每天 10 次 | 证件照、成长对比图；纪念册、星尘纪念页；趣味测试、时间线、日常记录、健康分诊（各自原有规则） |
| **现金** | 实物，普通微信支付 | 实体纪念品 |

**失败处理（D5）**：任务失败由系统自动重试，最多再试 2 次（共 3 次尝试）；第 3 次仍失败，任务进入终态 `failed`，按扣费流水**原路全额退还冻干**，并发站内通知「已退还 N 颗」。退还只回到冻干余额，现金不退。用户侧不提供「重试」按钮。

**历史锁定作品**：生产从未收过真实款项，历史上以 `locked=true` 入库的作品只存在于测试环境。保留 `POST /api/works/:id/unlock` 用冻干按该玩法现价解锁，不新开预览。

### 2.3 计价细则

- **按积累量分档**沿用 `domain/pricing.ts` 的 `resolvePriceTier`，在**扣冻干那一刻**计算。
- **会员相关的分档逻辑全部删除**：`MEMBER_SPEC_TIER`、`MEMBER_PRICE_TIER`、`isMember`、`memberSaving`。
- **套餐按张退还**：每张失败退 1 颗（10 张套餐的 12 颗里多出的 2 颗视为套餐折扣，不按比例分摊）。
- **颗数的单一来源**是 `domain/dongan-pricing.ts`，端上只读服务端下发的颗数，不写死。
- **iOS 单笔最低 1 元**只约束充值，不约束消耗。

## 3. 数据模型（迁移 `0042`）

当前最新迁移是 `0041_pet_daily_logs.sql`。所有新表通过 `user_id REFERENCES users(id) ON DELETE CASCADE` 挂在用户上，测试重置时会被 `TRUNCATE users CASCADE` 连带清空。

### 3.1 新表

**`wallet_accounts`**：每个用户一行，承担行锁。

| 列 | 说明 |
| --- | --- |
| `user_id` uuid PK | — |
| `balance` int NOT NULL DEFAULT 0 CHECK (balance >= 0) | 当前可用总额，等于未过期批次的 `remaining` 之和 |
| `frozen_reason` text NULL | 非空时禁止消耗（iOS 强制退款扣不回差额时使用，3.3） |
| `newcomer_gift_at` / `first_topup_at` timestamptz NULL | 新人礼、首充资格只发一次的判据 |
| `updated_at` | — |

**`wallet_lots`**：每次入账是一批，记录来源、单价与有效期。

| 列 | 说明 |
| --- | --- |
| `id` uuid PK、`user_id` | — |
| `pocket` text CHECK IN ('purchased','gift') | 购买所得或赠送所得 |
| `source` text | `topup` / `newcomer_gift` / `spend_return` / `admin_grant` |
| `units` int > 0、`remaining` int >= 0 | 入账数量与剩余数量 |
| `unit_price_fen` int NULL | 仅 `topup`：该笔实付金额 ÷ 到账颗数（含加送），用于退款折算 |
| `growth_order_id` uuid NULL | 仅 `topup`：对应充值单 |
| `expires_at` timestamptz NULL | 赠送所得必填，购买所得为空 |
| `status` text CHECK IN ('active','expired','refunded') | — |
| `created_at` | — |

索引：`(user_id, pocket, expires_at NULLS LAST, created_at) WHERE status='active' AND remaining>0`，用于扣减排序。

**`wallet_ledger`**：每一次余额变动一行，只增不改。

| 列 | 说明 |
| --- | --- |
| `id` uuid PK、`user_id` | — |
| `delta` int（正为入账，负为扣减） | — |
| `balance_after` int | 变动后余额，用于对账与明细展示 |
| `reason` text | `topup` / `newcomer_gift` / `spend` / `spend_return` / `expire` / `topup_refund` / `admin_adjust` |
| `biz_key` text NOT NULL **UNIQUE** | 幂等键，见 3.2 |
| `ref_type` / `ref_id` | 业务对象，如 `ai_run` + id、`work` + id、`art_photo_batch` + id |
| `allocations` jsonb | 扣减时从哪些批次各扣了多少：`[{lotId, units}]`；退还按这里原路退 |
| `title` text | 收支明细里展示的文字，如「森林画报」「新人见面礼」 |
| `actor_id` uuid NULL | 后台人工调整的操作人 |
| `created_at` | — |

### 3.2 幂等键 `biz_key`

| 场景 | 键 |
| --- | --- |
| 充值到账 | `topup:<growth_order_id>` |
| 新人礼 | `gift:newcomer:<user_id>` |
| AI 单张扣费 | `spend:ai_run:<id>` |
| AI 付费重拍 | `spend:ai_reroll:<id>:<n>` |
| 写真套餐 | `spend:bundle:<batch_id>` |
| 作品保存高清 | `spend:work:<work_id>:v<version>` |
| 健康导出 | `spend:health:<document_id>` |
| 退还 | `return:<原 biz_key>[:<部分序号>]` |
| 赠送过期 | `expire:<lot_id>` |
| 充值退款 | `refund:<payment_refund_id>` |

重复请求撞唯一约束时，返回第一次的结果，不重复扣。

### 3.3 核心操作（`server/wallet/` 新模块）

| 函数 | 规则 |
| --- | --- |
| `getWallet(userId)` | 余额、赠送所得最近到期日与数量、首充资格 |
| `credit(userId, {pocket, source, units, unitPriceFen?, expiresAt?, bizKey, ...})` | 建批次、写流水、加余额，同一事务 |
| `spend(userId, {units, bizKey, refType, refId, title})` | `SELECT ... FROM wallet_accounts WHERE user_id=$1 FOR UPDATE` → 检查 `frozen_reason` → 余额不足抛 402 `WALLET_INSUFFICIENT`（带 `required` / `balance` / `shortfall`）→ 按「赠送所得按到期日升序 → 购买所得按入账先后」扣批次 → 写流水与 `allocations` |
| `refundSpend(bizKey, units?)` | 按 `allocations` 原路退回；赠送所得保留原到期日（已过期则不退该部分）；部分退还时带序号 |
| `expireGifts()` | Worker 每 60 秒调用，把到期的赠送批次置 `expired` 并写 `expire` 流水 |
| `revokeTopup(growthOrderId)` | 充值单全额退款时调用：扣回该批 `remaining`；不足部分从其他购买批次按先后扣回；仍不足则置 `frozen_reason='refund_shortfall'` 并告警 |

所有调用都要放在 `inTransaction` 内，且**扣冻干必须与业务写入在同一事务**：例如「扣 2 颗 + 写入 `ai_runs` 排队」要么都成功，要么都回滚。生图调用 lingsuan 发生在事务提交之后、由 Worker 执行。

### 3.4 价格字段

- 在 manifest 的 `pricing` 里新增 `cost`（颗）与可选的 `tierCosts`（`basic` / `advanced` / `annual`）；纪念调性用 `toneVariants.memorial.pricing.cost`。`unlockPrice` 不再参与计价，保留只读以兼容历史订单展示。
- **线上读的是 `plugin_configs` 表**，`plugins/runtime.ts:634` 是 `ON CONFLICT DO NOTHING`，只改 `registry.ts` 不会生效。必须按 CLAUDE.md 的「逐键合并」规则回填 `pricing.cost`；实验变体 `experiment_variants` 能覆盖价格的分支同步改成 `cost`。
- 「免费」与「锁定」目前都由 `unlockPrice <= 0` 判定（`generation-worker.ts:96`、`platform-service.ts:407`），两处同步改成 `cost <= 0`。
- AI 单张、写真套餐、健康导出的颗数集中写在 `domain/dongan-pricing.ts`（新文件，Web 端选择器也要用），不分散在 service 里。

| `fd-topup-38` | 3800 | 50 | — |
| `fd-topup-68` | 6800 | 95 | — |
| `fd-topup-128` | 12800 | 188 | — |

- `WECHAT_VIRTUAL_PRODUCTS` 的键为 `sku:分`，例如 `"fd-topup-38:3800": "<微信道具 productId>"`。
- 微信后台道具名称写「冻干 50 颗」这类，**不出现「代币」「兑换」字样**。
- **每次充值新建一张单**：`payment_transactions` 有 `UNIQUE(order_kind, order_id)`，而渠道关单后的支付行会让这张单永久无法再付（`service.ts:49,91`）。

- 单笔上限 128 元；单日累计充值上限 300 元（35 号文第 8 章），在创建充值单时校验。

| --- | --- |
| 再拍一张 | 原任务保留，返回新任务 ID；重新扣费。失败任务没有手动重试接口，旧 retry 返回 410；没有免费重拍 |
| 收支游标 | `GET /api/wallet/ledger?before=<id>` 使用流水 ID 作为游标，并以时间与 ID 稳定排序 |
| 纪念画册 | 纪念空间和 memorial 阶段的画册均免费，不占证件照/成长对比的每日十次 |
| 旧作品现金订单 | `POST /api/orders` 返回 410；历史锁定作品走 `POST /api/works/[id]/unlock`，现金历史订单仍可查询 |
| 写真套餐 | 新建仅 ten/twenty；历史 all（36 张）批次只读兼容，不重新出售。单张失败按张退，接口下发 `returnedUnits` |
| 非玩法页报价 | `GET /api/wallet` 同时下发 `costs.annualReport/healthDocument/memorialFilm`，与玩法报价共同来自 `domain/dongan-pricing.ts` |
| 免费次数 | 只有 pet-id-card 与 pl-23 每日合计十次，sourceWorkId 重新生成也计次；付费任务不占次数 |
| 自动重试 | 图文、AI、视频任务自动重试两次，共三次尝试；终态失败退回冻干，不退现金。Provider 内部网络重试与任务尝试次数分别计数 |
| 退款赠送批次 | 因任务失败退回的原赠送批次若已到期，重新给予七天有效期；避免任务失败导致赠送颗数丢失 |
| Web 验收 | D6 下 Web 只保编译和既定 E2E；402 充值面板与原请求自动继续由小程序真实 wallet 模块的行为测试覆盖 |

验证证据、未发布状态与外部门禁见 [实施交接](../delivery/10-冻干钱包实施交接.md) 第 6 节。
