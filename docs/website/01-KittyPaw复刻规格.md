# 官网复刻规格：KittyPaw

参考站唯一一个：**KittyPaw** — <https://kitty.grok.me/>

目标是**结构与风格 1:1 复刻**，只把内容换成 petbaby 自己的产品。色彩与字体按第 7 章换成本项目既有 token，其余（骨架、排版方法、动效口径、交互细节）照搬。

取值来源：站点 SSR HTML、`assets/styles-DkWU7M6X.css`（Tailwind v4 `@theme` 层）、`assets/routes-BZC_yRK1.js`（framer-motion 参数）、`assets/bg.mp4`（hero 视频）。均为线上产物实测，非推测。

技术栈（对方）：TanStack Start SSR + Tailwind CSS v4 + framer-motion + lucide-react。我们不必用同一套，静态 HTML/CSS + 少量 JS 即可达到同样效果。

> 关于「Grok 官方案例」：未能证实。`grok.me` 不在 xAI 已知域名之列（其产品域为 `x.ai` 与 `grok.com`）。文案有占位痕迹（`…so your furry life.` 句子不完整，`648+` / `12k+` / `98%` / `20,000+ cat parents` 均为示意数据）。判定为完成度很高的模板／演示站。这不影响复刻价值，但它不是经过真实业务检验的范式，遇到与本项目冲突处以本项目既有约定为准。

## 1. 页面结构

单页锚点站，无路由跳转。原站锚点：`#home` `#products` `#grooming` `#wellness` `#vet` `#contact`。

> 本项目实现的锚点（按内容映射改名，多一个作品区）：`#home` `#plays` `#services`
> `#portrait` `#memorial` `#how` `#works` `#voices` `#contact`。
> `#voices` 是口碑占位区，暂不入导航（内容待定，见第 9 章第 6 项）。

| #   | 区块     | 布局                                                    | 底色            |
| --- | ------ | ----------------------------------------------------- | ------------- |
| 1   | hero   | 满屏视频 + 大标题 + CTA + 头像社群证明                             | `kp-black`    |
| 2   | 信任条    | 3 项图标文字，`flex-wrap justify-between`，窄横条               | `kp-elevated` |
| 3   | 产品区    | 3 卡网格 `sm:2 → lg:3`                                   | `kp-ink`      |
| 4   | 服务导航   | 3 张入口卡 `md:3`                                         | `kp-elevated` |
| 5   | 服务详情 A | 图文左右分栏 `md:grid-cols-2`，**图在左**（`order-2 md:order-1`） | `kp-ink`      |
| 6   | 服务详情 B | 图文左右分栏，**图在右** + 2×2 数据格                              | `kp-elevated` |
| 7   | 流程区    | 01/02/03 三栏，顶线分隔，无卡片                                  | `kp-ink`      |
| 8   | 口碑区    | 3 条引语卡                                                | `kp-elevated` |
| 9   | 订阅 CTA | 大圆角面板 + 行内表单                                          | `kp-ink`      |
| 10  | 页脚     | `1.4fr 1fr 1fr 1fr` 四栏 + 底部版权行                        | `kp-black`    |

节奏的本质是**深浅交替的横带**：页面底色 `kp-ink`，偶数区块换 `kp-elevated` 并加 `border-t border-kp-border`。三档底色差异极小（`#0a0a0b` / `#121214` / `#1a1a1e`，明度差 2–4%），足够分段而不割裂。**不靠留白分段，靠明度台阶。**

第 5、6 两个区块图文左右互换，是避免连续分栏呆板的关键，复刻时必须保留这个交替。

### 容器与间距

```
容器      mx-auto max-w-6xl              → 1152px
内边距    px-4    → md:px-12  → xl:px-16 → 16 / 48 / 64px
区块留白  py-20   → md:py-28            → 80 / 112px
标题间距  mb-12   → md:mb-16            → 48 / 64px
锚点补偿  scroll-mt-8
```

三档断点：默认（移动）→ `md` 768px → `xl` 1280px。`sm` 与 `lg` 只切网格列数。移动端全部单列。

### 网格断点逐区块（实测 class 串，不是一套通用规则）

复刻时最容易走的偏差是「所有三卡网格共用一套断点」。原站四处三卡网格用了三套规则：

| 区块       | class                                               | 切换点              |
| -------- | --------------------------------------------------- | ---------------- |
| 产品区      | `grid gap-5 sm:grid-cols-2 lg:grid-cols-3 lg:gap-6` | 640 两列 → 1024 三列 |
| 服务导航     | `grid gap-4 md:grid-cols-3 md:gap-5`                | 768 直接三列         |
| 流程区      | `grid gap-6 md:grid-cols-3 md:gap-8`                | 768 直接三列         |
| 口碑区      | `grid gap-5 md:grid-cols-3`                         | 768 直接三列         |
| 服务详情 A/B | `md:grid-cols-2 md:gap-14`                          | 768 两列           |
| 2×2 数据格  | `grid grid-cols-2 gap-4 sm:gap-5`                   | 恒两列，只变间距         |
| CTA      | `lg:grid-cols-[1.2fr_1fr]`                          | **1024** 才分栏     |
| 页脚       | `md:grid-cols-[1.4fr_1fr_1fr_1fr]`                  | 768 直接四栏         |

服务导航/流程/口碑**跳过两列态**：三项一组两列会留一个孤项。产品卡带图更高、窄屏两列仍
读得动，所以多给一档 `sm`。CTA 推到 `lg` 是因为二维码那栏在 768–1023 会挤成窄条扫不动。

### 区块标题三件套

全站最高频的复用模式，每个区块头部都是这个组合：

```html
<p class="eyebrow">Premium Products</p>      <!-- 小字 · 大正字距 · 全大写 · 最弱色 -->
<h2 style="font-size:clamp(2rem,4vw,3.5rem);letter-spacing:-0.03em;line-height:1.1">
  Made for cats.<br/>Chosen by people.       <!-- 展示字 · 负字距 · 手动断行 -->
</h2>
<p class="body">…</p>                        <!-- 说明 · 限宽 · 次级色 -->
```

`eyebrow` 的 `tracking-[0.18em]` 正字距与 `h2` 的 `-0.03em` 负字距形成反差 —— **小字放松、大字收紧**，这是廉价与精致的分界之一。

标题区两种排布：`md:flex-row md:items-end md:justify-between`（标题左、说明右，产品区用）或 `max-w-xl` 单列（其余区块用）。

## 2. hero 详解（重点，含视频）

### 2.1 视频参数（实测）

```
文件      /assets/bg.mp4
体积      4.4 MB
分辨率    1280 × 720
时长      10.005 秒
属性      autoPlay · muted · playsInline · preload="auto" · aria-hidden
初始      loop = false
样式      pointer-events-none absolute inset-0 z-0 h-full w-full object-cover
```

**内容是一个连续镜头，不是循环纹理**（抽 9 帧实测，干净帧存 `prototype/refframes/`）：

| 时间       | 画面                                                                                       |
| -------- | ---------------------------------------------------------------------------------------- |
| 0s       | 仰视屋顶天窗。深灰铝框呈梯形透视（下宽上窄），左右两侧边缘垂下**三叶草藤 + 粉白两色三叶草花**，一道**横向玻璃压条**在画幅约 78% 高度处横穿，天空淡蓝加稀薄丝状云 |
| 1.5s     | 仍是空镜，云在缓慢移动，藤蔓轻微摆动                                                                       |
| 2.5s     | **奶白色长毛波斯猫**自画幅下缘中央探头入画；**肉粉色壁虎**已在右上（中心约画幅 67% / 16%）                                   |
| 3.5–5.5s | 猫居中站定、抬头凝视壁虎。**5.5s 是全片信息最全的一帧**：猫脸清晰、壁虎悬在正上方                                            |
| 7.0s     | 猫在玻璃上走动、抬起一只前爪，**爪垫贴着玻璃摊平**                                                              |
| 8.5s     | 猫跨过镜头正上方，画面只剩**肚皮与四只压在玻璃上的爪垫**                                                           |
| 9.9s     | 回到空镜，与 0s 构图基本一致（**可无缝衔接循环**），云量略多于 0s                                                   |

**空间关系（最容易搞反的一点）**：猫**走在天窗玻璃的上面**，我们从室内隔着玻璃仰视它 ——
所以 8.5s 看到的是肚皮和爪垫，7.0s 能看到爪垫摊平贴在玻璃上。壁虎同样在玻璃外侧，
5.5s 那帧是四肢张开悬在空中的姿态，是掠过而非贴着爬。

其余几处容易忽略但影响复刻的细节：

- **梯形透视**：天窗四边不是矩形，下缘明显比上缘宽，仰角约 30–40°。这是「躺在地上往上看」的视角，不是平视窗外
- **横向压条**：画幅 78% 高度那道玻璃分隔条是构图的水平锚，去掉画面会散
- **植物只在左右两侧**，上缘与下缘留空。中央大片天空才留得住标题与主体
- **右下角有斜向阳光投影**落在墙面上，暗示光源在右上方

### 2.2 5 秒截断循环（关键设计）

```js
// 默认只播前 5 秒就归零重播
const onTimeUpdate = () => { if (!clicked && v.currentTime >= 5) { v.currentTime = 0; v.play(); } };
// 用户点击/触摸后才播完整 10 秒
const onClick = () => { setClicked(true); v.loop = true; v.play(); };
window.addEventListener('click', resumePlay, { once: true });     // 绕过自动播放限制
window.addEventListener('touchstart', resumePlay, { once: true });
```

进站看到的是「猫探头 → 抬头看壁虎」这 5 秒高潮片段在循环，把最有戏的部分反复给你；完整叙事留给愿意交互的人。**这个取舍要保留。**

首屏另用 `IntersectionObserver(threshold: 0.15)` 判断是否在视野内，离屏时停掉光标逻辑。

### 2.3 压暗遮罩

```css
background: radial-gradient(ellipse at 30% 50%,
            transparent 0%, rgba(0,0,0,0.25) 70%, rgba(0,0,0,0.55) 100%);
```

椭圆中心**偏左 30%**，正好落在标题区，所以左侧文字始终压在最暗处可读，而画面中央的主体不被压。标题另有 `text-shadow: 2px 5px 2px rgba(0,0,0,0.40)` 兜底。

### 2.4 hero 排版

```css
/* h1 */

line-height:    clamp(3rem, 7.5vw, 120px);
letter-spacing: clamp(-2px, -0.375vw, -6px);   /* 字距随字号联动收紧 */
```

标题按**单词**切分成两行（`[['Everything','Your'], ['Cats','Love']]`），每行 `flex flex-wrap gap-x-4 md:gap-x-6`。

### 2.5 hero 入场时间线（精确值）

```js
顶栏     { opacity:0, y:-40 } → duration 1.4,  ease [.16,1,.3,1]
标题容器 staggerChildren: 0.18, delayChildren: 0.8
标题单词 { opacity:0, x:-50 } → spring(stiffness:70, damping:12)
说明文字 { opacity:0, y:15 }  → delay 1.8, duration 1,   ease easeOut
底部条   { opacity:0, y:40 }  → delay 2.2, duration 1.2, ease [.16,1,.3,1]
```

整条时间线约 3.4 秒走完。标题逐词从左滑入用 spring 而非 duration，落点有轻微过冲。

### 2.6 底部条

```

右：3 张重叠头像（-space-x-2.5 → md:-3.5 → xl:-4，1.5px 白描边）
    + 数字 clamp(1.5rem,2vw,32px) + 一行说明 text-[10px] → md:text-xs → xl:text-xl

```

### 2.7 自定义光标（**已改为实现**，2026-08 拍板）

桌面端（`min-width:1024px`）且首屏在视野内时，把 `documentElement` 与 `body` 的 `cursor` 设为 `none`，换成自绘环：外圈 80px，文字 `Touch to Continue • Walk Cat •` 按 `rotate(i/n*360deg)` 逐字符排一圈，12 秒匀速自转；圆心 3px 白点带 `0 0 8px rgba(255,255,255,.8)` 光晕。跟随用 spring(damping 28 / stiffness 280 / mass 0.4)。悬到 `button, a, input, select, textarea, [role='button']` 上时环淡出并恢复系统指针。

**已实现**（原判为「不做」，2026-08 改为做）。当初否掉的两条理由仍然成立，因此实现时各配了一条对策：

| 原顾虑                            | 对策                                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 触屏上 `cursor` 完全无效，而微信内移动端是主要流量 | 三道门都过才建 DOM：`(pointer: fine)` + 视口 ≥1024px + 非 reduced-motion。不满足时连 DOM 都不建，另监听 matchMedia 变化以应对中途拔鼠标 |
| 隐藏系统指针对依赖指针定位的用户是可用性损失         | **只在 hero 内隐藏**，不动 `documentElement`/`body`。原站是全局 `cursor:none` 再靠白名单恢复，漏一个选择器就有一片区域没指针               |

实现细节与中文适配见第 9.1 章偏离 ⑯。

## 4. 色彩与材质

### 完整色板（仅 10 个变量，全中性、零彩色）

```css
--color-kp-black:        #000;        /* 首屏与页脚 */
--color-kp-ink:          #0a0a0b;     /* 页面基底 */
--color-kp-elevated:     #121214;     /* 交替横带、卡面 */
--color-kp-subtle:       #1a1a1e;     /* 图片占位、图标底 */
--color-kp-white:        #fff;        /* 标题 */
--color-kp-fg:           #f4f4f5;     /* 强调正文 */
--color-kp-muted:        #a1a1aa;     /* 默认正文 */
--color-kp-faint:        #71717a;     /* eyebrow、元信息 */
--color-kp-border:       #ffffff1f;   /* 12% 白，默认描边 */
--color-kp-border-strong:#ffffff38;   /* 22% 白，hover / 输入框 */
```

唯一的「颜色」来自图片与 hero 视频。描边用半透明白而非实色灰 —— 叠在任何底色上都自动成立。

### 圆角分级（按尺度递增，不用语义档）

```
rounded-full    → 按钮、徽标、头像、输入框
rounded-2xl     → 小卡（数据格）、图标底
rounded-[24px]  → 中卡（服务卡、引语卡）
rounded-[28px]  → 产品卡
rounded-[32px]  → 大面板（图片框、CTA 面板）
```

**尺寸越大圆角越大。**「所有卡片同一圆角」是粗糙感来源。

### 材质手法

- **卡片** = `border border-kp-border` + `bg-kp-elevated`，**无阴影**（深色底阴影不可见，用描边定形状）
- **图片框** = `overflow-hidden` + `border` + `aspect-[4/3]`，图 `object-cover h-full w-full`。全站图片统一 4:3
- **徽标** = `bg-black/45` + `border-white/15` + `backdrop-blur-md`，压在图上仍可读
- **CTA 面板补光** = `radial-gradient(ellipse at 80% 20%, rgba(255,255,255,0.08), transparent 55%)` + `opacity-40`，右上一点微光避免大面板发死
- **2×2 数据格** = `rounded-2xl border bg-kp-ink px-4 py-4`，数字 `text-2xl md:text-3xl` + 标签 `text-xs md:text-sm`

### 按钮三级（仅此三种）

```css
/* 主：白底黑字，唯一实心 */
rounded-full bg-white px-6 py-3 font-semibold text-black shadow-lg
hover:bg-neutral-100  active:scale-95

/* 次：描边透明底，hover 反白 */
rounded-full border border-kp-border-strong bg-transparent px-4 py-2 text-kp-fg
hover:bg-white hover:text-black

/* 文字：箭头跟随 */
inline-flex items-center gap-2 text-sm text-kp-fg opacity-80 group-hover:opacity-100
```

`active:scale-95` 是全站唯一的按压反馈。

## 5. 动效

`ease` 全站统一 `[0.16, 1, 0.3, 1]`（expo.out 型，起步快尾部长）。

### 滚动入场（全站复用）

```js
{
  initial:    { opacity: 0, y: 28 },
  whileInView:{ opacity: 1, y: 0 },
  viewport:   { once: true, margin: '-80px' },   // 只播一次 · 提前 80px 触发
  transition: { duration: 0.7, ease: [0.16, 1, 0.3, 1] }
}
```

网格子项另有两档更轻快的参数，**不与区块级共用**（实测原站，按圆角反查区块）：

| 区块                      | y   | duration | delay      |
| ----------------------- | --- | -------- | ---------- |
| 服务导航卡（`rounded-[24px]`） | 20  | 0.55     | `i * 0.07` |
| 产品卡（`rounded-[28px]`）   | 24  | 0.6      | `i * 0.08` |
| 流程区                     | 20  | 0.55     | `i * 0.08` |
| 口碑区                     | 20  | 0.55     | `i * 0.08` |

子项若跟容器同幅度同时长，三张卡会齐刷刷大幅位移，反而比错峰更晃眼 —— 这是这两档存在的原因。

**`once: true` 很重要** —— 滚回去不重播，避免长页面反复动。

### 交互

### 7.2 字体：中文双字体

Braah One / Gabarito 都不含中文字形。等价分工：

| ----------------- | -------------------------------------------------------------------- |

### 7.3 中文排版差异（三条硬约束）

1. **负字距收敛**：西文 `-0.03em` → 中文 `-0.01 ~ -0.02em`，再紧会粘。`cute` 皮肤字面更圆，只收 `-0.01em`
2. **不做 `uppercase`**：中文无效。eyebrow 的正字距可保留甚至加到 `0.2em`（中文小字放宽更透气）
3. **主按钮逐字母弹跳不做**：中文按字符弹会散。改成整体 `scale` 微动 + 箭头 `x:6` 跟随

- 统一 `aspect-[4/3]`（`object-cover`）
- 作品展示图必须是**真实生成结果**。缺图时**只留文字排版，不放占位色块** —— `LocalImageProvider` 的纯色 SVG 正是方案点名的违例
- 风格对比图沿用同一只样板宠物（橘白猫「摩奇」，`tools/imagegen/prompts.mjs` 的 `MODEL_PET`）—— 换宠物会让用户比较宠物而非风格
- 现成素材在 `tools/imagegen/out/`：`plugins/`（1600×1000，玩法成品）、`styles/`（900×1200，风格对比）、`model/`（1200×1600，样板宠物）

## 8. hero 视频：生成提示词（已完成，存档）

需你自行生成后交付。以下提示词按 KittyPaw 的镜头逻辑设计，**不是复制它的画面**（那是猫探头看壁虎），而是复用它有效的三个要素：仰视视角、主体中后段入画、前景植物做景深。

### 8.1 硬性技术要求

```
时长      10 秒（可 8–12 秒，需 ≥6 秒以支持 5 秒截断循环）
分辨率    1280×720 起，1920×1080 更好
比例      16:9（object-cover 裁切，主体须居中偏上）
体积      ≤5 MB（KittyPaw 是 4.4MB/10s，超了首屏会卡）
格式      MP4 / H.264（兼容性优先，不用 WebM 单一格式）
音轨      无（muted 播放，带音轨纯属浪费体积）
```

### 8.2 镜头设计要求

改写 `bg.mp4` 时，以下五条原视频**已经满足**，保持不动即可；若换镜头重做则必须逐条对照：

- **前 5 秒是一个完整小高潮**：0–1s 空镜建立场景，2–3s 主体入画，4–5s 主体成为画面中心 —— 因为默认只循环前 5 秒
- **左侧 40% 区域留空**：标题压在那里。原视频靠「植物只在两侧 + 猫居中」达成，本轮把植物改成左上/右下对角后仍需守住这条：**左侧中段（标题所在高度）不要堆植物**
- **中央上方不放强对比细节**：压暗遮罩中心透明，那里会完全露出
- **首尾可衔接**：原视频 9.9s 与 0s 构图基本一致，改写时要保住
- **不要文字、不要 logo**：会与标题打架

### 8.3 即梦：选哪个模式

本需求的镜头特征决定了模式选择 —— **镜头完全固定，单一连续镜头，主体从画外进入再离开**。
认清这一点，各模式的适配度就很清楚了：

| 模式                         | 适配       | 理由                                                                                         |
| -------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| **全能参考（Seedance 2.0/2.5）** | ★★★ 首选   | 支持多张参考图 + **参考视频**，可用 `@参考视频 参考该视频的动作` 做动作复刻。手上正好有原 `bg.mp4`，等于把「运动」和「外观」分开控制 —— 这就是本需求的原型 |
| **视频 3.0 图生视频（单首帧）**       | ★★☆ 稳妥退路 | 固定镜头 + 主体从画外入画，正是标准图生视频的形态。支持 10 秒、1080p。原视频大概率就是这么做的                                      |
| **智能多帧 1.0**               | ★☆☆ 不推荐  | 见下                                                                                         |
| **视频 3.0 首尾帧**             | ☆☆☆ 不可用  | 见下                                                                                         |

#### 为什么不用智能多帧

它的设计目标是**多节点串成一条空间连续的长镜头**（空间漫游、产品展示、角色动态延展），
价值在于「镜头在移动、跨越多个空间节点时保持连续」。

而本需求的镜头**全程一动不动**，只有一个主体进出画面。智能多帧的核心能力在这里完全用不上，
却要付出两项代价：**锁在 1.0 模型**（画质与指令遵循都弱于 3.0 / Seedance），
以及**多张关键帧的一致性风险**（每张里的德文猫若长得不一样，成片会在帧之间变脸）。

付出画质，换来用不上的能力 —— 不划算。

#### 为什么首尾帧不可用

本视频的 **0s 与 9.9s 构图基本一致**（都是空镜，这正是它能无缝循环的原因）。首尾帧给模型两张
几乎相同的图，等于告诉它「十秒内什么都没变」—— 猫的进出全靠提示词硬撑，模型极可能就让云飘一飘
了事。首尾差异大才是首尾帧的用武之地，这里恰好相反。

#### 关键前提：只需要编辑一张图

不论走哪条路，**都得先手工改出一张静帧** —— 因为植物与云是「画面里已有的东西」，
文字提示词改不动它们，只能驱动后续出现的内容（猫、壁虎）。

好消息是**只需要一张**，不是四张。选 `refframes/frame-05_5s.png`（猫脸最清晰、壁虎在正上方，
全片信息最全的一帧）做编辑底图。

编辑提示词（即梦图片生成／参考图编辑，输入 `frame-05_5s.png`）：

```

壁虎快速窜出画面。
9-10秒：猫走出画面，天窗恢复空镜，只剩云缓慢飘移和藤叶轻摆，画面与开头一致。

写实摄影质感，暖调自然光，前景藤叶浅景深，动物动作自然，无文字，无人物，无声音。
```

#### 参数与限制（视频 3.0）

| 项         | 说明                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------- |
| 时长        | 5s / 10s，本需求取 **10s**                                                                              |
| 分辨率       | 可选 720p / 1080p，默认 720p。**取 1080p** 后与运镜模板互斥（本需求不用运镜，无影响）                                          |
| 比例        | `aspect_ratio` 仅文生视频生效；图生视频按输入图比例就近匹配，故静帧务必 16:9                                                   |
| **负向提示词** | **视频 3.0 不支持** `negative_prompt`。网页版若有该输入框可填，没有就把约束写进正文 —— 这也是上面提示词里反复出现「不是蓬松长毛猫」「不推拉不摇移」这类正向措辞的原因 |
| 首尾帧       | 仅视频 3.0 支持，3.0 Pro 不支持（本需求不用）                                                                      |
| 音频        | 两个模型都不支持 `with_audio`。正好，hero 视频要静音                                                                |

以上参数来自第三方 API 聚合平台文档转述，火山引擎官方产品页当时取不到正文，**建议在即梦界面
里再核对一次**，尤其是时长上限与 1080p 是否需要会员。

#### 时长不足时

优先保前 5 秒（空镜 → 入画 → 凝视），砍掉 7–8 秒的走动 —— 默认循环只播前 5 秒，
走动属于「点击后才看到」的加分项。

### 9.1 实现与规格的偏离（逐条记录）

正文保持原判不改写，实现层面的偏离记在这里。

**① hero 压暗遮罩多加两道线性渐变。** 规格 2.3 的椭圆中心是 `transparent 0%`，即文案区最亮。
原站成立是因为英文标题落在深灰天窗铝框内；中文标题更宽、压到了中央亮天空上，
实测白字对该区均值只有 **2.72:1**。因此在椭圆之上叠了左下两道线性压暗
（`to top` 与 `to right`，只覆盖文案区）。压暗后四个时间点（0.5 / 3.5 / 5 / 8.5s）
× 两档视口的标题对比度为 **4.73–5.60:1**，中央与右上不动，猫与壁虎仍完整露出。

**② 缩略带标签下沉到格外。** 规格 4 章的图上徽标（`bg-black/45` + `backdrop-blur`）
是给大图用的。七格平分 1152px 后每格仅约 145px，11px 徽标既盖画面又读不出，
故改为图下 12px 文字（实测 5.54:1）。`play-media` / `media-frame` 的大图徽标不变。

**③ hero 标题词距收紧一档。** 原站 `gap-x-4 → md:gap-x-6`（16/24px）。西文单词间本有空格，
中文没有 —— 照抄会把「留住 每一个」读成两个断开的词组。改为 8/12px，只够标示分词节奏。

**④ 卡面徽标与 2×2 数据格不写 `PL-xx` 内部编号。** 首版写了「图文 · PL-01」「PL-20」，
但官网访客不认这套代号。徽标改成玩法类别（「图文创作」），数据格数字位改成名称
（「纪念册」「纪念视频」「纪念页」「成长对比」）。编号只对我们自己有意义。

**⑤ 桌面下拉面板底色由 `bg-white/10` 改为 `rgba(42,31,31,.72)`。** 规格 5 章的
`w-64 rounded-2xl border-white/20 bg-white/10 p-4 backdrop-blur-xl` 与 spring(380,26) 均照搬，
只有底色改了。原站是深色站、面板压在深灰天窗铝框上，`white/10` 足够；我们的面板落在
hero 亮天空区，实测白字仅 **4.43:1**。改为暖褐半透明底后升到 **12.33:1**
（同一个 `SHADOW_HUE` 家族，不引入新色）。`@supports not backdrop-filter` 的兜底同步加到 `.95`。

**⑥ 顶栏取消了内联导航。** 首版我自造了「玩法 / 服务 / 作品 / 怎么用 / 联系」五个内联链接
外加一个「打开小程序」按钮，与原站不符 —— 复核其 SSR HTML 后确认：**所有断点都只有
logo + 一个 `aria-haspopup` 的「Menu」按钮**，没有内联链接，顶栏也没有 CTA（主 CTA 在
hero 底部条）。现已改为单按钮驱动两个面板，共用一个开合状态，靠 `hidden md:block` /
`md:hidden` 的等价 CSS 断点切换谁可见，与原站同构。

两处实现细节顺带对齐了原站：移动面板补上顶部的 logo + 关闭按钮一行（首版漏了，
而全屏面板会盖住顶栏按钮，没有它就只能靠 Esc 关）；移动导航项由 26px/700 改为
原站的 **24px/500**（`text-2xl font-medium`）。

另加了两条原站有、规格正文未列的交互：**点面板外关闭**（下拉不铺满屏幕，不加这条
会一直挂在顶栏上）与 **Esc 关闭后把焦点还给按钮**（键盘用户不会掉到页首）。

**⑦ 网格断点原为一刀切，已按原站逐区块拆开。** 首版所有三卡网格共用
「768 两列 → 1024 三列」，但原站四处用了三套规则（实测其 class 串）：

| 区块      | 原站                                             | 说明                 |
| ------- | ---------------------------------------------- | ------------------ |
| 产品区（玩法） | `gap-5 sm:grid-cols-2 lg:grid-cols-3 lg:gap-6` | 640 两列、1024 三列，多一档 |
| 服务导航    | `gap-4 md:grid-cols-3 md:gap-5`                | 768 直接三列           |
| 流程区     | `gap-6 md:grid-cols-3 md:gap-8`                | 同上，间距更大            |
| 口碑区     | `gap-5 md:grid-cols-3`                         | 同上                 |
| CTA     | `lg:grid-cols-[1.2fr_1fr]`                     | **1024** 才分栏，非 768 |
| 页脚      | `md:grid-cols-[1.4fr_1fr_1fr_1fr]`             | 768 直接四栏，无两栏态      |

服务导航/流程/口碑跳过两列态是有道理的：三项一组两列会留一个孤项。产品卡带图更高，
窄屏两列仍读得动，所以多给一档。CTA 推到 1024 是因为二维码那栏在 768–1023 之间会挤成
窄条扫不动。全部改成移动优先（基础单列 + `min-width` 升级），并逐宽度实测过
（640/768/1024/1280 四个切换点两侧各采样一次，九个网格全部符合）。

**⑧ h2 缺第三档、字重档位缺 600。** 规格 3 章的流式字号给了 h2 三档，首版只实现两档，
流程区与口碑区误用了大档。现补 `.h2-sm`（`clamp(2rem,4vw,3.25rem)` lh 1.1），
桌面下三档为 56 / 52 / 48px。

另外规格多处写 `font-semibold`（600），首版一律用了 700。已补 `--fw-semibold: 600`
并改用于 h3 卡标题、主按钮、页脚小标题、引语署名 —— **700 在中文黑体上发糊**，
600 更贴「精致不是可爱」的基调。`--fw-bold`(700) 保留给 `.link-arrow`、列表强调、作品名。

卡标题同时从 17/18px 抬到规格的 **18/20px**（`text-lg / md:text-xl`）：首版与 15px 正文的
层级差太小，卡片标题读不出主次。

**⑨ 正文移动端字号保持 15px，未降到规格的 14px。** 规格是 `text-sm → md:text-base`
（14 → 16）。md 以上已对齐 16px，移动端这档显式留在 15px —— 中文字面比西文满，
14px 在手机上偏小。这是三条中文硬约束（7.3）之外的同类判断，一并记在这里。

**⑩ 网格子项入场原与区块级共用一套参数，已拆成三档。** 首版全站用 `y:28 / 0.7s`，
且 delay 一律 `i*0.07`。实测原站有三套（见第 5 章修订后的表）：区块级 `y28/0.7`、
产品卡 `y24/0.6/0.08`、服务卡 `y20/0.55/0.07`、流程与口碑 `y20/0.55/0.08`。
规格正文原先漏了产品卡这一档，已补进正文。九处初始态逐个实测已对齐。

**瀑布流 11 张不给 stagger**：按 0.08s 递进尾部要等 0.88s 才出齐，太拖；分列错峰更合理，
但 CSS columns 下 DOM 顺序与视觉列不对应，按 `nth-child` 给延迟会错峰错到别的列上。

**⑪ 2×2 数据格字号补到规格值。** 首版为防中文换行收成了数字 20/24px、标签 12/13px。
那个顾虑来自更长的旧文案，标签改短后已不成立 —— 实测规格值（数字 `text-2xl / md:text-3xl`
= 24/30px，标签 `text-xs / md:text-sm` = 12/14px）在三档视口下四格均不换行，已改回规格值。

**⑫ CTA 面板补光换成暖光。** 规格是 `rgba(255,255,255,0.08)` + `opacity-40`（深色站用白光）。
浅色面板上白光完全看不见，改为 amber300 系的 `rgba(255,209,102,.32)` + `opacity .8`，
保留「右上一点微光避免大面板发死」的意图。

**⑬ 页脚三栏改用 `nav` + `h2`（规格未涉及，语义修正）。** 原先是裸 `div` + `h3`。
`h3` 会被读屏当成上一个 `h2`（CTA 的「现在就给它拍一张」）的下级内容 —— 页脚栏目
不属于 CTA 区块。改为三个 `<nav aria-labelledby>` 各配一个 `h2`（在 `footer` 地标内
`h2` 是顶层），读屏可当独立区块跳转。`.footer-title` 是类选择器，视觉无变化。

顺带清了两处删内联导航时的残留：`.btn-sm`（顶栏 CTA 用的，按钮删了规则还在）、
HTML 上的 `.trust-band` 类（职责与 `.band` 完全重复，早期 CSS 已删、类名留着）。
`.proof-text` 无 CSS 定义是正常的 —— 它是 `.hero-proof` flex 布局里必需的结构包装，
去掉它两个 span 会被排成横向。

**⑭ 首屏性能：加 lazy／固有尺寸，`preload` 由 auto 改 metadata。** 规格 8.1 在意首屏开销
（体积 ≤5MB 的理由就是「超了首屏会卡」），但首版 29 张图无一个 `loading="lazy"`、
也都没有 `width`/`height`。现状：

- hero 三头像 `loading="eager" fetchpriority="high"`（首屏底部条内），其余 26 张 `lazy`
- 全部补 `width`/`height` 固有尺寸 + `decoding="async"` → **CLS 实测 0**（三档）
- `bg-poster.jpg` 加 `<link rel="preload" as="image">`：它是视频加载完成前唯一决定首屏
  观感的图，不提前取会与 3.5MB 的视频同时起跑
- `preload` 由规格 8.1 的 `auto` 改 `metadata`。**注意这条实际不起作用** —— `autoplay`
  会覆盖 preload 提示（自动播放必须取足数据），实测 load 时仍下载完整视频。
  保留 `metadata` 只是声明意图；视频体积是唯一的真实杠杆，规格已把它压到 3.51MB
- 补 favicon（内联 SVG data URI，渐变取值同顶栏 `.brand-mark`）：原先会吃一个
  `/favicon.ico` 404

> **踩坑记录**：给 `<img>` 加 `width`/`height` 属性后，**任何只设 `width` 而不设 `height`
> 的 CSS 规则都会让属性高度生效**。`.media-frame img` 与 `.clay-frame img` 原本只有
> `width:100%` + `aspect-ratio`，加属性后 `aspect-ratio` 被无视、两个大图撑到 1200px 高，
> 桌面页高从 8652 涨到 10118px。补 `height:auto` 才修好。加固有尺寸时要同时检查
> 所有 img 规则有没有显式 `height`。

**正式站待办（原型不做）**：瀑布流 26 张 lazy 图共约 3.4MB，桌面滚到底会全部下载。
正式站应上 `srcset`/`sizes` 给多档尺寸 —— 原型只有单档源图，加了也没有实际来源，
且会让 HTML 复杂度翻倍。

**⑮ hero 首屏按参考图逐项校准（2026-08 第二轮）。** 与线上首屏截图逐项比对后改了六处，
其中第一处是结构性偏差：

**1. hero 不套 `max-w-6xl` 容器。** 实测原站：`<header>`、文案区、底部条三块各自只有
`px-4 → md:px-12 → xl:px-16`，hero 区内**没有 `max-w-6xl` 也没有 `mx-auto`**。首版给它套了
1152px 容器，1440px 视口下左右各白留 144px，首屏明显偏窄。现改为铺满视口宽 + 三档内边距

**2. hero 主 CTA 改白底黑字。** 规格 4 章的原始口径就是
`rounded-full bg-white px-6 py-3 font-semibold text-black shadow-lg`，首版用了品牌玫红。
白底压在深色视频上对比度最高，且玫红在暖调视频上会与画面里的花色打架。新增 `.btn-on-dark`

**3. 品牌标识与菜单按钮补三档尺寸。** 原站 logo `h-[26px] md:h-9 xl:h-10`（26/36/40px）、

（16/20/24px）。首版全部固定在第一档，桌面下顶栏显得单薄。

**4. 压暗遮罩减轻到实测下限。** 偏离 ① 加的两道线性压暗过重。四档候选在最亮帧
（0.5s 空镜）量标题区纯底色：

| 强度                        | 标题白字对比     | 画面亮度      |
| ------------------------- | ---------- | --------- |
| `.66/.38/.56/.22`（首版）     | 7.51:1     | 0.332     |
| `.56/.30/.46/.18`         | 6.37:1     | 0.373     |
| `.48/.24/.38/.14`         | 5.53:1     | 0.410     |
| **`.40/.20/.30/.12`（采用）** | **4.99:1** | **0.437** |
| 只留椭圆（原站原值）                | 3.09:1     | 0.575     |

取第四档：画面亮度 +32%、视频细节露出来，标题仍守住 4.5:1。**完全去掉线性压暗不可用** ——
3.09:1 中文标题读不出，原因见偏离 ①。

**5. 主 CTA 加 hover 动效**（规格 7.3：中文不做逐字母弹跳，改整体 scale + 箭头跟随）。
整体 `scale(1.03)` + 阴影抬高 + 箭头 `x:6`。hover 用 240ms + `--ease-spring`，按压回到 120ms ——
按压必须跟手，放大用同样时长会显得急躁。

**6. 副标语改写，增加情绪落点。** 首版「上传一张日常照片，几分钟拿到身份证、电影海报…」
把功能罗列完了但没说清为什么值得做。改成先落在情绪、功能收一句带过。仍是占位。

**⑯ 自定义光标已实现（规格 2.7 从「不做」改为「做」）。** 参数照搬存档值：外圈自转 12 秒、
逐字符 `rotate(i/n*360deg)` 排一圈、圆心 3px 白点带 `0 0 8px rgba(255,255,255,.8)` 光晕、
跟随用 spring(damping 28 / stiffness 280 / mass 0.4) 逐帧积分。

规格 2.7 当初否掉它的两条理由，处理方式分别是：

- **「触屏 cursor 无效」** → 三道门都过才建 DOM：`(pointer: fine)` + 视口 ≥1024px +
  非 reduced-motion。任一不满足整块不启用，连 DOM 都不建。另监听 matchMedia 变化，
  中途拔掉鼠标或旋转平板会退出。
- **「隐藏系统指针是可用性损失」** → **只在 hero 内隐藏**（`.hero.cursor-on { cursor: none }`），
  不动 `documentElement`/`body`。原站是全局 `cursor:none` 再靠 hover 白名单恢复，
  漏一个选择器就有一片区域没有指针；限定在 hero 内则天然安全。悬到
  `button, a, input, select, textarea, [role='button']` 上时环淡出、系统指针立即接管。

按中文调整了四处（原站值 → 实现值）：

| 项   | 原站                                      | 实现                 | 原因                    |
| --- | --------------------------------------- | ------------------ | --------------------- |
| 环文字 | `Touch to Continue • Walk Cat •`（29 字符） | 「点击看完整片段」（**7 字**） | 中文字面宽约为英文两倍，字数不压会挤成一团 |
| 半径  | 40px（外圈 80px）                           | **32px**           | 与字数一起压小，环太大会盖住画面主体    |
| 容器  | 80px                                    | **84px**           | 见下                    |
| 字号  | ——                                      | 10px               | 再小在视频上读不出             |

**不放 `•` 间隔点**：原站用它分隔两个短语，我们只有一个短语，孤立的 `•` 排在环上会被
看成第二个圆心白点（实测截图里确实如此）。首尾也不留空格 —— 空格会占掉一个字符位，
让环出现一段空缺。

**容器尺寸要按字符包围盒实测，不能直接用 `RADIUS×2`**：字心在半径处，字自身还向外占约
半个字高。给 68px（=32×2+4）时四边各裁掉约 6px、环上的字缺角；实测包围盒 81px，
给到 84px 才留出余量。改半径或字号时这个值要重量。

离屏用 `IntersectionObserver(threshold 0.15)` 停掉 rAF，与规格 2.7 原文一致。

**⑰ 第 8 区块（口碑）未按「整块去掉」处理。** 规格 6 章给了两个选项：换成作品展示或整块隐去。
第 11 区块已经承担了作品展示，再放一遍是重复；整块删掉又会让页面少一个说服层次。
折中：保留区块结构与三卡布局，内容换成我们自己的设计取舍，署名明写「示意 · 非用户评价」。
**这仍是占位** —— 正式上线前须替换或删除，见上表第 6 项。

### 10.1 一条约定与它的边界
