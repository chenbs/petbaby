## 0. 结论先行

现有素材的问题不是“不够精致”，而是**只有风格，没有事情发生**。30 张静态图大多采用“单只宠物居中 + 换背景或画风”的安全构图；用户能看懂它是什么，却很少产生“我也想看我家宠物变成这样”的冲动。65 张参考图真正有效的部分也不只是某种画风，而是六类可复用的趣味机制：

1. **反差身份**：宠物成为旅行博主、咖啡师、囚犯、魔法学院学生、时装模特。
2. **正在发生的情节**：偷鱼逃跑、坐过山车、举饮料打卡、对镜自拍，而不是站着摆拍。
3. **主人与宠物的关系**：追逐、抚摸、合影等互动让画面从“宠物素材”变成“我们之间的事”。
4. **可读的信息密度**：图鉴、设定集、九宫格、漫画、电影海报让一张图可以看十几秒，而不只是一眼划过。
5. **社交语法**：夸张表情、第一视角、截图感、字幕梗和竖版封面天然适合朋友圈、小红书或微博。
6. **可拥有的成品感**：产品设计图、包装盒、摆件、画册等让数字图进一步变成礼物或实体商品。

因此不建议继续给 PL-10 增加一批“暖调 / 梦幻 / 油画”式同义风格。建议把图片区重构为**场景模板货架**：用户先选“想让它经历什么”，再选气质；模板决定角色数、构图、镜头、动作与道具，风格只是模板中的一个变量。

首发采用“**8 个一级入口 + 每个入口多个模板**”的两层货架，而不是把入口和模板做成一一对应。原始 65 图批次曾登记 61 个独立模板，视觉审核后保留 55 个 live、下架 6 个；animal 扩展批次历史生成 24 个模板，当前保留 21 个 live、下架 3 个。第 9 个 `human / 如果它是人` 入口下 40 个 V2 条目已完成本地效果图、提示词和计划对象键映射，仍为 `pending-review`，公开 API 仍只返回原有 8 个含 live 模板的入口。旧宠物人化方案和 52 张中间图已撤回；全局注册表为 116 个条目、76 个可生成、40 个等待发布审批。65 张效果图的逐图归属、独立 `templateId`、母版状态和排除项统一维护在 [`28-图片母版货架与65图归档矩阵.md`](28-图片母版货架与65图归档矩阵.md)，animal 批次见 [`30-动物效果图扩展执行计划.md`](30-动物效果图扩展执行计划.md)，宠物人化接入和撤回记录见 [`31-宠物人化两阶段执行与审批记录.md`](31-宠物人化两阶段执行与审批记录.md)。

当前公开的 8 个一级入口为：`好笑出片`、`和我合照`、`旅行打卡`、`职业反差`、`动作剧情`、`角色设定`、`图鉴与档案`、`艺术肖像 / 纪念收藏`。第 9 个 `如果它是人` 只完成注册和工程实现，审批冻结前不公开。免费、单次付费、高客单和实体承接是模板级属性，不是一级入口；同一入口下可以同时存在免费模板和付费模板。

所有正式模板遵守同一条生成原则：**有用户图就走图生图；有模板参考图就把用户图与自有模板参考图一起送给模型；只有两者都不存在时才允许文生图。** 双主体模板必须使用两个独立上传槽位，固定 `主人` 与 `宠物` 的角色对应关系，不能让模型自行猜测。

## 1. 研究口径与限制

### 1.1 样本范围

- 参考集：`apps/website/public/assets/example/`，共 65 张，已逐张审阅，清单见附录 A。
- 现有集：`apps/website/public/assets/` 根目录静态图，共 30 张；另有 1 个背景视频，不计入静态图对比。
- 产品现状：当前 7 个 live manifest、`pages/index`、`pages/create`、`pages/ai-create`、`pages/ai-run`、作品与实体下单链路。

### 1.2 参考集不是可直接上线的模板库

参考集里有明显的平台截图、水印、知名人物、影视/游戏视觉、品牌场景和第三方创作者作品。它们用于内部母版生产时，可以高保真参考**构图、镜头、背景环境、地标氛围、服装、独特道具、文字布局和整体效果**；但原图本身不能打包进客户端、不能作为线上接口长期发送的参考资产，也不能在宣传中暗示与原作者、品牌或 IP 有合作。

上线前每个模板必须重新制作一张**自己的模板参考图**：在内部受控生产阶段将效果图与自有或已获授权的宠物身份图同时送入图生图接口，默认保留效果图的全部场景与视觉细节，只替换原宠物主体。主体替换批次的场景变更预算为 **0%**：不改背景、构图、裁切、光线、色彩、文字布局、服装、地标或独特道具；只有新宠物与既有服装/道具发生物理冲突时，才做最小适配。文字仍可按新宠物和画面内容改成准确可读的内容。效果原图不能作为线上模板、宣传图、产品包内素材或用户运行时请求输入；生成结果需通过主体替换、年龄与品种真实性、画面质量和权利风险审查后才可冻结。用户输入图与正式参考图都属于生产输入，需在隐私说明中明确第三方模型处理、保存周期与删除机制。

### 1.3 分类方法

每张图从五个维度标注：

| 维度 | 取值示例 |
| --- | --- |
| 主体结构 | 单宠 / 主人+宠物 / 同宠多姿态 / 宠物+衍生物 |
| 内容机制 | 剧情 / 身份扮演 / 情绪互动 / 信息图鉴 / 艺术转译 / 社交梗 |
| 视觉语法 | 鱼眼、俯拍、自拍、棚拍、双重曝光、漫画分格、九宫格、设定板 |
| 用户价值 | 好笑想分享 / 好看想收藏 / 有信息想细看 / 有纪念意义 / 想做成实物 |
| 生成风险 | 角色错配、身份漂移、肢体错误、文字乱码、侵权、敏感内容 |

## 2. 参考图分类与可复用特征

同一张图可能同时属于多个类别。下面按其**最值得转化为产品能力的主机制**归类，而不是按文件夹或画风机械分组。

### 2.1 A 类：动作剧情与强镜头，负责“停下来”

代表：`1.png`、`2.png`、`5.png`、`16.png`，以及旅行自拍组 `1786368644435.png`—`1786368934169.png`。

共同特征：

- 画面处在动作中点，而非拍摄前的站定状态。
- 鱼眼、超广角、俯拍、第一视角或自拍臂制造临场感。
- 前中后景都有信息：主体、追逐者/环境、飞散物或地标。
- 表情清楚，动作一眼可读，缩略图状态也有冲突。
- 用户看到的不是“某种滤镜”，而是一个可以转述的故事：“它偷了鱼，我在后面追。”

产品化判断：这是最能提高点击和分享的一类，应成为首页 Hero 与社交传播钩子。模板要锁定镜头与动作，不允许退化为“宠物正面站立 + 背景替换”。

### 2.2 B 类：主人与宠物关系写真，负责“这是我们”

代表：`1.png`、`2.png`、`16.png`、`1786369158880.png`。

共同特征：

- 人与宠物之间存在触摸、追逐、并肩或共同看镜头等关系动作。
- 环境光、距离与视线把两者放在同一空间，而非后期贴图感。
- 情绪可以是荒诞，也可以是亲密；关键不是唯美，而是互动可信。
- 适合节日、到家纪念日、生日、晚年陪伴等高情绪场景。

产品化判断：双主体是现有产品的关键空白，也是比单宠模板更有支付解释的一类。必须要求用户分别上传主人图与宠物图；生成前显示两个角色槽，结果页提供“主人不像 / 宠物不像”定向重抽原因。

### 2.3 C 类：宠物拟人、职业与生活方式，负责“身份反差”

代表：`1786367409484.png`—`1786368555480.png`、`1786368973628.png`、`1786369135481.png`、`b983ec71...jpg`。

共同特征：

- 宠物保持脸、毛色与品种识别点，同时穿衣、工作、走秀、上学或经营店铺。
- 场景、服装、道具成套，形成明确职业或世界观，不是随意加一顶帽子。
- 反差来自“宠物神态仍像它，但身份像人”，容易形成昵称和人设。
- 可连续扩展：咖啡师、奶茶店长、甜品主理人、时装模特、魔法学生、探险队员等。

产品化判断：适合做可持续更新的模板系列与主题周，但要避免低级的“换装相框”。需要至少一个身份动作与一个功能性道具，例如咖啡师要在吧台做咖啡，而不是只穿围裙坐着。

### 2.4 D 类：图鉴、设定板与说明书，负责“值得细看”

代表：`3.png`、`7.png`、`9.png`、`11.png`、`12.png`、`15.png`、`1786368990305.png`、`1786369014024.png`、`1786369023697.png`。

共同特征：

- 一个主体被拆成正侧背、表情、细节、能力、性格、装备或知识卡片。
- 主图与多个小窗形成视觉层级；用户会放大查看，而非划过。
- 文字和图标让作品像“有用的收藏品”，也适合二次传播和打印。
- 同宠多姿态九宫格把一致性本身变成卖点。

产品化判断：这是比普通 AI 肖像更能支撑付费的方向，但模型不适合直接生成大段准确中文。应把流程拆成“模型生成无字主视觉与姿态图 → 程序排版结构化中文与图标”，否则会出现乱码、错误品种知识或伪科学信息。

### 2.5 E 类：艺术转译与叙事海报，负责“收藏与送礼”

代表：`5deeda1a...jpg`、`08bd1d4d...jpg`、`6.png`、`10.png`、`13.png`、`14.png`、`17.png`、`18.png`、`223c5d78...jpg`、`550bc288...jpg`、`1786369038890.png` 及多张水墨/插画头像。

共同特征：

- 不只是滤镜，而是把主体放进一套完整媒介语言：油画笔触、水墨留白、双重曝光、电影海报、角色概念图。
- 主体轮廓、毛发或脸部特征仍然是识别锚点。
- 适合做墙面微喷、画册封面、礼物卡等高完成度成品。
- 双重曝光与纪念性画面情绪强，但不应默认套用于仍在陪伴中的宠物。

产品化判断：保留为高质量模板，但不再按“暖调 / 幻想”这类抽象风格单独售卖；应绑定具体用途，例如“武侠人物志”“云端守护者”“电影主角海报”。

### 2.6 F 类：表情、漫画与社交梗，负责“反复使用”

代表：`4f109cb7...jpg`、`9e6a1f75...jpg`、`9f8ebfc6...jpg`、`1786368804360.png`、`1786368846261.png`、`1786369065023.png`、`1786369082391.png`、`b1d8e78f...jpg`、`bb3a7964...jpg`。

共同特征：

- 表情幅度大、构图简单、语义明确，适合做头像、聊天图和梗图。
- 九宫格和漫画分格给同一宠物建立连续表演空间。
- “殴打主人”“愤怒”“惊讶”等标题或字幕给用户一个发送理由。
- 可利用宠物真实习惯生成个性化文案，而不是所有用户得到同一套“早安晚安”。

产品化判断：免费或低成本高频层更合适，负责拉回访和分享。文字必须后置程序排版；涉及攻击、侮辱的梗要给温和替代，不自动生成针对真实个人的羞辱文案。

### 2.7 G 类：衍生实物与“我想拥有”，负责提高客单价

代表：`3.png`、`1786369051729.png`、`1786369135481.png`。

共同特征：

- 作品不止停留在一张图，而是呈现结构图、包装盒、桌面摆件或大小款组合。
- 通过材质、尺寸、包装和展示环境建立商品可信度。
- 能自然衔接现有“已解锁作品 → 实体纪念品”链路。

产品化判断：首期不承诺真正 3D 建模或盲盒生产。先做“角色设定集 + 包装效果图 + A4 微喷”；若供应链成熟，再加摆件 SKU，必须先完成打样、材质与肖像授权条款。

### 2.8 H 类：只吸收结构、不进入首发

代表：`4.png` 的直播截图、`8.png` 的成人服饰商品页、`6.png`/`17.png` 的知名人物与电影语法、`10.png`/`13.png` 的游戏角色设定。

原因：

- 平台 UI 截图容易制造虚假互动数据或冒充真实直播。
- 成人服饰不符合宠物产品核心，也增加内容审核风险。
- 明确知名人物、球队、影视或游戏角色存在肖像、商标与 IP 风险。

可复用的只有抽象结构：直播界面可转成“本宠直播间”虚构海报，商品详情页可转成“本宠穿搭说明书”，人物海报可转成“宠物生涯高光”，但必须使用自有文字、图形与世界观。

## 3. 现有素材的不足与改进方向

### 3.1 现有 30 张静态素材承担的角色

| 资产组 | 数量 | 当前作用 | 主要问题 |
| --- | ---: | --- | --- |
| `avatar-*` | 3 | 用户评价头像 | 普通生活照，可信但不构成作品卖点 |
| `hero-*` | 3 | 官网首屏信任缩略图 | 仍是普通宠物肖像，不能解释产品能做什么 |
| `detail-*` | 2 | 肖像/纪念详情 | 构图极远或过静，情感与成品细节都弱 |
| `play-*` | 6 | 身份证、海报、画册及 AI 玩法入口 | 多数是产品摆拍或单宠居中，模板差异主要靠外框和背景 |
| `style-*` | 4 | 同一宠物风格对比 | 对比逻辑正确，但四张都保持同一坐姿，差异只剩材质与背景 |
| `work-*` | 11 | 作品瀑布流 | 品种丰富，但镜头、动作、表情和叙事高度重复 |
| `bg-poster.jpg` | 1 | 视频首屏封面 | 氛围有余，真实产出和宠物细节不足 |

### 3.2 核心差距

1. **构图同质**：大量图片是眼平、正面、居中、半身或全身坐姿，用户看第三张就能预测第十张。
2. **缺少动作动词**：现有图可以描述为“猫在画面里”；参考图则是“猫叼鱼逃跑、狗坐过山车、猫在奶茶店营业”。
3. **缺少关系**：现有作品几乎都是单宠，没有主人与宠物的触摸、追逐、并肩和视线互动。
4. **缺少可传播句子**：图片很难被用户一句话转述，因而没有天然标题、评论区问题或分享理由。
5. **风格替代玩法**：`肖像封面 / 绘本主角 / 杂志大片` 与 `暖调胶片 / 纸艺拼贴 / 影棚 / 幻想` 两层都偏抽象，组合后仍可能只得到一张正面肖像。
6. **信息量不足**：没有设定、表情、档案、能力、时间或剧情层，一眼看完。
7. **成品价值弱**：只有少数图片展示装裱或画册；作品柜更像素材陈列，而不是值得购买的商品陈列。
8. **营销图与真实产出边界不够强**：入口样图应证明对应生成器能稳定产出，而不是只证明美术能做一张好图。

### 3.3 改进原则

- 从“选风格”改为“选场景/故事”，风格成为模板内二级选项。
- 每个付费模板至少包含：一个明确动作、一个场景锚点、一个情绪钩子、一个分享标题。
- 首页样图采用“高戏剧 40% + 高亲密 30% + 高信息 20% + 艺术收藏 10%”的内容组合，避免全站只剩夸张梗图。
- 同一模板样图至少展示猫、狗各一例；双主体模板至少展示不同性别/年龄的主人，避免用户误以为只适配某一类人。
- 同一宠物的风格对比继续保留，但新增动作和用途对比；比较项只能变一个变量。
- 入口图、候选图、最终图均保留 AI 显式标识；付费只移除营销水印，不能移除 AI 标识。

## 4. 从参考图沉淀出的模板协议

### 4.1 模板不是一段提示词

每个模板应是一份结构化配置，至少包含：

```json

  "name": "偷鱼大作战",
  "subjectMode": "owner_pet",
  "roles": [
    { "id": "owner", "required": true, "minPhotos": 1, "maxPhotos": 3 },
    { "id": "pet", "required": true, "minPhotos": 1, "maxPhotos": 4 }
  ],
  "referenceAssetId": "owned-ref-fish-chase-v1",
  "composition": "vertical 9:16, extreme-wide low angle, pet foreground, owner background",
  "action": "pet runs toward camera holding a fish; owner reaches from behind",
  "identityLocks": ["pet coat pattern", "pet face", "owner face", "role assignment"],
  "editableFields": ["locationMood", "ownerOutfit", "caption"],
```

`referenceAssetId` 只指向自有或已授权模板参考图，绝不能直接指向 `example/` 的第三方原图。`example/` 可在内部母版生产中作为一次性的效果参考输入，但不进入 manifest、对象存储、线上请求、官网或广告。

### 4.2 主体路由规则

| 效果图主体 | 用户输入 | 角色替换规则 |
| --- | --- | --- |
| 一个主体，无论原图是人、宠物、角色或生物 | 1 个宠物槽，推荐 2–4 张同一宠物照片 | 参考图唯一主体替换为用户宠物；不得保留原人物脸或额外生成另一只主宠 |
| 两个主体，其中一个可解释为主人、一个为宠物 | 主人槽 1–3 张 + 宠物槽 1–4 张 | 主人只映射主人位，宠物只映射宠物位；不得互换、融合或复制 |
| 同一主体多姿态/九宫格 | 1 个宠物槽 2–4 张 | 所有格子是同一只宠物，不得生成多只不同花色宠物 |
| 宠物 + 迷你版/巨型版 | 1 个宠物槽 2–4 张 | 两个形象都来自同一宠物，仅尺度不同；文案明确“同宠分身” |
| 完整人类主体，身份由宠物翻译 | 1 个宠物槽，当前固定 1 张身份照 | 图一使用宠物原图提供身份特征，图二使用自有效果图约束完整人体、服装、姿势、构图和画风，一次生成两张真人候选 |
| 群像或三主体以上 | 首期不开放 | 多角色一致性、上传成本和错配风险过高 |

双主体玩法最低上传 2 张图：主人槽至少 1 张、宠物槽至少 1 张；为了提高一致性，可以分别补充到主人 3 张、宠物 4 张。双主体输入不得用一个通用 `photoIds[]` 混装。即使底层最终仍传数组，产品与服务端协议也应保留 `role=owner|pet`；否则系统无法验证角色归属，也无法为“谁不像”做定向重抽。

### 4.3 图生图是正式生产硬门槛

正式参考图和面向用户的正式成图都必须走图生图。文生图具有构图、角色和风格随机性，只能辅助准备非核心背景或草案，不能直接晋级为模板母版、入口样图或付费成品。

生成输入按以下顺序选择：

1. `用户角色照片 + 自有模板参考图`：正式标准路径。利用多图编辑，把身份来源与构图来源分开。
2. `用户角色照片 + 自有构图底稿 + 结构化模板提示词`：模板母版尚未冻结时的测试路径，仍是图生图。
3. `自有样板角色照片 + 自有构图底稿/上一轮合格图`：生产自有母版和商品样图的路径。
4. `用户角色照片 + 结构化模板提示词`：多图接口临时不可用时的最低降级路径，仍须有角色图片输入；该结果不能替代已经拍板的模板母版。

纯文生图只允许生成不包含核心角色的普通背景、无品牌道具或早期方向草案；产物必须再与自有角色或自有构图底稿合成，并至少经过一轮图生图重构。没有任何图片输入的结果不得进入 `masters/` 或 `final/`。

离线 lingsuan 工具已先后验证双参考和三参考输入：单宠母版生产按“效果图 + 宠物身份图”，双主体母版生产按“效果图 + 主人身份图 + 宠物身份图”，multipart 均按职责顺序重复追加 `image` 字段。平台 Provider 现已扩展为有序 `references[]` 契约；运行时单宠固定为“自有冻结母版 → 宠物”，双主体固定为“自有冻结母版 → 主人 → 宠物”。宠物人化当前固定为“宠物原图 → 自有效果图”一次请求，返回两张真人候选，不生成或缓存身份卡，也不支持重抽。缺少任一必需参考图时明确失败，不得静默回落文生图。

### 4.4 参考照质量门槛

上传时即时检查并给可操作提示：

- 宠物：脸部无遮挡、主体占画面 25% 以上、毛色不被重滤镜改变；最好包含正脸和 45° 侧脸。
- 主人：单人、脸部清楚、无遮挡；双主体玩法不要上传已经抱宠物的合照作为主人槽，以免模型把宠物复制两次。
- 模糊、过暗、背影可以保留在照片库，但不作为身份参考首选。
- 系统自动推荐最清楚的一张为 `identity anchor`，其余照片补充侧面、花纹和体型。

### 4.5 通用提示词骨架

提示词只负责约束模型能理解的视觉任务，准确中文、价格、日期、档案数据由程序排版：


### 4.6 定向重抽而非整组盲抽

候选页在“重抽一组”之外增加失败原因：

- 宠物不像：提高宠物身份参考权重，不改变构图；宠物人化时只加强宠物到人脸的身份翻译，不恢复动物器官。
- 主人不像：提高主人身份参考权重，不改变宠物；仅允许主人+宠物模板使用。
- 太像动物：移除兽鼻、毛脸、动物口鼻和混合解剖，恢复自然完整的成年人体；仅允许宠物人化模板使用。
- 构图偏离：恢复冻结母版中的角色位置、姿势、镜头和场景，不重新设计画面。

这四个原因既改善结果，也形成模板质量数据。模板如果连续出现高角色错配率，应自动下架到 `testing`，而不是继续消耗用户重抽次数。

### 5.3 暂缓模板

- `巨型伙伴幻想`：视觉震撼，但巨型宠物与小宠物的同宠一致性、纪念语义容易误读，已登记为独立模板，必须完成同宠身份和叙事语义门禁后才能开放。
- `宠物漫画连续剧`：需要跨格身份与剧情一致性，单次九宫格可先验证模型能力。
- `直播间截图`：容易制造虚假礼物、人数和平台背书，首期不做。
- `知名 IP cosplay`：不做品牌、球队、影视、游戏角色复刻，只做原创世界观。
- `宠物 + 多位家庭成员`：超过双主体后错配率和上传成本陡增，首期不开放。

## 6. 完整用户流程

### 6.1 单主体

`选择模板 → 选择宠物 → 系统推荐 2–4 张身份参考 → 用户确认 → 选择少量可调项 → 查看预计效果与价格 → 生成四张候选 → 选一张/定向重抽 → 免费保存或付费解锁 → 分享/作品柜/实体下单`

关键要求：

- 在生成前展示价格，不在结果出来后突然告价。
- 生成消耗、候选数量和可重抽次数在按钮旁明确。
- 取不到用户图片字节时，承诺“像它”的模板应明确失败并返还额度；不应静默退回文生图。需求只允许在“没有可用参考图”时退化，不等于存储抖动可以悄悄降级交付。
- 免费模板不建 0 元订单，直接保存。

### 6.2 双主体

`选择模板 → 主人槽上传/选择 → 宠物槽选择 2–4 张 → 分别显示角色预览 → 角色确认 → 生成 → 四选一 → 分角色反馈/重抽 → 解锁`

角色确认页必须显示：

```text
主人角色：张三（头像预览）
宠物角色：年糕（2 张参考照预览）
本模板会把主人放在后景，把年糕放在前景。
```

服务端校验：主人槽不可为空且只能是单人照片；宠物槽必须属于当前宠物档案；两个槽位不能复用同一个文件；任务快照保存角色映射与模板版本，保证后续重抽不漂移。

### 6.3 宠物人化

`选择人化模板 → 选择宠物和 1 张身份照 → 选择对应自有效果图 → 一次生成两张真人候选 → 选一张 → 解锁`

宠物人化不生成或缓存私有人形身份卡，不把旧身份缓存作为新任务输入，也不提供重抽；效果图同时作为货架展示图和运行时图二。完整工程与接入记录见 31 号文。

### 6.4 候选与解锁

- 延续现有“四选一，只解锁选中图”的清晰机制。
- 候选缩略图就必须带 AI 标识和营销水印；高清版移除营销水印，保留 AI 标识。
- 用户选中后再建作品；选择锁定后如已创建订单，不允许无提示换图。
- 模板质量问题导致四张都不合格时，提供一次“本组作废”且不计重抽，触发条件由异常检测或客服审核记录，防止把模型失败转嫁给用户。

## 7. 付费设计

### 7.1 定价原则

1. 不卖“滤镜名字”，卖明确交付物：剧情封面、双人写真、九宫格拆图、图鉴 PDF、角色设定集。
2. 免费层负责传播和回访，不能用 0 元订单制造摩擦。
3. 付费层的溢价来自双主体、信息密度、多页/多图、一致性控制与实体承接，而不是“去掉 AI 标识”。
4. 不引入代币；既有合规方案已判断代币与一次性交付物不匹配。
5. 价格是产品建议，需在真实 Provider 成本、iOS/安卓虚拟支付费率和转化实验后定稿。

### 7.2 建议价格梯度

| 层级 | 玩法 | 建议价 | 用户买到什么 |

### 7.3 会员关系

不建议把所有图片模板塞入 ¥128 年会员“全场免费”：这会重回以低价会员稀释单次交付物的旧问题。更合适的是：

- 会员每月获得 1 次模板定向重抽保障，不是无限生图。
- 会员购买双主体/设定集时包含最高规格或一张附加裁切版。
- 会员继续以现有跨场景权益为核心，图片模板只是小权益，不重写会员价值主张。

### 7.4 支付合规前置

会员和数字作品解锁属于现有 `23-虚拟支付合规改造方案.md` 的待改范围，2026-04-01 截止期已过。新数字 SKU 在该方案完成、场景适用性法律意见明确、按 SKU 选择支付 provider 之前**不得对外上线收费**。实体微喷仍走普通微信支付，不能误接虚拟支付。

## 8. 内容、版权、隐私与质量门禁

### 8.1 版权/IP

- `example/` 原图不得进入生产包、正式模板、官网或广告；仅允许在内部受控的母版生成调用中作为一次性高保真效果参考，可提供场景、地标、服装、道具、文字布局、构图、镜头和动作，调用完成后不保存为线上资产，也不进入用户运行时请求。
- 不提供“迪士尼风、某电影同款、某画师风、某球队海报”等模板名。
- 原创世界观需有自己的名称、徽记、服装与配色，避免近似知名 IP 的整体视觉。
- 用户上传他人肖像时要求确认授权；双主体结果默认私密，分享由用户主动开启。

### 8.2 AI 标识

- 所有 AI 结果遵循既有显式与隐式标识方案。
- 付费只移除 `PETBABY 免费预览`、小程序码等营销水印，不移除 AI 标识。
- 纯程序排版、不修改照片主体的模板也要按实际生成链路标识，不能用同一话术笼统处理。

### 8.3 隐私与数据

- 生成前明确说明用户照片会传给第三方图像服务。
- 角色参考图、模板版本、供应商与模型版本可追溯；不得在日志记录原始图片字节或可公开 URL。
- 取消/失败任务返还额度，并按既有存储策略删除无主候选。
- 主人照片属于更敏感的个人信息。实现已提供独立私有存储、明确授权确认、归属校验、读取与删除接口，并在账户删除时清理；公开发布前仍需把第三方处理说明和删除规则同步到正式隐私政策。
- 历史宠物人形身份卡属于已废弃的用户私有派生素材，继续保留删除清理兼容，但不再由新任务生成、读取或进入样例灌入。

### 8.4 模板上线验收

每个模板用至少 20 只宠物测试，其中猫狗各 8，只看单一品种不算通过；双主体另需至少 12 位不同外观主人。人工盲评：

| 指标 | 上线门槛 |
| --- | ---: |
| 宠物可辨认率（主人能从同类宠物中认出） | ≥ 85% |
| 第一眼可爱度与年轻审美盲评达标率 | ≥ 85% |
| 双主体角色正确率 | ≥ 95% |
| 核心动作/构图命中率 | ≥ 85% |
| 明显多肢、融合、重复主体缺陷率 | ≤ 5% |
| 普通模板四张候选至少一张可用；宠物人化两张候选至少一张可用 | ≥ 90% |
| 中文排版准确率（程序层） | 100% |

模板不达标时回到 `testing`，不能靠增加用户重抽次数掩盖稳定性问题。

## 9. 数据与实验方案

### 9.1 漏斗事件

在现有 `plugin_selected / ai_created / ai_succeeded / candidate_selected` 基础上补模板维度：

- `image_template_impression`
- `image_template_opened`
- `role_upload_started / completed`
- `generation_started / succeeded / failed`
- `candidate_feedback`（宠物不像/主人不像/动作不对/太乱）
- `candidate_selected`
- `unlock_started / paid`
- `saved_to_album`
- `share_created / share_visited`
- `physical_order_started / paid`

所有事件带 `templateId`、`templateVersion`、`subjectMode`、`provider`、`modelVersion`，不带照片 URL、人脸特征或用户提示词全文。

### 9.2 首轮实验

1. 首页入口：现有“AI 宠物肖像”卡 vs “偷鱼大作战”剧情卡，观察卡片点击率。
2. 选择方式：先选抽象风格 vs 先选具体场景，观察上传完成率与生成启动率。
3. 候选反馈：仅“重抽” vs 分原因定向重抽，观察二次可用率与退款/投诉。
4. 双主体价格：¥16.9 vs ¥19.9，前提是两组使用同一质量门槛，不用降质换低价。
5. 免费钩子：通缉令 vs 九宫格，观察保存率、分享率和 7 日回访。

### 9.3 阶段门槛

- M0 样图验证：当前 55 个原始批次 live 模板与 21 个 animal live 模板分别做 20 组内部测试并达到第 8.4 节门槛；宠物人化 V2 已完成本地素材映射，仍待发布审批和真实双参考验证，且不继承旧两阶段方案的候选、测试或审批结论。
- M1 小流量：只开免费 3 款和付费 2 款；付费链路须先通过虚拟支付合规门禁。
- M2 扩品：任一模板在 500 次打开后，生成启动率 < 12% 或四选一可用率 < 90%，下架复盘，不继续堆流量。
- M3 实体：数字设定集达到稳定购买和低退款后，再做供应链样品；没有实物打样不得在效果图上写“可定制摆件”。

## 10. 自有参考图生产方案

### 10.1 目标与资产边界

V1 当时建立了一套可追溯、可迁移、能真实代表生成器能力的自有参考图库：8 个一级入口下登记 61 个独立模板，生产基线为 23 个冻结母版、38 个待视觉审批候选；后续审核、冻结与下架结论已把原始批次收敛为 55 个 live，叠加 animal 扩展 21 个 live 和宠物人化 V2 的 40 个 `pending-review` 条目，当前全局货架为 76 live / 40 pending-review。第三方 `example/` 原图只允许在内部受控母版生产中作为一次性图生图效果参考，用于高保真提供背景环境、地标、服装、独特道具、文字布局、构图、镜头、动作和氛围；运行时的主体替换场景变更预算为 0%，不重新设计环境，也不为了变化而添加或替换内容。效果原图不进入成品目录、正式模板、对象存储、官网、广告或用户线上请求。

自有输入资产包括：

- 自有或已获得明确授权的宠物照片、主人照片。
- 自行拍摄、程序搭建、购买完整商用授权或内部生成后重新合成的场景底稿。
- 自制线框、姿势草图、色块构图和道具拼贴；底稿必须记录素材来源与授权状态。
- 上一轮人工验收通过的图生图结果；每轮只能沿合格结果继续细化，避免反复随机重开。

### 10.2 样板角色体系

首轮固定使用多个辨识度明显的自有或已授权样板宠物，以及 4 位独立授权主人（`owner-f01`、`owner-f02`、`owner-m01`、`owner-m02`，2 女 2 男）；原始主人照片仅允许用于内部母版生产和稳定性验证，不进入客户端、公开样例或营销素材。每个角色应准备正面、左右 45 度、侧面、全身和动作照，背景简单、主体清晰、不带强滤镜。首批至少覆盖德文猫、暹罗/布偶/缅因/美短/折耳/三花等猫型，以及金毛、德牧、边牧、贵宾、柯基、柴犬、腊肠、马尔济斯、灵缇等犬型，并让不同效果图和不同玩法优先分配不同品种；同一品种只有在做身份迁移对照时才允许复用。

“摩奇”只指宠物小岛的卡通示例宠物。既有离线代码曾把真实橘白对比样板命名为 `MODEL_PET/mochi`，现已改为 `legacy-tabby`；它与小岛卡通角色无关，V1 自有参考图库不以它为统一主体，也不再把真实照片称作“摩奇”。

双主体玩法必须同时具备主人和宠物两个独立输入槽。只有宠物图时，只能测试单主体玩法，不能生成一个随机主人并把结果计入双主体通过率。

### 10.3 单张母版的图生图流水线

1. **双参考输入**：效果图固定在第一个输入位，作为主要效果与场景参考；自有宠物图在后续输入位，作为宠物身份和可爱度参考。默认保留效果图的核心构图、场景类型、叙事动作、地标、服装、独特道具和文字布局，只清除并替换原宠物主体。
2. **场景锁定轮**：以效果图为不可变编辑底图，使用遮罩锁定背景，只开放原宠物区域和允许移除的平台水印；不改变场景内容、构图、色彩、文字、服装、地标或独特道具。
3. **身份轮**：身份图只提供品种、毛色、花纹、耳形、眼睛颜色、实际年龄和自然体型；效果图提供动作、表情、透视、笔触、风格、毛发画法和五官画法。不得把身份照片的写实光线、毛发细节或年龄感带入结果，也不得幼化或美化新宠物。
4. **缺陷轮**：针对手、爪、接触点、道具边界、重复主体和局部遮挡进行定向修复，不改变已通过的构图。
5. **风格轮**：统一光线、色彩、镜头质感和材料细节；仍以最后一张合格图继续图生图。
6. **成品轮**：放大、裁切、检查安全区。原图已有文字可保留，或按新宠物与实际内容改成准确、可读的文字；大段中文和结构化信息仍优先由程序后置排版，禁止乱码和内容错配。
7. **迁移轮**：冻结母版后，运行时只上传“自有冻结母版 + 新宠物身份图”，不再上传第三方效果图。每张单宠母版各替换成另一只猫和另一只狗；双主体再替换主人。核心构图和动作仍成立，母版才可进入线上候选。

自有参考图库的成品尺寸只有两档：所有竖版统一为 **720×1280（9:16）**，所有横版统一为 **1280×720（16:9）**，不再生产 3:4、4:5、4:3 等其他成品比例。提示词、接口请求、本地裁切和元数据必须使用同一档尺寸；由于 lingsuan 可能不严格遵守请求的 `size`，最终文件必须经过本地强制裁切并回读宽高，尺寸不符不得进入候选目录。历史预览不追溯改尺寸，新版本生成开始执行本规则。

任何一步不合格都只回退一轮，并记录失败原因；不得通过提高变化强度反复抽卡来掩盖模板不可控。文生图若用于准备背景，必须停在第 1 步之前，不能跳过后续图生图流水线。

### 10.9 lingsuan 请求队列约束

所有 lingsuan 文生图和图生图请求必须先进入共享 FIFO 队列，禁止脚本用 `Promise.all` 直接把整批 HTTP 请求同时发给供应商。离线素材工具默认串行，可通过 `LINGSUAN_IMAGE_CONCURRENCY` 或脚本任务池参数提高吞吐，但有效值始终限制在 1～20；即使误填 21 或更大，实际同时运行的供应商任务也不得超过 20。可重试的网络错误、429 和 5xx 在首次失败后最多重试 3 次，明确不可恢复的其他 4xx 立即失败；失败、超时和重试都必须由队列释放或重新占用槽位，不能造成永久卡槽。

平台运行时的 PL-10、岛立绘和后续模板生图共用同一个进程级队列，不能为每次 `generate()` 单独创建并发池。生产部署保持单个 Worker 实例；若未来增加 Worker 副本，必须先实现跨进程的数据库租约或独立队列服务，确保所有副本合计仍不超过 20，而不是把“每个进程最多 20”误当成供应商全局最多 20。
