## 1. 当前产品契约

宠物人化不再先生成人物身份卡。每个任务只执行一次图生图：

```text
图一：用户选择的原始宠物照片
图二：与目标模板对应的自有效果图
固定提示词 + 模板专属提示词
  -> lingsuan 单次请求
  -> 2 张候选
```

硬约束：

1. 图二参考权重为 80%，尽可能保持场景、色调、服饰、动作、风格、画质和细腻程度。
2. 每张效果图拥有一段不同的模板专属提示词，占 10%。
3. 宠物特征翻译规则占 10%，重点转译眼睛颜色、毛发颜色、脸部比例、口鼻、神态与材质关系。
4. 最终只允许一个完整、自然、可信的真人，不出现动物、动物口鼻、毛脸、羽毛、爪子或混合解剖。
5. 每次固定生成 2 张，不支持重抽；失败重试仍属于任务恢复，不等于重抽新一组。

固定第一部分当前文本为：

> 参考图二生成新图，图二参考占比重70%，要保持图二的场景、色调、动作、风格、画质、细腻程度。允许修改五官的颜色、头发、装饰、颜色、形状、服饰

固定第一、三部分在 `buildImageTemplatePrompt()` 中维护；第二部分从 `pet-human-effect-prompts.json` 按模板 ID 注入。

## 2. 效果图存储与登记契约

暂存效果图推荐为 `720x1280`、9:16 竖图，文件名使用 `<id>.png|jpg|webp`。该目录位于部署镜像之外，后端运行时**不能直接读取这里的本地文件**。

正式运行前需要把效果图上传到后端对象存储并登记对象键。宠物人化与普通模板不同：同一张自有效果图既是用户在模板货架看到的展示图，也是 lingsuan 请求中的图二，因此其 `sampleStorageKey` 与 `masterStorageKey` 必须指向同一个对象。

标准化提示词格式：

```json
[
  {
    "id": "human-template-id",
    "prompt": "该效果图专属的第二部分提示词"
  }
]
```

运行时会拒绝空 ID、空提示词和重复 ID；任一 `live` 宠物人化模板缺少专属提示词时启动即明确失败。

## 3. 已完成代码改造

- `growth-service.ts` 的宠物人化引用顺序为 `pet-identity`（图一）→ `effect-reference`（图二）。
- 新任务不调用 `ensurePetHumanIdentity()`，不写人物身份缓存、身份 ID、提示词版本或身份生成成本。
- 宠物人化候选数量固定为 2；普通模板和小岛仍为 4。
- 宠物人化 `rerollRemaining` 固定为 0，服务端重抽返回 `AI_REROLL_NOT_SUPPORTED`（HTTP 409）。
- Web 与小程序创建页显示 2 张候选，结果页隐藏重抽原因和重抽按钮。
- 作品说明按主体模式写“二选一”或“四选一”。
- 模板 API 下发 `candidateCount` 与 `rerollSupported`。

迁移 `0026_pet_human_identities.sql`、`pet-human-identity-service.ts` 及删除清理调用仍保留，用于兼容和清理历史数据。它们不是当前生成链路，不得因文件仍存在而重新接回。
