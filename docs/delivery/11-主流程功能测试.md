# 主流程功能测试

日期：2026-10-08。目标是确认主要功能可以正常使用，重点发现点击无反馈、持续加载、异常报错和主流程缺陷；不是全面兼容性或发布验收。

**用户复核后的更正**：此前“本地主要流程已跑通”的结论过宽。合成纯色照片、占位 AI 结果和接口成功，不能证明用户看到的作品正常，也不能证明每个玩法真实出片。当前测试账号中蓝色封面/视频源于纯色输入，橙色 `PET 1` 为开发适配器占位结果；人化失败为缺素材路径测试，两条视频失败实际源于当时 Worker 找不到 ffmpeg，并非主动注入的故障。下面的“开发模式”仅代表调用、扣费、归档等链路，真实 AI 效果仍未验收。

## 测试方式与账户

- 开发者工具实际运行小程序，检查页面状态、入口、充值组件和接口结果；用移动浏览器 E2E 补测 Web/H5 流程。
- 使用独立测试账户和隔离测试服务，不清空日常开发数据库、不消费用户的冻干、不调用收费生成服务。
- 分别覆盖余额充足、不足与零余额；取消充值后恢复操作，模拟充值后重放原操作。
- 本地生成、支付与健康模型采用开发适配器，真实服务和手机系统交互列入用户验证清单。
- 每项记录实际执行结果与证据；未执行或仅模拟的部分明确注明。
- 测试使用独立 PostgreSQL 数据库、3300 端口服务和真实 Worker。三个独立账户分别为：充足账户（起始 53 颗，后用开发充值补充）、不足账户（健康导出时 3 颗，单张/套餐/视频测试时 1 颗）、零余额账户（0 颗）。零余额准备通过测试账户的钱包扣减服务完成，不修改用户账户。
- 开发者工具对嵌套自定义组件的元素点击支持不完整。健康导出用真实按钮组件的 `handleTap` 发出绑定事件，充值/关闭走真实组件方法，其余主要交互以页面事件方法驱动。页面及组件实际运行、请求真实隔离后端；这类证据不能替代手机上的手指点击验证。

## 发现问题与复测

| 问题 | 原因与处理 | 复测 |
| --- | --- | --- |
| 很多 `request:fail` | 当时 3000 端口没有后端进程；局域网地址没变。重新启动开发后端 | 本机、局域网 `/api/health` 返回 200；最终小程序回到正常后端 |
| 0 颗导出健康档案一直等待（此前定位） | 钱包 JS 已更新，但页面 JSON 编译缓存缺少充值组件；请求结束后仍等待不可见面板的事件。已清编译缓存、固定组件 ID、增加组件缺失兜底；后端余额预检移到 PDF 制作之前 | 本轮使用真实隔离后端验证不足/零余额面板、取消、充值后自动继续；均解除忙碌状态 |
| 写真/套餐页就地上传总是报错 | 前端来源为 `ai-create` / `art-photo-bundle`，后端来源枚举缺少这两个值 | 扩充来源契约及类型；两个入口各复测上传成功，新增回归用例 |
| 健康档案下载错误/打不开时无反馈 | 未检查下载 HTTP 状态，系统打开文件没有失败回调 | 增加下载中提示、15 秒超时、HTTP 状态检查及打开失败提示；404 在模拟器可见提示，错误文件不再交给系统打开 |
| 年度报告下载扩展名错误 | 新产物为 PNG，下载接口固定给 `.svg` 文件名 | 按实际 MIME 设置 `.png` / 历史 `.svg`；真实 PNG 下载与两种格式回归通过 |
| 视频完成后显示 `ready` 英文状态 | 端上状态映射未覆盖新完成状态 | 补全完成状态映射；模拟器显示「已完成」 |
| 纪念册作品点击保存报错 | 详情对 PDF 显示图片保存按钮，把 PDF 传给相册 | 改为带文档菜单的 PDF 打开入口；覆盖下载失败、打开失败、重复点击与取消；模拟器真实点击后请求完成、按钮恢复 |
| 证件照无法可靠保存到手机相册 | 免费正式产物为 SVG，浏览器能显示但微信相册不支持该交付格式 | 新生成任务同时保存完整分辨率 PNG；历史 SVG 的鉴权预览和图片下载响应转换为 PNG，不改历史文件/版本；回归覆盖文件字节、尺寸、MIME、扩展名及其他账户拒绝访问 |
| 失败任务一直显示在“进行中” | 作品柜把失败、草稿和待挑选结果都放进该栏 | 栏目及筛选名称改为“制作记录”，不再对终态失败提示“好了会通知你”；保留失败和退款记录供回查 |

环境问题：隔离 Worker 起初找不到 ffmpeg，已配置本机可执行文件和中文字体；视频及年度影片随后实际成片并下载。自定义 Next 构建目录被 lint 当成源文件扫描，已补上缓存忽略规则，再跑完整校验。

本轮验证命令和当前数量统一见 [文档索引的验收快照](../README.md)。已执行平台 `pnpm check`、独立 PostgreSQL + Worker 的 `pnpm test:e2e`、小程序 `pnpm validate`。未提交、未发布，测试使用合成照片，不修改用户账户或日常开发数据库。

第一轮结束曾恢复原账号与后端。用户要求查看测试作品后，已重新启动原隔离库对应的 3300 服务/Worker，切换至充足测试账号；本轮保留该账号和环境供用户查看，日常 3000 服务仍运行。没有删除或替换占位结果以伪装真实出片。

## 失败记录与红蓝预览原因复核（2026-10-09）

直接查询原隔离 PostgreSQL 的任务、作品及钱包流水，并下载作品实际响应与存储文件逐一比对，未改任务状态或替换测试结果。

- 两条列表中的短片项目对应渲染错误均为 `spawn ffmpeg ENOENT`，三次尝试后进入失败；各扣减的冻干已按原业务键返还。修正 Worker 的 `FFMPEG_PATH` 后另建的短片在首次尝试完成、已有正式 MP4；旧失败项目保留原状态，不会因配置修好变成成功。另有一条早期年度影片因同一错误失败并退款。
- “蓝天白衣”对应 `human-effect-31`，错误为“必需参考图不存在，请重新选择或联系运营补齐母版”，三次尝试后失败并返还原扣费。隔离对象目录缺少该模板必需效果图，不是照片显示组件故障，也尚未走到真实供应商调用。
- 成功写真、人宠和套餐逐张任务的数据库记录全部为 `provider=local`、`model_version=local-v1`。隔离环境主动清空真实 AI 接口与密钥，因此走本地占位生成器；它绘制红橙底、圆形和 `PET 1`，再正常保存为 PNG。响应字节与存储产物完全相同，说明展示的是占位产物本身，不是网络下载失败后出现的红色占位。
- 原测试照片 `functional-test.png` 为 240×320 的纯蓝图，像素三个通道分别恒为 66/123/209。身份证把该图放入证件区域，短片以该图实际渲染，因而两者仍是蓝色。视频和 PDF 的响应为有效 MP4/PDF，均与存储文件字节一致。
- 作品列表对普通图片读取结果 `outputUrl`；但对视频/PDF/H5 读取输入照片 `photo.url` 作封面，所以这些蓝色卡片不能证明成片失败，也不是视频抽帧或 PDF 页面缩略图。当前实现确实没有为这几种类型提供成片缩略图。

## 需要用户验证

按下面顺序走一遍即可，无需逐项重复本地回归：

1. **手机常用按钮与返回**：从首页进入写真、记录、健康；轻点提交/关闭充值面板/返回，确认按钮有反应且不会一直转圈。特别复测 0 颗导出健康档案后关闭面板。开发者工具的组件方法验证不能代替这一步。
2. **拍照、相册及文件权限**：就地上传一张照片，保存一张作品到相册、拒绝权限后重试；下载/打开健康 PDF，检查中文显示与打印。iOS/Android 各至少一次。
3. **真实微信登录与付款**：首次登录；在不足余额时取消付款，再付款成功，确认冻干入账及原操作只执行一次。这轮只用开发付款，没有实际扣人民币。
4. **真实 AI 出片**：单宠、人宠、人化各做一单，检查真实照片输入、身份相似度、选片和保存；人化的成功链路本轮未使用待发布效果素材验证。本地占位生成不能证明成片质量。
5. **微信分享、订阅及网络切换**：分享给另一个微信号打开，撤销后再打开；订阅允许/拒绝；手机断网提交、恢复网络后重试，确认页面能恢复且不重复扣费。
6. **外部履约**：真实实物支付、退款及供应商制作/物流。隔离测试只验证下单、开发支付和印刷文件，不代表供应商已履约。

结论：余额充足/不足/零余额、取消、失败恢复及部分文件生成有本地证据；作品详情的 PDF/SVG 缺陷已修复。不能据此认定每个玩法真实生成成功或全部主流程已验收；单张/套餐/人宠/人化的真实 AI 出片和上述手机/外部服务项目仍待验证。
