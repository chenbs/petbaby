# 独立官网实现说明

`02-独立官网实施方案.md` 是方案，本文是**它的实现记录**：产物在哪、怎么验、与方案有哪些偏离、还差什么。

代码在 `apps/website/`（Astro 7，纯静态）。方案正文保持原判不改写，偏离逐条记在第 4 章 —— 与 `docs/demand/` 和 `01-KittyPaw复刻规格.md` 同一个约定。

---

## 1. 常用命令

全部在 `apps/website/` 下执行（本仓库不是 pnpm workspace，不能用 `pnpm --filter`）：

```bash
pnpm install
pnpm dev              # 本地预览，localhost:4321
pnpm build            # 构建到 dist/，含 content schema 校验
pnpm check            # astro check：类型与模板诊断
pnpm check:links      # 站内链接、资源、canonical 与 sitemap 的一致性门禁
pnpm check:pixels     # 首页与原型的逐像素比对，改首页结构后必跑
pnpm verify           # 浏览器端验收断言 63 条，见第 5 章
```

后两条需要 Chromium 与 sharp，两者从 `apps/platform/node_modules` 借（官网自己不装 Playwright）。跑之前先 `pnpm build`。

`pnpm verify` 覆盖「只有真在浏览器里跑才能验」的五组：首屏 CLS 与图片属性、小程序码三触点的双轨交互与键盘可达、文章正文排版、solid 顶栏实测对比度、法务页与 404。它需要 Chromium，改交互或样式后手动跑。

原实现曾在 `.github/workflows/ci.yml` 配置 `website` job；该工作流已于 2026-08-22 删除。当前 `install → check → build → check:links` 需手工执行，恢复等价 CI 门禁属于发布前事项。

## 3. 三条不能破的约束

**`src/styles/site.css` 与 `src/scripts/site.js` 是原型文件的逐字节副本。** 已用 `cmp` 验过。原型的视觉一致性靠「同一份 CSS 文件」保证，不是靠人工比对 —— 要改样式就说明视觉出现了偏差，先停下来查原因。新页面类型需要的样式一律进 `src/styles/site-additions.css`，正文排版进 `prose.css`。

**素材三处同步。** 真源 `tools/imagegen/out/website/` → 原型 `docs/website/prototype/assets/` → 官网 `apps/website/public/assets/`。`release-website.sh` 会逐张 `cmp` 并在不一致时 warn，但**不自动同步** —— 哪份是新的只有人知道，脚本猜错会把新图覆盖成旧图。

**域名只有一个来源。** `SITE_URL` 环境变量同时喂给 `astro.config.mjs` 的 `site` 与 `src/config/site.ts`；`robots.txt` 与 `llms.txt` 都是端点而非静态文件，从同一个常量渲染。canonical 与 sitemap 逐字一致是硬要求，`check:links` 会双向核对。

## 4. 与方案的偏离（逐条）

**① 占位用可渲染的值，不用 `{{BRAND_NAME}}` 字面量。** 方案第 10 章的表格写的是把占位串放进 `src/config/site.ts`。字面量会直接渲染到页面上显示成「{{BRAND_NAME}}」，首屏当场破相，也过不了第 13 章第 1 步的逐像素比对。改为：品牌名沿用原型的「宠物星尘」，域名沿用 `petbaby.example.com`，收口靠三处定位 —— `site.ts` 的 `PLACEHOLDERS` 清单、页面上可 grep 的 `data-placeholder` 属性、`SITE_URL` 环境变量覆盖。

**② `robots.txt` / `llms.txt` 走端点，不进 `public/`。** 方案第 3 章的目录表把它们放在 `public/` 下。但 `Sitemap:` 那一行的域名必须与 canonical 一致，静态文件里写死域名的话收口要改两处，而漏改不会报错、只会让搜索引擎抓一个不存在的 sitemap。

**③ 弹框圆角用 `--radius-play` 而非方案写的 `--radius-clay`。** `site.css` 里没有 `--radius-clay`；同值（28px）的既有变量是 `--radius-play`。不新造变量。

**④ 首页不建 `blog/index.astro`，分页统一由 `[...page].astro` 产出。** 方案第 3 章的目录表同时列了 `index.astro` 与 `[...page].astro`，两个文件都能匹配 `/blog/` 会撞路由。`paginate()` 本身就会把第一页产在 `/blog/`。

**⑤ 逐像素比对截到页脚为止，页脚单独用结构断言核。** 页脚是刻意与原型不同的：方案 7.6 要求加「文章」入口、11.1 要求加 ICP 备案位、第 4 章要求法务链接指向真页面而不是 `#home` 死链。这些都改变页脚高度；在页脚里做 DOM 手术把它改回原型的样子，比对的就不是真实产物了。比对范围内（1–11 区块）三档全部 **0 差异像素**。

**⑥ 顶栏右侧多包一层 `.topbar-actions`。** 原型顶栏右侧只有菜单一个元素、直接当 flex 子项；现在是「扫码 + 菜单」两个。这一层只做 flex 行，不引入视觉变化（逐像素比对可证）。

**⑦ 标签 URL 把空格换成连字符。** 「AI 肖像」若直接 percent-encode 成 `AI%20肖像`，产物目录名里会真的出现一个空格，在静态托管、日志分析、手工 curl 之间反复出问题。中文原样保留（URL 里保留中文对用户更可读）。

**⑧ noindex 页面不给 canonical。** 404 会以任意错误路径被访问到，canonical 指向 `/404/`（一个 Nginx 上并不存在的地址）比不给更糟 —— canonical 指向死链是明确的错误信号。

**⑨ 加了 `sharp` 依赖。** 方案的技术栈表没列它，但文章封面用 `image()` 时 Astro 需要它做尺寸优化，缺了构建直接失败。版本钉在 `0.35.3`，与 `apps/platform` 一致。

**⑩ `release-website.sh` 的软链切换不做 `rm` 兜底。** 方案第 8 章只说「原子切换 + 软链」。实现时先写了 `mv -T … || { rm -f current && mv … }` 的兜底，实测发现 `rm -f` 删不掉目录 —— 当 `current` 是目录（早期手工 rsync 的遗留）时，兜底静默失败、旧版本继续对外服务，而脚本照样报「发布完成」。改为：`current` 存在但不是软链时直接 fail 并提示人工挪走；切换后再断言 `readlink` 真的等于本次的目录。

## 5. 验收结果

| 方案第 13 章的步骤 | 验收标准 | 结果 |
| --- | --- | --- |
| 1 骨架与首页 11 区块 | 与原型逐像素比对三档断点 | **390 / 768 / 1440 全部 0 差异像素**（重复两次一致） |
| | CLS 仍为 0 | CLS **0**（两档实测），29 张图全带固有尺寸、26 张 lazy |
| 2 小程序码三触点 | 桌面悬停 / 触屏点击都能开关 | 桌面 mouseenter/mouseleave、iPhone 13 tap/再 tap/点外部，全通过 |
| | Tab 可达、Esc 关闭且焦点返还 | Tab 顺序 品牌 → 扫码 → 菜单 → CTA；Esc 后焦点回按钮 |
| | hero 内与 CTA 区不显示悬浮按钮 | 四段滚动状态全部符合（hero 内隐藏 → 玩法区显示 → CTA 区淡出 → 离开又显示） |
| | reduced-motion 下无动画 | `opacity:1`、`transition:0.001s` |
| | 重跑首屏性能核验 | 加完两个按钮后 CLS 仍 0，逐像素基线未变；弹框内的码是 `lazy` |
| 3 SEO 基础设施 | sitemap 可解析且 URL 与 canonical 逐字一致 | 10 个 URL 双向核对无遗漏，全部带末尾斜杠 |
| | 结构化数据按页面类型给 | 首页 `Organization+WebSite`、列表/标签/法务 `+BreadcrumbList`、详情 `+Article`；无 `Product`/`Offer`/`FAQPage` |
| 4 文章模块 | 放 2 篇真实文章跑通 | 2 篇，列表/详情/标签/分页/RSS 全通 |
| | 故意写错 frontmatter 应在构建时报错 | 四个字段（title 超长、description 过短、日期非法、tags 类型错）全部被挡 |
| | 正文列表有符号、行内链接有下划线 | `list-style: disc` + `padding-left: 24px`；链接 `underline`；表格/引用/`th`/`strong` 均有样式 |
| 5 法务两页 + solid 顶栏 | 页脚链接不再是死链 | 指向 `/legal/terms/` `/legal/privacy/`，`check:links` 确认命中产物；页面上 `href="#home"` 归零 |
| | solid 顶栏在浅底上可读（实测对比度） | 滚动到正文中段实测 **12.79–13.03:1**；方案给的算值（13.12 / 5.54 / 5.20）复算一致 |
| | 未定稿提示条醒目 | 主色描边 `rgb(196,51,92)` + 浅底，7 个章节骨架 |
| 6 部署与 CI | staging 走通一次发布 + 回滚 | 连续 4 次发布验证原子切换与旧版本清理（`KEEP_RELEASES=2` 生效）；回滚切软链瞬时生效 |
| | 死链检查通过 | `check:links` 检查 11 页 / 10 canonical，全部命中 |

Nginx 的 `try_files` 规则按真实产物树逐条核过：15 条路径（目录式 URL、`.txt`/`.xml` 端点、素材、不存在路径）解析结果全部符合，`error_page` 目标存在，`/_astro/` 13 个文件名都带内容哈希（可 `immutable` 长缓存），`/assets/` 31 个不带（故只给 7 天）。

**未在真实环境验证的部分**：宿主机 Nginx 的实际加载（本机没有 Nginx，只做了配置语法与路由规则的静态核对）、HTTPS 证书、`release-website.sh` 的发布后 `curl` 校验段（需要真实域名）。软链切换在 Windows 上靠 `MSYS=winsymlinks:sysfile` 取得真实符号链接语义后验证；Linux 上语义相同。

## 6. 还差什么

**上线硬阻塞只有一项：小程序码。** 生成后放 `apps/website/public/assets/miniprogram-qr.png`（PNG ≥430×430、无白边、不做有损压缩），再把 `src/config/site.ts` 的 `MINIPROGRAM_QR.available` 改成 `true` 即可，无需改其他代码 —— 三个触点共用这一个文件。未提供前三处都渲染虚线占位框。

`available` 是手工开关而不是自动探测：静态构建没法探测 `public/` 下的文件是否存在。

其余占位见 `src/config/site.ts` 的 `PLACEHOLDERS` 清单（品牌名与 logo、正式域名、og:image、主标语、用户评价、信任条时长、ICP 备案号、法务正文）。域名收口不必改代码，构建时传 `SITE_URL=https://真实域名 pnpm build`，或在 `deploy/.env.<mode>` 里设 `WEBSITE_URL`。

两件必须走流程、代码这边代办不了的事：

1. **ICP 备案是国内服务器托管的前置条件** —— 没有备案域名解析不了，占位只是让代码先跑通。
2. **法务正文必须在面向真实用户开放前替换** —— 内部预览、给同事看不受影响。半真半假的隐私政策比空页面风险更高（用户会当它是承诺，而它没经过法务审核），这也是占位刻意写成「草案骨架 + 未定稿提示条」的原因。

主域给官网后，应用挪到 `app.` 子域的连带改动见方案第 9 章（`PUBLIC_APP_URL`、Nginx `server_name`、证书、微信支付回调与小程序 request 域名白名单）—— 那不是官网侧的工作，但漏了会出故障。
