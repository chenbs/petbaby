## 已记录的实现差异与产品边界

1. 有在途依赖时，删除照片返回 409。处理中的 AI/视频不能通过只改状态来「取消」并放开删除，否则 Worker 仍可能读取或归档；已有取消能力受真实任务状态限制。图文生成本轮没有新增取消入口，须等待任务结束再删除。
2. 年度视频原有按字符串拼接 `source_id` 的方式不满足 UUID 列，现按 user、pet、year 的 SHA-256 稳定 UUID 生成；不同宠物同一年不再互相覆盖。
3. 年度预览与确认没有独立 token/version 合同：确认时重新校验所选照片 ID 和归属，冻结**确认时最新的**有效日期/来源及 aggregate；排队后的图库变更不影响这份快照。预览与确认之间不锁定元数据。普通视频仅冻结入队素材和配置，标题仍可取项目当前值；旧队列缺 `photoIds` 时按冻结对象键找回原照片，不改用最新草稿。这两种快照范围不同。
4. 事务外部对象写入通过回滚补偿登记持久清理任务；它覆盖已知回滚和存储删除失败路径，不能宣称进程崩溃在任意写入时刻都零孤儿。
5. 原媒体访问坚持 owner-only、`no-store`；分享、互动和纪念出口读取独立 JPEG/衍生对象。历史作品封面在删除原照前补齐独立展示图；头像上传入口本就生成独立 `private/<userId>/avatars/*.webp`。作品柜的 PDF/H5/视频显示独立照片封面，不把文件本身交给图片标签。
6. 小程序制作草稿的 **task 字段**仅保存任务 ID/状态，不持久化完整任务响应；原有 review、coverTitle 等草稿字段仍保留。离页增加轮询代次，迟到响应不覆盖新一轮请求。已知终态成功/失败后清除 task/submission；提交响应丢失而尚未取得 task 的未知状态保留原提交键，以免重复创建任务。
7. `selectAiCandidate` 按宠物→AI run→照片的顺序加事务锁；等待锁后重读已有 workId，并发选择只归档一个作品，删除原照后未归档候选不能再新增原照引用。宠物人化仍固定宠物图一、自有效果图二、两候选、不生成身份卡且不支持重抽。
