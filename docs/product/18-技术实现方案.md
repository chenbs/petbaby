## 0. 全局技术约束（先读）

这几条是本仓的既有陷阱，改造中每一项都可能踩到：

1. **新增迁移必须三处同步**：① `drizzle/00NN_*.sql` 前向 SQL；② `client.ts` 第 61 行起的**硬编码** `readFile` 清单；③ `resetDatabaseForTest()` 的 TRUNCATE 表清单与重跑文件名。只做①会让本地与 E2E 拿不到新表。
2. **迁移一律 forward-only**，不改历史文件。
3. **已部署环境改 `registry.ts` 不自动生效**（`runtime.ts` 只在首次访问播种），manifest 变更需走后台 `updateRuntimePlugin` 或逐键回填；**回填逐键合并，不整行覆盖**。
4. **覆盖率白名单**（`vitest.config.ts`）含 `domain/**`、`plugins/**`、`platform-service.ts`、`generation-worker.ts` 等 7 项，阈值 lines/functions/statements 75%、branches 65%。**给这些文件加分支必须同步补测试**，否则 `pnpm check` 挂。
5. **小程序 `.wxss` 不得出现硬编码颜色/圆角/阴影/间距/字号与 `rgba(`**，新组件必须在同页 `usingComponents` 注册（`validate` 第 10 项），标签必须闭合（第 11 项）。
6. **主题注入串有 2KB 硬门禁**，与主题无关的常量进 `theme/tokens.js` 的 `CONSTANT_VARS` 并与 `app.wxss` 的 `page{}` 逐字一致。
7. **`server-only` 在 Vitest 里 alias 到 `tests/server-only.ts`**；`fileParallelism: false`（共享 PGlite 单例）。

## 1. 迁移清单（0017–0020）

四支新迁移。每支都要同步 `client.ts` 清单与 `resetDatabaseForTest()`。

### 0017_pet_senior_stage.sql（C3 生命阶段三态）

```sql
-- life_stage 无 CHECK 约束（0005 只给了 NOT NULL DEFAULT 'active'），
-- 因此新增 'senior' 取值不需要改约束，只需放宽应用层 Zod 枚举。
-- 本迁移只补索引：健康线要按生命阶段过滤（memorial 屏蔽健康功能）。
CREATE INDEX IF NOT EXISTS pets_user_life_stage_idx ON pets(user_id, life_stage);
```

**核实结论**：`grep life_stage drizzle/*.sql` 只命中 `0005_attribution_and_lifecycle.sql:12`，无 CHECK 约束。所以 C3 的数据库改动极小，主要工作在 `domain/models.ts` 的枚举与端上 UI。

### 0018_pet_weight_records.sql（A4 体重记录）

```sql
CREATE TABLE IF NOT EXISTS pet_weight_records (
  id uuid PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  pet_id uuid NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  weight_grams integer NOT NULL,
  measured_on date NOT NULL,
  note text,
  created_at timestamptz NOT NULL
);
CREATE INDEX IF NOT EXISTS pet_weight_pet_measured_idx ON pet_weight_records(pet_id, measured_on DESC);
CREATE UNIQUE INDEX IF NOT EXISTS pet_weight_pet_day_uniq ON pet_weight_records(pet_id, measured_on);
```

三个决定：

- **`weight_grams integer` 而不是 `numeric` 公斤**。浮点公斤会出现 `4.1 + 0.2 != 4.3` 的显示问题，而克是整数且足够精确（幼猫增重以十克计）。
- **`measured_on date` 而不是 `timestamptz`**。体重是「哪一天称的」，不是「哪一刻」。这与 `CLAUDE.md` 记的「纯日期串按本地零点」同口径，避免时区差一天。
- **同一天同一宠物唯一**。一天称三次没有趋势意义，重复录入应覆盖而非堆叠（`ON CONFLICT ... DO UPDATE`）。

### 0019_health_advisory.sql（A1/A2 健康分诊与记录）

```sql
CREATE TABLE IF NOT EXISTS health_sessions (
  id uuid PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  pet_id uuid NOT NULL REFERENCES pets(id) ON DELETE CASCADE,
  description text NOT NULL,
  photo_ids jsonb NOT NULL DEFAULT '[]'::jsonb,
  pet_snapshot jsonb NOT NULL,
  triage_level text NOT NULL,
  triage_source text NOT NULL,
  advisory jsonb NOT NULL,
  model_snapshot jsonb,
  status text NOT NULL DEFAULT 'succeeded',
  error_code text,
  created_at timestamptz NOT NULL
);
CREATE INDEX IF NOT EXISTS health_sessions_pet_created_idx ON health_sessions(pet_id, created_at DESC);
CREATE INDEX IF NOT EXISTS health_sessions_user_created_idx ON health_sessions(user_id, created_at DESC);
```

字段说明与不显然的决定：

- **`triage_level`** 取 `emergency` / `urgent_24h` / `observe` / `routine` 四值，对应产品方案 3.7 的四档。
- **`triage_source`** 取 `keyword` / `model`。**这个字段是审计要求**：紧急症状走关键词直通（A3），必须能事后区分「AI 判的」与「规则判的」。争议追溯时这是关键证据。
- **`pet_snapshot`** 快照品种/年龄/体重/生命阶段。用户后续改档案不应改变历史分诊记录的输入前提——同 `plugin_snapshot` 的思路。
- **`advisory` 用 jsonb 而非 text**。结论是结构化的（四档 + 升级条件 + 就医准备清单 + 可能相关方向），存文本会导致端上无法分别渲染免责声明与结论。
- **`model_snapshot`** 记模型与版本，成本与效果回溯用。
- **保留 `status` / `error_code`**：模型调用会失败，失败也要落库（否则用户看到空白且无法追溯）。与 `generation_tasks` 的失败落库口径一致。

### 0020_pricing_and_membership.sql（C5 定价分档 + C7 会员重做）

```sql
-- C5：作品与订单记录定价档位，便于对账与后续调价不影响历史单
ALTER TABLE orders ADD COLUMN IF NOT EXISTS price_tier text;
ALTER TABLE works ADD COLUMN IF NOT EXISTS accumulation_snapshot jsonb;

-- C7：新增年度会员版本；月度置为 inactive（不删，已购用户需履约到期）
UPDATE membership_plan_versions SET status='inactive' WHERE code='monthly' AND status='active';
INSERT INTO membership_plan_versions (id,code,label,amount,period,entitlements,status,version,created_at)

  '{"tierUnlock":true,"healthExportUnlimited":true,"annualHealthReport":1,"annualReport":1,"physicalDiscount":0.9}',
```

## 2. C1：AI 生成内容标识（上线阻塞，先做）

### 2.1 现状与问题

`generation-worker.ts:68/73` 的水印文案是「PETBABY 免费预览 · 小程序码」，付费后 `getDownload()` 返回 `outputKey`（无水印原图）。`src/server/ai/` 下无任何标识写入。**行为与《标识办法》第四、五条相反。**

### 2.2 新增模块 `src/server/media/ai-label.ts`

集中两件事，避免散落：

```ts
export function needsAiLabel(plugin: PluginManifest): boolean
export async function applyAiLabel(body: Uint8Array, contentType: string): Promise<Uint8Array>
export function aiLabelMetadata(contentId: string): Record<string, string>
```

**`needsAiLabel` 的判据是 `generator.type === "image-api"`，不是「所有产物」。** 图文排版类（`html-template`）套用用户原照片，不是生成合成内容；视频是 ffmpeg 模板合成（`05-tech-and-compliance.md` 明确不用生成式视频模型）。给它们打「AI 生成」是错误标注，会误导用户。

### 2.3 显式标识实现

- **图片**：sharp `composite` 右下角文字，字号 = `max(20, height * 0.02)`，深色半透明底衬保证对比度。**不能只用半透明白字**——压在亮处会看不见，这与官网那条「半透明层叠必须按最坏帧实测」同一个坑。
- **落点**：`generation-worker.ts` 的产物写入前、以及 `ai-runs` 候选图写入时。**注意 AI 四选一有两处写入**（候选图与选中后的 work），两处都要打。
- **付费不移除**：`applyAiLabel` 作用在 `outputKey` 的字节上，不是只作用在 `previewKey`。这是与营销水印的本质区别。

### 2.4 隐式标识实现

sharp 的 `withMetadata()` 写 EXIF/XMP。写入字段：生成合成属性、服务提供者名称、内容编号（用 work id）。

**已知限制需记录**：sharp 对 PNG 的 EXIF 支持不如 JPEG。若实测写不进去，退路是改用 XMP 或在 PNG 的 `tEXt` 块写——**这一项在验收文档里单列，因为它有可能需要换实现**。

### 2.5 文案与协议

- `legal/terms` 增加标识方法与样式说明（第八条要求）
- 端上「AI 生成」字样在结论同屏，不折叠

## 5. C4/C5/C7：玩法合并、定价分档、会员

### 5.1 C4 玩法合并与调性切换

**方案选择：一个 manifest 带多套文案，运行时按生命阶段选择。**

替代方案（每个生命阶段一个 manifest）被否决：那等于把 manifest 数量从 10 变成 21，与「减少数量」的目标相反，且赛马变体（`experiment_variants`）会乘以 3。

实现：`manifest` 增加可选字段

```ts
toneVariants?: {
  senior?: { name?: string; description?: string; unlockPrice?: number };
  memorial?: { name?: string; description?: string; unlockPrice?: number };
}
```

- `runtime.ts` 的 `manifestSchema`（第 11 行）加该字段
- `/api/plugins` 出口按**当前选中宠物**的生命阶段解析（不传 petId 时给 `active` 文案）
- 任务入库时 `plugin_snapshot` 存**解析后**的 manifest，保证在途任务与历史作品不受后续改动影响

**删除 PL-20/21/22 的 registry 条目**（D3–D5），能力并入 PL-03/19/15 的 `toneVariants.memorial`。

**历史作品必须仍能打开**：靠 `plugin_snapshot`。`getWork` 读的是快照而非 registry，删条目不影响。**这条要在验收中显式验证**——它是删除动作唯一的真实风险。

### 5.2 C5 定价分档

**计算位置：下单时算，不是生成时算。** 理由：用户可能生成后隔几天才付；期间可能又上传了照片。按下单时的实际积累量计价对用户更有利，也避免「生成时便宜、付款时变贵」的投诉。

新增 `src/domain/pricing.ts`（放 `domain/` 因为 Web 端选择器也要用，从 `server/` 导入会让 RSC 边界看起来是错的——沿用 `domain/video-duration.ts` 的先例）：

```ts
export type PriceTier = "basic" | "advanced" | "annual";
export function resolvePriceTier(input: { photoCount: number; spanDays: number }): PriceTier
export function tierPrice(pluginId: string, tier: PriceTier): number
```

- 跨度用 `coalesce(shot_at, created_at)` 的 max−min（与 `timeline-service.ts` 同口径）
- **同时满足多档取最高档**
- `createOrder()` 写入 `orders.price_tier` 与 `works.accumulation_snapshot`
- **纪念形态不分档**：`lifeStage === "memorial"` 时直接取 `toneVariants.memorial.unlockPrice`，跳过分档计算

**必须避免的实现错误**：`orders` 已有 `plugin_snapshot`，但快照里的 `unlockPrice` 是基础价。分档价必须**同时**写进 `orders.amount` 与 `price_tier`，否则对账时算不出为什么这单是 ¥49。

### 5.3 C7/C8/D2/D6 会员

除迁移 0020 外，代码侧必改一处：

**`growth-service.ts:484` 的 `payGrowthOrder`**：

```sql
UPDATE memberships SET status='active',quota=(entitlements->>'monthlyQuota')::int,...
```

新权益里没有 `monthlyQuota`，`->>` 返回 NULL，`::int` 得 NULL，而 `memberships.quota` 是 NOT NULL → **付款后报错，会员激活失败**。

改为 `quota=COALESCE((entitlements->>'monthlyQuota')::int, 0)`。

**这是本次改造最容易漏的一处**：迁移改了权益 JSON，但激活逻辑读的键还在旧结构上，且只在真实支付路径触发（`payOrder` 的模拟支付在生产被拒），本地不容易发现。测试必须覆盖。

新增权益判定 `src/server/entitlements.ts`：

```ts
export async function hasTierUnlock(userId: string): Promise<boolean>
export async function hasHealthExport(userId: string): Promise<boolean>
```

供 `createOrder`（会员跳过分档直接给最高档）与健康档案导出使用。

## 6. A1–A3：健康分诊线

### 6.1 架构决定：独立服务，不复用 generation_tasks

`17` 号文 3.9 已判断这是「第六类执行管线」，产出**不是作品**：不进 `works`、不可分享、不进作品库。

复用 `generation_tasks` 会污染现有模型：它假设产出落 `works`（`work_id` 字段、`plugin_snapshot`、`daily_quotas` 绑定），而健康线没有 work。**独立建表（0019）+ 独立服务**。

新增文件：

| 文件 | 职责 |
| --- | --- |
| `src/server/health/triage.ts` | 纯函数：关键词直通判定、四档归一、输出结构校验、**药物名过滤** |
| `src/server/health/provider.ts` | 模型 provider，本地零配置实现 + HTTP 实现，沿用 `ai/provider.ts` 的主备与熔断模式 |
| `src/server/health-service.ts` | 编排：限频 → 快照档案 → 关键词直通或调模型 → 落库 |
| `src/app/api/health-sessions/route.ts` | POST 创建、GET 列表 |
| `src/app/api/health-sessions/[id]/route.ts` | GET 详情 |

### 6.2 关键词直通（A3）必须在模型之前

```ts
const EMERGENCY_PATTERNS = [/呼吸(困难|急促)/, /抽搐|痉挛|癫痫/, /误(食|吞)/, /尿(闭|不出)/, ...];
```

命中即返回 `triage_level='emergency'`、`triage_source='keyword'`，**不调模型**。理由（写进代码注释）：模型有延迟也有失败率，尿闭的猫等不了十几秒。

**这里有一个必须处理的反直觉点**：关键词是**宽进严出**——宁可把不紧急的判成紧急，不能反过来。所以模式要覆盖口语表达（「喘得厉害」「尿不出来」），不能只匹配医学术语。

### 6.3 药物名过滤是代码级硬约束，不能只靠提示词

`17` 号文 3.8 红线 2 要求不输出任何药物。**提示词约束不可靠**——模型会在「不要提药」的指令下仍然提到药名。

`triage.ts` 增加输出后置过滤：命中药物名词典（通用名 + 常见商品名 + 剂型词）即**整段丢弃并降级为通用建议**，同时记 `error_code='DRUG_MENTION_FILTERED'` 便于监控。

**宁可给用户一个更笼统的建议，也不能给出用药提示。**

### 6.4 免责声明由服务端下发，不由端上写死

`advisory` jsonb 里带 `disclaimer` 字段，端上必须渲染。理由：两端（小程序 + Web）各写一份文案，改法务口径时必然漏一处。服务端下发保证一致。

**端上不得折叠该字段**（红线 5：结论之前或同屏）。

### 6.5 频次限制

复用 `daily_quotas` 的机制但**独立计数**：健康分诊用完不该影响创意生成的额度（那是两种资源）。新增 `health_daily_quotas` 或在 `daily_quotas` 加 `kind` 列——**倾向后者**，避免表爆炸，但要注意 `daily_quotas` 现有唯一约束是 `(user_id, quota_date)`，加 `kind` 需改约束，属改历史迁移的反模式。**结论：新建 `health_daily_quotas` 表**（并入 0019）。

- 文字分诊 3 次/日
- 图片识别 1 次/日
- 会员不加次数

### 6.6 memorial 屏蔽

`health-service.ts` 入口即判：`pet.lifeStage === "memorial"` → `AppError("HEALTH_UNAVAILABLE_MEMORIAL", ..., 409)`。

同时端上不显示入口。**两处都要**：只做端上隐藏，接口仍可调；只做服务端拦截，用户会看到入口点进去报错。

### 6.7 本地零配置

沿用 `ai/provider.ts` 的模式：无凭据时用本地实现。健康线的本地实现**不是随机文本**，而是基于关键词的确定性规则输出——这样 E2E 可断言，且开发时看到的结构与生产一致。

## 7. A4–A6、A7–A9

### 7.1 A4 体重记录

- 迁移 0018
- `platform-service.ts` 加 `recordWeight` / `listWeights`（`ON CONFLICT (pet_id, measured_on) DO UPDATE`）
- `/api/pets/[id]/weights` GET/POST
- 端上：`pages/pets` 与 `/pets` 加录入入口
- **不做 BMI 或肥胖评级**（评价性结论接近诊断）

### 7.2 A5 健康档案 PDF

`src/server/health/export.ts`，复用 `memorial/album.ts` 的 PDF 能力（多页 SVG → sharp 光栅化 → pdf-lib）。

**三条内容约束**：

- 症状记录标明「宠主自述」，**不呈现分诊结论为诊断**
- 体重曲线用真实数据点，无数据时不画空图表（留文字说明）
- 光栅化用例需显式给 60 秒超时（覆盖率开启时 v8 instrumentation 让 sharp 明显变慢，5 秒默认会造成只在 `test:coverage` 里挂的假失败——`memorial/album.test.ts` 已有先例）

### 7.3 A6 年度健康报告

复用 `annual/aggregate.ts` 的年度聚合骨架，但**数据源独立**（体重 + 症状 + 疫苗，不是照片与作品）。

### 7.4 A7 去年今日入口（成本最低，优先做）

服务端已完成，只缺端上：

- 小程序 `pages/index` 或宠物卡片位调 `/api/on-this-day`
- Web `/` 同步
- **命中才显示，没有就静默**（不显示「今天没有回忆」——那是提醒用户产品没内容）

### 7.5 A8 里程碑自动产出

- Worker 的 60 秒运维轮次中加一项（或并入 `on-this-day` 的小时轮次——**倾向后者**，里程碑一天最多产出一条，不需要 60 秒精度）
- 复用 `growth-compare-v1` 或画册单页，**不新建生成器**
- 只列已达成，不含第 1 天；`memorial` 宠物不产未来里程碑

### 7.6 A9 月度小册

- 月初静默为上月有新照片的宠物成册
- 当月照片 < 3 张不生成
- 免费带水印，是钩子不是交付物
