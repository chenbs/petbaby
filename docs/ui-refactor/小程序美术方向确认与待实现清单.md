## 1. 已确认的美术方向

用户选定三套页面级视觉语言：**01 暖调胶片画廊、04 宠物主场、07 官网参考·内容品牌**。页面可按用途分配不同语言，不要求全站只用一种；其余四套本轮不采用。以下分配已接入代码，实际效果仍以逐页验收为准。

| 语言 | 使用原则 | 关键视觉 |
| --- | --- | --- |
| 暖调胶片画廊 | 陪伴、记录、时间和纪念；纪念页降低动效和装饰 | 真实照片、大留白、轻阴影；暖白、暖棕、珊瑚是参考主题下的示范配色 |
| 宠物主场 | 宠物身份、日常管理与轻互动；健康页保留严肃的信息层级 | 宠物头像、柔和形状和清楚的状态反馈；薄荷/淡紫是参考主题下的示范配色 |
| 官网参考·内容品牌 | 作品展示、AI 选择、交易与账户；品牌形象与官网相连 | 图片优先、细线与编号；白底、墨色、玫红是参考主题下的示范配色 |

**官网参考修订：所有展示图片使用与另外两套一致的圆角语言。** 首屏/作品大图目标圆角约 20px，作品缩略图约 12px；小程序 750rpx 设计宽度下分别以 `40rpx`、`24rpx` 为评审基准，最终走圆角 token，不直接在页面写数值。带图卡片及其遮罩同弧度裁切，不沿用旧预览的直角。白底、墨色、玫红只属于官网参考主题的配色示例，切换用户主题后同样随之换色。`visual-proposals.html` 是设计预览；真实小程序的首轮改版已开始，终稿仍待设备验收。

## 3. 配图来源核对与后续换图

最初的七套 HTML 展板为了快速比较 UI，直接引用 `apps/website/public/assets/` 里的**既有官网静态样片**，当时没有重新生成图片，也没有从小程序页面里抽出内置图片。其中：

- “AI 肖像”使用 `play-portrait.jpg`，“绘本主角”使用 `play-storybook.jpg`；“暖调胶片”等也沿用 `style-*.jpg`。这些属于较早的官网展示素材，原始文件仍在 `apps/website/public/assets/`，旧展示组件已随官网首页改版移除。它们确实不符合这次期望的官网新版品质，不能作为新版小程序最终素材。
- 小程序当前的玩法图主要通过 `/api/plugin-samples/...` 和 `/api/image-templates/.../sample` 读取；`pages/ai-create` 的模板图是 `item.sampleUrl`。展板本地文件路径与运行时 URL **不是同一个供图路径**，不能据此断言线上小程序正在显示这些同名旧 JPG。
- 官网较新的 `website-v2-*.jpg` 可做视觉品质参考，但也需要逐张判断是否适合小程序的实际入口比例和裁切。

**素材工作口径与当前进度：**图位盘点、本地生成、用户对展板全部 24 张图的终审、展板引用替换和默认样片注册已执行，逐图记录在[新图台账](./小程序新图图位与审核台账.md)；测试环境播种、四主题设备适配与真机核验尚未执行。以下顺序中第 1 步的视觉终审和本地哈希核验已完成，设备相关检查仍待执行：

1. 按台账逐个核验新图的内容、提示词、SHA-256、版权来源和旧图回滚键；由产品负责人完成终审，淘汰候选不得进入播种白名单。
2. 以官网新版样片的明亮、完整主体、清晰面部和商业完成度作最终品质检查；同一组风格对比固定同一只宠物，检查实际小图裁切和四主题适配。
3. 在测试环境播种后逐个验证运行时 URL、缓存和历史链接，再按图位切换并留截图；AI 模板公共预览仍遵守冻结母版关系，不因展板名称新增入口。
4. 最终在真机上检查首屏、列表、详情、四选一/二选一、弱网和深浅主题。已登记但未批准上线的宠物人化 V2 效果图继续保持 `pending-review`，不因这轮视觉改版被自动上架。

## 4. 新四主题与页面语言的关系

六套布局全部采用，效果图见 [`layout-proposals-6.html`](./layout-proposals-6.html)；展板中的“待选”属于选择阶段历史文案。**页面美术语言管构图、影像使用和阅读节奏；六套布局管信息顺序；用户主题管颜色、表面、文字、状态和按钮。** 三者叠加，不得让页面归属表暗中锁定颜色。无论选择哪套主题，23 页、访客分享页、自定义导航栏、tabBar、弹层和空态都使用当前设备用户选择的主题。第一次进入且没有有效偏好时只用统一初始主题 `pet`；这不是某一页的固定主题。纪念页保留 `mood: "memorial"` 的低动效、少装饰规则，健康/交易/隐私页保留严肃的信息层级；它们都不覆盖主题 ID。互动场景的配色属于用户创建的内容属性，场景画布可以保留，画布外控制区仍跟随用户主题。

现有 `cute / glass / light / dark` 四套皮肤在正式切换时废弃，以基于本次新美术的四套主题取代。下列名称、ID 和基准配色是实施口径；具体色值以四主题 token 完整性及对比度验收后的值为准，不在页面写死：

| 新 ID / 名称 | 定位与基准配色（背景 / 正文 / 主操作） | 与页面语言的关系 |
| --- | --- | --- |
| `film` 暖调胶片 | `#F9F7F3` / `#242021` / `#B43B4F`；暖白、深墨、珊瑚，辅以植物绿 | 陪伴页最贴近参考稿；在作品/交易页仍保持原布局和信息密度 |
| `pet` 宠物主场 | `#F5F9F7` / `#20322D` / `#197262`；薄荷底、深绿、少量淡紫 | 身份页最贴近参考稿；健康页只保留温和色彩，不使用拟诊断装饰 |
| `brand` 内容品牌 | `#FAFAFA` / `#1C1C1C` / `#B12863`；白、墨色、玫红，辅以冷灰 | 作品和 AI 页最贴近官网参考；照片圆角仍统一保留 |
| `night` 夜间观影 | `#171B1B` / `#F5F7F5` / `#F3A1B6`；中性深底、浅字、柔和强调色 | 是上述影像与排版体系的夜间取值，不引入第四种页面美术语言 |

实现时在 `theme/index.js` 注册新四套并设 `DEFAULT_THEME_ID = "pet"`；`theme/tokens.js` 的完整语义键、主题选择页每卡用自身 token 预览、切换即时生效和无网络请求的行为继续保留。`petbaby_theme` 存储键继续沿用，首次升级时做一次显式兼容映射：`cute→pet`、`glass→film`、`light→brand`、`dark→night`；新 ID 原样保留，未知/损坏值回落 `pet` 并写回。此映射是升级兼容，不是声称旧肤与新肤视觉等价；禁止读到旧 ID 就静默随机换肤。选择保持设备本地偏好，登录、退出和访客进入不替用户改写偏好，切换后刷新页面栈与导航栏。分享 URL 不携带作者的主题 ID，访客按自己的本地选择渲染。

移除 `memorial-share` 中的 `fixedTheme: "cute"` 及 `theme/page-mixin.js` 的固定主题分支，保留 `mood: "memorial"`；同步清理登录页、`theme/tokens.js` 派生逻辑与共享组件中的旧 ID 特判。主题预览卡展示其他主题是选择器的内容，不是页面固定换肤。旧需求文档中“分享页固定 cute”仅作历史记录，此处新确认结论优先；实施时同步更新 `docs/product/21-小程序功能点清单.md` 的 MP-19.1、MP-22.1、MP-23.1/23.3 等受影响条目。

## 5. 逐页布局稿的最低交付内容

以下顺序指信息层级，不新增功能或改动服务端口径；每页应产出一张首屏、一张完整纵向稿和关键状态稿，再对照权威功能清单的对应 `MP-xx` 项逐项勾核。共用状态规则：加载时保留标题、导航与主内容骨架；错误显示可理解原因和原有重试入口；空态只给当前真正可用的下一步；无权限/已删除与真正空数据分开。网络失败不得伪装成空态，主操作不可覆盖系统安全区、tabBar 或键盘。涉及提交和支付的按钮需要禁用、处理中、成功及失败反馈。

| 页 | 首屏至页面末尾的信息顺序 / 主操作位置 | 必须单独画出的业务状态与边界 |
| --- | --- | --- |
| P01 首页 | 当前宠物与切换、陪伴天数→记录动作→最近收好/命中回忆→第二屏玩法货架；记录动作在首屏 | 无宠建档；里程碑仅当天、去年今日仅命中显示；玩法无图文字回退、加载/上架空态 |
| P02 制作 | 四步进度→当前宠物→照片九宫格→玩法参数→实际价格/档位→生成；当前步骤底部主操作 | 草稿恢复、上传进度/重试、超限、免费免价格、提交结果未知后查任务、生成失败重试 |
| P03 作品柜 | 三筛选→进行中/失败任务置顶→3:4 成品双列→继续加载；卡片打开详情 | 排队进度、失败重试、待解锁/已过期标签；筛选空态“清空筛选”和真无作品“去做一个”分开 |
| P04 作品详情 | 大图/视频→水印说明与事实→价格/解锁→版本、分享和保存等原有动作 | 锁定/已解锁、视频 poster、支付反馈、分享撤销确认、无图与下载权限失败 |

## 6. 视觉 token、组件和适配规则

1. 先做一份设计规格表，列出三套页面语言下的图片形态、标题/正文层级、间距、细线、操作区与状态组件，再映射到 `theme/tokens.js` 的语义键和 `CONSTANT_VARS`。四主题必须补齐所有语义 token，新增跨主题不变的几何量优先放常量；只把随主题变化的颜色、表面和效果放入主题值。`.wxss` 继续禁止硬编码颜色、字号、圆角、间距、阴影。CSS 变量注入串保持每主题及降级态不超过 2048 字节，不靠放宽门禁实施。
2. 先复用 `t-*` 公共组件与 `custom-tab-bar`，统一主/次/危险按钮、行项、筛选、表单、通知、弹层和空态的正常/按下/禁用/加载/错误取值。实底信息区承载价格、免责声明、权限和退款提示；不把长字压在图片上。主题切换只改颜色与表面，不改变组件尺寸、信息顺序和触达位置。若旧玻璃组件承载必要手势和流程，可保留其交互并改成新主题表面；不把玻璃视觉当成第五套皮肤。
3. 图片组件统一裁切规则：展示型大图圆角 `40rpx`，缩略图 `24rpx`；这两档作为共享结构变量登记，图片、遮罩、骨架、选中描边同弧度。玩法 Hero 16:10、作品卡 3:4、宠物头像 1:1；AI 模板以源图方向展示且不拉伸，用户照片详情和纪念访客照片保留原比例。不同主题不得给图片增加整幅色罩或把宠物面部裁掉。图上文字需实底/足够遮罩和独立对比校验。
4. 750rpx 宽设计基准下页面横边距沿现有 `pagePadding`；手机窄屏优先保留文字可读性，双列图墙可按可用宽度降为单列，不横向溢出。固定底部操作区与自定义 tabBar 分别计算 `safe-area-inset-bottom`，键盘弹出时表单主操作可见；沉浸页保留自定义导航返回和状态栏空间。标题不溢出，金额、异常码和按钮文案不截断到失义。
5. 四主题及模糊降级态逐项校验正文/卡面/按钮文字至少 4.5:1；次级提示至少 3:1，若承担必要信息则也按 4.5:1；图上文字在实际最亮和最暗样片上复核。纪念模式降低动效并尊重系统减少动态效果设置；支付、健康红线和危险操作始终以文字与状态共同表达，不能只靠颜色。

## 7. 新图生产清单与发布边界

在开始生成前建立**逐图位资产台账**，每条至少记录：`slotId`、页面/入口（含动态 `pluginId`、`entryId`、`templateId`）、展示文案、当前来源（本地文件或完整 API URL/对象键）、公开/私有属性、目标宽高比与安全裁切、目标示例内容、生成提示词和参考图来源、授权依据、产出路径及 SHA-256、审核人/结论、发布版本/新对象键、回滚键。新图数量由真实 live 入口盘点决定，不能用一批通用宠物照重复充当不同玩法的产出。首批盘点至少覆盖：

| 图位组 | 盘点边界与新图要求 |
| --- | --- |
| 首页玩法与制作入口（P01/P02） | 按 `/api/plugins` 实际 live `pluginId` 逐卡盘点 Hero、网格、制作预览；每张图表达真实成品种类，缺图维持文字回退 |
