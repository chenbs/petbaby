# 小程序 Design Audit 与视觉改造规格

审核日期：2026-09-27。对象：`apps/miniprogram/app.json` 注册的 23 页、`app.wxss`、四套主题及共享组件。审核依据为当前 WXML/WXSS、主题值、页面逻辑及既有视觉验收矩阵；设备实拍与真实服务端图片仍须在实施后另行核验，不能把设计预览当成真机结论。

## 产品判断与当前设计问题

产品的内容是宠物照片、创作结果与陪伴记录。现有实现已具备四套主题、图片入口、完整的状态组件和主要业务流程，比通用工具页更接近产品形态；问题集中在「照片被 UI 容器同化」和「每个流程都采用同一套卡片/按钮语法」。用户第一眼常先看到边框、阴影、英文眉题、步骤或功能列表，随后才看到自己的宠物。

| 级别 | 证据与成因 | 体验影响 |
| --- | --- | --- |
| P0 | `pages/ai-run` 候选图以固定 3:4 框 `aspectFill` 比较；源图可能为竖幅，裁去头部或服饰仍可被选中。`pages/ai-create` 样片同样裁切，源图方向无法比较。 | 创作决策依据不完整，尤其影响宠物人化的二选一。 |
| P1 | 首页与个人页把头像横裁为 16:10 大图，并将名字、天数压在照片上。头像一般为方图或半身照；窄屏上的强裁切、遮罩和压字可能掩盖脸部。 | 最重要的宠物身份反而不稳定；缺头像时大面积 emoji 占位。 |
| P1 | `t-card` 默认同时有实底、圆角和双层阴影；`me` 的宠物、额度、常用功能、设置连续成卡，`health`/`commerce`/`orders` 也多次重复。 | 各区块同等重量，页面像功能看板；信息层级只能靠标题维持。 |
| P1 | 首页玩法图上每项都有价格浮标、代码和压图文字；无宠物时另有标语 Hero 和装饰印章。 | 创作产品容易读成促销货架；图像的表情与风格被 UI 覆盖。 |
| P1 | 普通创作的资料和照片阶段被固定 88vh 的玻璃面板覆盖，里面又嵌入卡片、步骤条和常驻 CTA。 | 表单可用高度紧、层级重复；键盘、小屏和长提示下尤需设备核验。 |
| P1 | `ai-create` 入口、样片和照片使用多组同形双列选项；选中态靠边框加外发光，图片又统一 `aspectFill`。 | 用户需读完多个网格才能明白当前选择；样片的完整构图不可见。 |
| P1 | `app.wxss` 的字级、线性间距和组件约束与各页并存；`--ls-tight` 等负字距、英文全大写眉题频繁出现。 | 中文标题紧、英文装饰过多，弱化真实内容与亲和感。 |
| P2 | 共享主按钮及 AI 按钮同时使用强投影/渐变；次按钮和 ghost 都有边框，页面还常有多个全宽按钮。 | 操作主次不够明确，尤其是上传、预览、保存、分享相邻时。 |
| P2 | 列表图、作品图、候选图混用固定裁切；纪念访客页和照片详情已采用原比例，说明系统内有两套不一致的图片原则。 | 记录图的表情或身体会被裁掉，图墙与详情落差大。 |
| P2 | 空态、加载、错误已有组件，但大面积 card 骨架和带装饰的空态在内容页反复出现。 | 状态转换时版面跳动，错误提示与主要操作竞争注意力。 |
| P3 | 页面标题、组件标题、卡片标题常在相邻区域重复；部分说明在 UI 里描述功能而非当前内容。 | 增加扫描负担和屏幕高度。 |

### 年轻感与趣味性判断

当前的薄荷色、圆角与图片并不自动带来年轻感。真正有效的是清楚的视觉节奏、宠物照片的辨识度、轻快但可预期的反馈，以及从记录自然进入创作与分享。现有图片 Hero 和作品墙具备基础，但主页更像「宠物封面 + 玩法货架」，个人页更像入口目录；情绪记忆点和探索路径被同一种卡片形态冲淡。保留照片、时间线和创作结果作为自然的趣味来源，不加 emoji 装饰或游戏化健康/纪念内容。

## 新方向与 Design System

方向：**宠物影像叙事 + 轻编辑感**。第一层是真实宠物和作品，第二层是照片的日期、名字、简短故事，第三层才是工具与交易信息。通过完整影像、留白、不同的模块节奏形成识别度；有业务意义的价格、权限和错误留在实底信息区。四套已获确认的主题保留用户选择能力与语义 token，页面美术语言仍遵守既定的胶片 / 宠物 / 内容品牌分配，统一的是组件结构和图片原则。

| 系统 | 规格与实施边界 |
| --- | --- |
| Color | 继续用四主题的 `primary / secondary / background / surface / cardBackground / textPrimary / textSecondary / disabled / divider / success / warning / error`。`primary` 只表示主操作和选中；默认宠物主题须兼有中性底、绿色功能色及暖色辅助，不能整屏仅靠一种绿。纯色不散落到页面 WXSS。 |
| Typography | 页面标题用 `titleSize`，区块标题用 `font-h2`，内容标题用 `font-h3`，正文/描述用 `bodySize`，辅助说明和标签用 `smallSize` / `eyebrowSize`。中文正文足够行高；各级字距为 0。价格、状态以权重和位置分层，不依赖全大写英文。 |
| Spacing | 以现有 `--space-0` 至 `--space-8`、`--gap-item/group/section` 为统一阶梯；首屏、图片流、操作区允许不同节奏，不把每段强行等高。 |
| Radius | 图片 Hero 用 `--radius-image-hero`，小图用 `--radius-image-thumb`；工具表面用 `--radius-sm/md`，按钮走 `--button-radius`。卡片只用于可单独操作的内容单元或弹层，不让整个页面嵌套在卡片里。 |
| Shadow | 图片可用轻影，列表、表单、信息分区尽量无影；夜间主题用明度差和细线保持层次。取消默认卡片叠层带来的普遍悬浮感。 |
| Image | 内容可辨认优先：宠物身份和 AI 样片/候选保留完整构图，作品图墙在稳定网格中裁切但详情完整显示；压图文字只用于已验证的安全区域，金额和长文不压图。照片加载失败有实底文字替代。 |
| Components | `t-button` 主/次/ghost/danger/AI 保留功能，视觉上主按钮一个区块只突出一个；`t-card` 给可点击作品或必要面板，普通分区改无框；`t-field`、`t-steps`、`t-tag`、`t-dialog`、`t-popup`、`t-notice`、`t-empty`、`t-loading`、`t-skeleton`、自定义 tabBar 沿用统一 token、触达与状态。 |
| Motion | 只在按压、照片加载、选中和展开时给轻反馈；遵守纪念页低动效与系统减少动态效果。 |

## 逐页审核与改造方案

每行依次写页面目标/核心任务、第一与第二焦点、主 CTA、当前问题，以及布局/视觉/交互调整。按核心路径排序，编号仍对应 `app.json`。

| 页 | 目标与任务；第一眼 / 第二眼；主 CTA | 当前问题与改造方案 |
| --- | --- | --- |
| P01 首页 | 看见当前宠物并进入记录/创作；宠物 / 最近照片与作品；「收好照片」 | 横幅头像与压字会裁脸，价格浮标把玩法变货架。改为照片与身份文字分层的宠物首屏；最近记录用轻量影像流；玩法展示图与名称分开，保留原跳转、错误和空态。 |
| P02 普通创作 | 选宠物、照片、参数并生成；当前作品样片 / 当前步骤；「免费生成预览」 | 88vh 玻璃表单包卡片，视觉沉重。保留步骤和逻辑，改为可滚动实底工作区与独立样片区，费用说明靠近生成动作；长表单、键盘和失败态可见。 |
| P03 作品柜 | 浏览完成品、处理进行中任务；作品图 / 筛选；打开作品 | 三个筛选框与任务卡先于作品图；图上代码和版本抢占画面。筛选收紧成工具行，任务作轻列表，成品以照片为主、文字在图外，保留筛选/重试。 |
| P04 作品详情 | 看成品、解锁、保存或分享；完整作品 / 状态价格；对应状态的解锁或保存 | 沉浸画布方向正确；实底抽屉需避免重复标题和多排同权按钮，分享与版本次级收纳，保留水印及所有权限。 |
| P05 订单与退款 | 查付款与退款；状态金额 / 时间；待付时继续付款 | 每单通用卡与按钮堆叠。改紧凑交易行，状态文字和金额同屏，退款查询与刷新次级化；错误和合规信息保持完整。 |
| P06 我的 | 看宠物与常用入口；宠物 / 账户状态；进入宠物档案或记录 | 横幅宠物卡、额度卡、两块导航卡连续堆叠。身份照片与姓名分层、额度压缩成信息行、入口无框分组，保留所有导航与通知。 |
| P07 宠物档案 | 切换、编辑宠物；头像姓名 / 生命周期；进入记录 | 每只宠物是功能卡并带多按钮。保留头像、状态与编辑能力，把主操作放在身份行，把危险/低频操作次级收纳；编辑表单保持原字段。 |
| P08 照片库 | 上传、查看、补充记录；照片 / 日期；收好照片 | 顶部多按钮与编辑动作拥挤；照片网格承载内容却需再缩读。动作按浏览/管理态分层，详情继续原比例；上传批次、失败重试、批量编辑不删。 |
| P09 账户与隐私 | 管理显示名、导出/删除；账户信息 / 数据操作；保存资料 | 表单和危险操作都在相似卡里。改实底表单与独立危险区，确认步骤和反馈不弱化。 |
| P10 时间线 | 按日期回看；日期与照片 / 里程碑；收好照片 | 顶部统计卡和年度短片卡与时间轴争首屏。照片轴更早露出，工具区后移；日期顺序、分页、年报确认保持。 |
| P11 健康助手 | 分诊、体重与护理记录；宠物和紧急度 / 结果说明；提交分诊 | 多个同权卡让紧急结果不够突出。结果作为清晰实底信息带，历史与导出下移；免责、四档紧急度、支付和错误不藏。 |
| P12 AI 创建 | 比较样片，选宠物与身份照；完整样片 / 选择状态；生成候选 | 横向入口 + 双列模板 + 照片网格层级重复，样片被裁。首屏先展示当前玩法，再以完整样片比较、选择和授权形成连续流程；候选数及不可重抽规则明确。 |
| P13 AI 候选 | 比较、选中并解锁；完整候选 / 选择反馈；解锁选中图 | 3:4 `aspectFill` 可能裁掉决定性画面；卡边框外发光抢图。候选按源图方向完整显示，选中反馈轻量；只在选中后进入原有沉浸确认，保留失败/取消/返还。 |
| P14 互动创建 | 配照片、文案、场景；照片 / 实时预览；创建互动页 | 表单和预览分段太像工作台。让场景预览连接照片选择与文案，主操作稳定可见；授权和上限不变。 |
| P15 互动页 | 体验场景，作者再管理；场景 / 互动反馈；作者保存或访客互动 | 作者工具易与场景同权。画布占主视区，编辑与分享作为实底次级控制；访客权限、导出和埋点不变。 |
| P16 短片创建 | 有序选图并设时长音乐；已选照片 / 时间顺序；创建并编辑 | 文本表单卡在照片之前。缩成简洁制作条，照片叙事流更显眼；三档时长、张数提示和音乐规则不变。 |
| P17 视频项目 | 看封面播放与渲染；封面 / 状态；按状态提交/重试/查看作品 | 状态卡和字幕卡可能抢封面。封面优先，状态作为信息行；保留取消确认、字幕保存和失败反馈。 |
| P18 纪念空间 | 浏览/创建纪念空间；封面与日期 / 故事；新建纪念空间 | 章节图有辨识度，但列表管理动作容易打断阅读。操作次级化、故事保持留白；不游戏化，不改隐藏/恢复。 |
| P19 纪念分享 | 安静阅读回忆；完整照片 / 故事；无强促销 CTA | 已用原比例照片，保持这一原则；加强长文段落与图片节奏，访问失效和隐私分支保持。 |
| P20 会员年报 | 查权益、比较方案与年报；当前权益 / 方案价格；选择方案 | 多组方案、订阅、报告卡连成运营页。权益与价格先清楚对比，提醒/年报分节；文案和实际价继续来自接口。 |
| P21 实体纪念品 | 选已解锁作品并下单；作品图 / 收货信息；确认下单 | 表单卡和订单卡压过作品。图片选择更清楚，收货/履约保持实底；价格、隐私和错误完整显示。 |
| P22 登录 | 完成身份验证；品牌与输入 / 错误反馈；登录或注册 | 多张卡使一屏表单冗长。缩减装饰，分段与输入集中；微信身份降级、已登录和退出逻辑不变。 |
| P23 主题 | 预览并切换四主题；真实预览 / 当前选中；选择主题 | 预览卡自带边框/背景容易把主题差异理解成色块。让预览图与对应 token 同时呈现，选中反馈明确；本地偏好和四主题即时生效不变。 |

## 验收与记录口径

优先顺序为 P01→P12/P02→P13/P04→P03→P06，再覆盖其余页面和共享组件。验收同时看 320px、375px、430px 手机宽度、长中文/英文、横/竖/方图、空/加载/错误与四主题；比较样片和候选必须能看到完整主体。`npm.cmd run validate` 是结构与 token 门禁，不替代微信模拟器截图；实际设备检查须在报告末尾记录证据和未完成项。所有 API、订单、权限、登录、数据结构与功能入口保持原语义。

## 本轮实施与验收记录

### 已完成

- 统一共享卡片和按钮的层级，移除全局负字距；23 页清除无意义英文眉题，沿用四主题 token、原有字体和间距阶梯。
- 首页改为照片优先的宠物首屏，头像缺失时使用最近记录照；普通创作、AI 模板/候选、作品柜、个人中心及登录页按审计方案重排。AI 样片与候选完整显示主体，不用固定裁切框决定选择。
- 照片库单张照片按原比例突出，多张使用双列；管理、分页、上传与详情保持原路径。宠物档案用影像行代替整张功能卡，短片与互动创建先看照片再编辑内容；会员方案在手机上使用完整行宽。
- 健康助手的分诊、体重、免疫和档案改为分段实底布局；服务端免责声明仍在结论之前、与结论同屏。账户和互动文字输入去除嵌套卡，纪念空间空状态去除重复新建入口，作品详情无效链接有独立错误页与重试入口。
