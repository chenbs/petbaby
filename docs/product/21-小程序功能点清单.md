# 小程序功能点清单（逐项修改执行清单）

盘点自 2026-08-19 的工作区代码。**组织维度固定为小程序**：按 `app.json` 的 `pages` 顺序分页，每页列出其功能点并编号；凡在管理后台或 Web 端有对应实现的，在「关联端与位置」列标出。

本文件只回答「有哪些功能点、改一项要动哪几端」。功能口径以 [`07-functional-backlog.md`](07-functional-backlog.md) 为准，**Web/后台/REST/玩法 manifest 的清单见** [`15-功能入口清单.md`](15-功能入口清单.md)（那份不再重复小程序侧，两份互补不重叠），UI 约定见 [`../ui-refactor/阶段0-代码盘点与方向分配.md`](../ui-refactor/阶段0-代码盘点与方向分配.md)。

支付相关入口已经有页面和接口；虚拟支付、`growth_orders` 回调发权益与退款回收的代码改造已完成，但真实签约、商品上架、回调和真机验收仍未完成。涉及 MP-04.3、MP-11.7、MP-13.8、MP-20.3/20.8、MP-21.3 时必须同时看 [`07-functional-backlog.md`](07-functional-backlog.md) 当前待办与 [`23-虚拟支付合规改造方案.md`](23-虚拟支付合规改造方案.md)，不能把“代码已实现”当作“支付已上线”。

## 用法

- **编号唯一且稳定**：`MP-<页序>.<项序>`，页序按 `app.json` 顺序（P00 为跨页框架层）。新增功能点在所属页尾部追加序号，**不重排已有编号** —— 编号是进度依据。
- 本表列出的功能点都是**当前已实现基线**；状态列只跟踪下一轮逐项修改。留空＝未进入本轮修改，`进行中`，`OK`＝本轮已改完并验证，`跳过`＋一句理由。留空不再表示功能未实现。
- **逐项顺序推进，不批量并行**。改完一项跑对应门禁再动下一项：小程序侧 `cd apps/miniprogram && pnpm validate`，平台侧 `cd apps/platform && pnpm check`。
- **「关联端与位置」非空的项不能只改小程序侧**。该列标注的三类端：
  - **Web 应用** = `apps/platform`（Web/H5 同构页面，与小程序共用同一套 REST 接口）
  - **后台** = `apps/platform/src/app/admin/**`（9 个工作台）
  - **官网** = `apps/website`（Astro 静态站，独立域名，只做对外介绍，不调业务接口）
- 该列写「—」表示确认小程序独有，改动不外溢。

## 附录 A：官网（`apps/website`）与小程序功能点的对应

官网是纯静态介绍站，**不调业务接口**，所以它与功能点的关联只有「对外描述是否与实现一致」这一层。改到下列功能点时要顺带核对官网文案：

| 官网区块 | 对应功能点 | 核对要点 |
| --- | --- | --- |
| `#features`（FeatureGallery.astro） | MP-01、MP-02、MP-07、MP-08、MP-10～MP-21 | 首页九组功能展示必须与小程序功能表同步，包含「人类转生计划」入口；图片、标题和能力边界不得超出当前实现 |
| `#features` / AI 创意工坊 | MP-12.*、MP-13.* | 所有新任务两张候选二选一；宠物人化不写人宠合影或身份卡 |
| `#features` / 互动与短片 | MP-14.*～MP-17.* | 互动场景、星尘收集、15 秒导出，以及 10/20/30 秒短片档位 |
| `#features` / 健康助手 | MP-11.* | 只能写辅助记录与分流；**不得出现「诊断」「确诊」「治愈」「问诊」** |
| `#features` / 纪念空间 | MP-18.*、MP-19.* | 纪念册、纪念视频、星尘页与分享；陪伴天数使用过去式且不递增 |
