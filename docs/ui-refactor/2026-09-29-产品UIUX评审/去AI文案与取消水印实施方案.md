# 去 AI 文案与取消水印实施方案（2026-09-30）

对应两项需求：
- **6a**：玩法中所有提到 AI 的文字都改掉，不出现任何标明 AI 生成的内容。
- **6b**：生成的内容和预览都不带水印，也不再把「去水印」作为付费点。

本文只做清点和方案，没有改代码。清点方法是全仓 grep 加逐文件阅读，没有跑页面。

**第二轮修订（2026-09-30，已按用户决定更新）**：
- 图片本身不加水印，也不画「AI 生成」角标。
- 在**小程序界面上**给生成结果加一条底部蒙层，文字为「该内容由AI生成」。蒙层不写进图片文件。
- 付费点只保留「保存高清原图」一项，不另设「长期保存」「导出」名目（见第 3.3 节）。
- 宣传文案、页面标题、按钮、错误信息里的 AI 字样照旧去掉。唯一保留「AI」的用户可见文字就是这条蒙层。

## 1. 先确认的一件事：合规边界

6a 里有一部分是可以直接做的，有一部分和强制性规定冲突，需要负责人决定。

| 内容 | 能否去掉 | 依据 |
| --- | --- | --- |
| 页面标题、按钮、介绍、通知、官网宣传语、SEO 关键词里的「AI」字样 | **可以**。法规管的是生成内容上的标识，没有要求在宣传文案里写 AI | — |
| 图片上可见的「AI 生成」角标（显式标识） | **有条件可以**。办法第九条允许用户申请不含显式标识的内容，前提是：用户协议写明用户自己的标识义务和使用责任；平台留存提供对象等日志不少于 6 个月 | [《人工智能生成合成内容标识办法》](https://www.gov.cn/zhengce/zhengceku/202503/content_7014286.htm)第四条、第九条 |
| 图片文件里的隐式标识（EXIF 元数据） | **不能去掉**。第九条只放宽显式标识；第五条要求的元数据隐式标识仍是义务 | 同上第五条；[GB 45438-2025](https://www.bzchaxun.com/view/6103202100000000.html) 为强制性国家标准 |
| 「人类转生计划」输出的真人面孔 | **风险最高**。人脸生成属于深度合成规定第十七条第（三）项，可能导致混淆时要显著标识。第九条的用户申请路径能否覆盖这一类，需要法务确认 | [《互联网信息服务深度合成管理规定》](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)第十七条 |
| 健康分诊结果旁的「AI 生成」 | 健康助手不是玩法，这个标注同时起到「这不是兽医意见」的提示作用。**建议保留**，或改为「智能分诊建议，非诊断」 | 健康线红线（CLAUDE.md） |

**采用方案（下文按此展开）**：
- 页面文案、按钮、错误信息、官网宣传全部去 AI 化。
- 图片字节里不画任何可见标记（水印、角标、条幅都不画）。
- **小程序界面上**，凡是展示 AI 生成结果的地方，都在图片底部叠一条深色渐变蒙层，写「该内容由AI生成」（见第 3.4 节）。它在小程序内起提示作用，满足「提供生成合成服务时向用户提示」的要求。
- 图片文件里的隐式元数据标识继续写入（第五条）。这是文件层面唯一的标识，也是微信等平台自动识别的依据。
- 用户保存到相册的文件上没有可见标识，所以要走第九条的路径：
  - 用户第一次保存高清原图时，弹出一次确认：「保存的图片上不带可见标识。你自己发布时，请按平台要求标注为 AI 生成内容。」
  - 确认结果和协议版本落库，日志保留 ≥ 6 个月。
  - 用户协议对应条款同步补上（官网 `terms.astro:24` 那一条要加强，不能删）。
- 人类转生计划输出的是真人面孔，风险最高，这一类是否也走第九条，**仍建议问一次法务**。如果法务要求文件上必须有可见标识，只对这一类在图片边角加 5% 高度的小字「AI 合成」（GB 45438 的最低要求），其他玩法不受影响。

如果负责人决定连隐式标识也去掉，这属于明确违规（办法第十条禁止删除、隐匿标识），本方案不建议这么做。

另外，微信等分发平台会读取元数据自动加标识，所以图片本身没有角标，用户发到朋友圈时也可能被平台标注。这一点没有做真机验证。

### 3.2 改法

1. **所有水印代码删除**：worker 的 SVG / PNG 条幅、growth-service 的预览文字、年度报告的 `withPreviewWatermark`、Web 的 `.preview-watermark`。
2. **免费玩法的覆盖逻辑删除**（`generation-worker.ts:83-98` 整段和注释）。免费作品直接给干净的正式产物。
3. **预览仍然是预览，但不带水印**：
   - AI 候选：维持长边 640 的缩图，不加字。
   - 排版类：现在预览和正式产物同尺寸，去掉水印后二者就完全一样了。改为预览长边 1080（这个尺寸在手机上看已经清晰），付费拿原尺寸 PNG 和 PDF。
   - 预览图不开 `show-menu-by-longpress`（现状也没有开），放大查看改用自定义查看器（见 3.3）。截屏无法阻止，这是可以接受的代价。
4. **年度报告分享**改为按 `locked` 选文件，与作品分享一致。
5. **订单权益**：`platform-service.ts:424` 的 `watermarkRemoved: true` 不再写入新订单，改为 `{ formats, fullResolution: true }`。历史订单保留原字段，读取侧两种都认。

### 3.3 没有水印之后，付费买的是什么：只保留「保存高清原图」

**决定：保留付费，只收一项「保存高清原图」**，不包装「长期保存」「导出」等名目。

- **为什么还要付费**：写真和人化每次要调一次 lingsuan，单张 46–62 秒，是真实成本。每天 1 次免费额度只包括「制作 + 在小程序里看预览」。
- **为什么只有一项**：用户能理解，按钮上也写得下（「保存高清原图 ¥16.9」）。画册的 PDF、短片的 MP4 本来就是这些玩法的原图形态，付费后一起给，不单独收费。
- **为什么不卖「长期保存」**：长期保存是所有作品的默认能力，不是付费权益（见 3.6）。付费只决定能不能把高清原图存到相册。

**预览与原图的边界**（去水印后，这是付费墙唯一的依据）：

| | 预览（免费） | 高清原图（付费） |
| --- | --- | --- |
| 在小程序里看 | 可以，含放大查看 | 可以 |
| 分享卡 / 公开页 | 可以（展示预览图） | 可以 |
| 保存到相册 | **不可以** | 可以 |
| 分辨率 | AI 类长边 640px；排版类长边 1080px | 完整分辨率，另附 PDF / MP4 |
| 界面蒙层「该内容由AI生成」 | 有（仅生成类） | 有（仅生成类，在界面上） |
| 文件里的可见标记 | 无 | 无 |

**实现上要堵住的保存路径**：
- 放大查看不用 `wx.previewImage`（它自带长按保存）。改用自定义全屏查看器：`<image>` 不开 `show-menu-by-longpress`，并叠上蒙层。
- 现在的 `art-photo-result.js:103` 用的是 `wx.previewImage`，但写真套餐是付费后才能看，不受影响，保留即可。
- 截屏无法阻止。预览是 640px，截屏得到的也是低清图，这个代价可以接受。

**各玩法的付费标签**：

| 玩法 | 现在的付费标签 | 改为 |
| --- | --- | --- |
| 宠物艺术写真 / 人化（pl-10） | 选中候选高清无水印 | 保存高清原图 |
| 电影海报 | 竖版高清海报 | 保存高清原图 |
| 时光画册 / 纪念册 | 长图 + PDF / 高清纪念册 | 保存高清原图（含 PDF） |
| 短片（pl-19） | 高清无水印视频 | 保存高清视频 |
| 写真套餐 | 付费即生成（不变） | 付费后全部成片可保存（不变） |
| 证件、成长对比 | 免费下载（带水印） | 免费保存 |
| 年度报告 | 解锁高清版 | 保存高清版（不变） |

**会员**：「无水印」不再作为权益。会员页改写为可数的「每月 N 张高清原图」，年度报告高清版保持不变。具体 N 由运营决定，写在 `domain/membership.ts` 的权益清单里。

**拉新载体的替代**：原来 PL-23 靠图上的小程序码传播，去掉水印后改由分享环节承接：
- 作品分享卡走公开页，带「做同款」。
- 结果页配置 `onShareTimeline`。
- 趣测和人化另外提供一张用户主动生成的「分享海报」，海报上带小程序码。海报是独立的图，作品原图本身不带任何标记。

### 3.4 小程序内的「该内容由AI生成」蒙层

**显示范围**：只在 `needsAiLabel(plugin)` 为真的内容上显示，也就是 `generator.type === "image-api"` 的写真、人化、模板玩法和电影海报。排版类（证件、画册、成长对比）、视频模板、趣测都不是生成合成内容，不显示；显示了反而是错误标注。

| 位置 | 需要蒙层的图 |
| --- | --- |
| `pages/ai-run` | 两张候选、选中后的沉浸大图 |
| `pages/work` | 作品大图（生成类作品） |
| `pages/works` | 缩略图（小号蒙层，只写「AI生成」四个字） |
| `pages/art-photo-result` | 每张成片、放大预览 |
| 新的自定义全屏查看器 | 大图底部 |
| 公开分享落地页（新增） | 大图底部；好友看到的也要有 |
| 人化对比分享海报的预览 | 预览时叠加 |
| 样片（首页、分类页、制作页的示例效果） | **不加**。样片是平台自己做的效果示意，已经标注「示例效果」，加蒙层会让首页满屏都是提示 |

**视觉规格**（四套主题统一，不读 skin 变量）：
- 位置：图片容器底部，贴底、通栏，跟随图片圆角裁切。
- 背景：`linear-gradient(transparent, rgba(20,10,4,.66) 55%)`，高度约 64rpx（大图 88rpx）。
- 文字：白色，22rpx（大图 24rpx），左对齐，左右内边距 16rpx，单行不换行。
- 对比度：底色取 α=0.60 暖黑时，压在纯白图上，白字仍有 5.17:1（node 计算）；渐变实色段取 0.66，余量更足。
- 不响应点击（`pointer-events: none`），不遮挡图片上的选中勾。
- 纪念相关内容不需要蒙层，因为那里没有生成类内容。

**实现**：
- 新增 `components/ai-mask`，或在 `app.wxss` 放一个公共 `.ai-mask` 类，由各页面按 `item.aiGenerated` 渲染。
- 服务端在作品和候选的响应里下发 `aiGenerated: boolean`：候选已有这个字段（`growth-service.ts:292`），`hydrateWork` 需要按 `needsAiLabel(work.plugin)` 补上。
- 蒙层文案由服务端下发（`aiNotice: "该内容由AI生成"`），端上不写死，理由同健康免责声明：两端各写一份，迟早漏改一处。
- validate 可以加一条：出现 `aiGenerated` 的 WXML 必须同时渲染 `.ai-mask`。

### 3.6 取消「未付费作品 90 天后清理」：所有作品长期保存

**现状（已查代码确认，是现有规则）**：
- AI 候选选中后生成的作品（`growth-service.ts:378`，`expires_at = now + 90 天`）和排版类付费玩法的作品（`generation-worker.ts:103`），都以 `locked=true` 入库并带 90 天到期时间。
- 免费玩法作品是 `locked=false`，`expires_at=NULL`，不受影响；视频、互动、纪念作品也不写 `expires_at`。
- `scripts/worker.ts:45` 每 60 秒调一次 `cleanupExpiredContent`（`maintenance.ts:13-22`）。到期的锁定作品会被删掉 png / svg / pdf 对象，再 `DELETE FROM works`，属于硬删除，作品柜里连记录都不剩。
- 小程序作品柜有「已过期」筛选和标签（`works.js:5,59-67`），Web 作品柜同样有（`works-client.tsx:38`）。
- Web 作品柜写着「免费作品保留 90 天，已解锁作品会一直陪着你」（`app/works/page.tsx:9`），和实际规则相反：被删的是待付费作品，不是免费作品。
- 这条规则最早来自 `docs/product/03-features-shell.md:54`（「免费用户低清作品保留 90 天（成本控制），付费作品永久」），运维清单 `docs/operations/04-external-prerequisites.md:96` 还计划在云控制台配「免费作品 90 天自动清理」的生命周期规则（目前是待补状态，还没配）。

**决定：所有作品长期保存，不按时间清理。** 只在以下情况删除：
- 用户在作品详情里自己删除。
- 用户删除宠物（沿用 `softDeletePetResources`）。
- 注销账户（沿用 `account-service.ts` 的清理）。

理由：
- 产品定位是「积累免费、交付物付费」（CLAUDE.md 情绪价值方向）。作品是用户积累的一部分，到期消失会让人觉得被惩罚。
- 预览本来就小：AI 预览长边 640px，大约几十 KB，长期保存的存储成本可以接受。
- 90 天后用户可能还会回来付费。作品没了，这个转化机会也就没了。

**改动**：

| 位置 | 改动 |
| --- | --- |
| `server/maintenance.ts:13-22` | `cleanupExpiredContent` 删掉作品清理那段，只保留 `rate_limits` 清理和 `processObjectCleanupJobs`。函数可以改名为 `cleanupOperationalData`，调用方 `scripts/worker.ts:45`、`api/internal/maintenance/route.ts:3` 同步改 |
| `server/growth-service.ts:378`、`server/worker/generation-worker.ts:103-105,119-123` | 新作品 `expires_at` 一律写 NULL，UPDATE 分支的 `CASE WHEN locked` 也去掉 |
| 新迁移（编号按实施时的 `docs/README.md`） | `UPDATE works SET expires_at=NULL WHERE expires_at IS NOT NULL`，把存量作品也改成不过期。列本身保留，不删，避免牵动 `rows.ts` 和历史迁移 |
| 小程序 `pages/works/works.js:5,59-67`、`works.wxml` | 删掉「已过期」筛选项和「已过期」状态标签 |
| Web `components/works-client.tsx:38`、`app/works/page.tsx:9` | 删掉 expired 筛选；文案改为「作品会一直保存在这里，保存高清原图后可以存到相册」 |
| `platform-service.test.ts:238`「cleans expired locked works」 | 反转为「锁定作品不会被维护任务清理」：把 `expires_at` 设为过去时间，跑维护任务，断言作品和对象仍在 |
| 新增测试 | 新生成的锁定作品 `expires_at` 为 NULL；小程序作品柜不再出现「已过期」 |
| `docs/product/03-features-shell.md:54` | 按「正文不改写、追加差异记录」的约定，追加一条「2026-09 起所有作品长期保存」 |
| `docs/operations/04-external-prerequisites.md:96` | 删除「免费作品 90 天自动清理」这条待配的对象存储生命周期规则，**不要去云控制台配置它**，否则会绕过数据库直接删掉作品文件 |
| CLAUDE.md | 在「陪伴与记录的数据边界」一节补一句：作品与照片一样，不因时间或未付费被维护任务删除 |

**需要留意的成本**：没有清理以后，对象存储会持续增长。建议在后台健康快照里加一个「作品对象总量」指标，按月观察。真要控制成本，优先考虑把一年以上无访问的**预览**转成低频存储，而不是删除。这一项可以以后再做，不在本次范围。
