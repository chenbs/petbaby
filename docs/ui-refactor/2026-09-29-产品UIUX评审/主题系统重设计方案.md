# 四套主题重设计方案（2026-09-30）

配套：[`themes.html`](./themes.html)（四套主题同一首页、同一组件的并排原型），效果图 [`shots/themes-home.png`](./shots/themes-home.png)、[`shots/themes-components.png`](./shots/themes-components.png)。本方案只出设计与实现计划，没有修改代码。

**第二轮修订（2026-09-30）**：
- 橘子汽水、手账相册、星夜影院三套采纳。
- 橘子汽水的按钮色从 `#FF7A2F` 调浅到 `#FF9A52`。
- 第三套「潮玩派对」被评价为「AI 味太重」，改成**赛博街机**。原因分析见 3.4。

## 1. 现状与问题

四套主题（`film` 暖调胶片、`pet` 宠物主场、`brand` 内容品牌、`night` 夜间观影）之间的区别，只是 `theme/themes/*.js` 里 57 个 token 的取值不同。逐项对比后，差异基本只在颜色上：

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| 颜色 | 四套各有底色、字色、主色 | 唯一有明显差异的维度 |
| 圆角 | 卡片 16 / 24 / 16 / 20rpx，按钮 999 / 24 / 14 / 16rpx | 只差 4–8rpx，肉眼几乎分不出 |
| 阴影 | 三套浅色都是暖褐柔影，夜间是纯黑柔影 | 同一种材质 |
| 字体 | `titleSize` 全部 44rpx，字重 700 / 800 | 无差异 |
| 动效 | `animationType` 全部 `fade` | 无差异；`bounce / glow / neon` 三个枚举值从没用过 |
| 布局 | 所有页面共用一套 WXML；`art-film / art-pet / art-brand` 类只改 `.section-title` 的字重 | 无差异 |
| 装饰 | `decor` 只在 `pet` 下给空状态加几个圆点 | 几乎没有 |
| 底栏 | `tabbar-glass / tabbar-dark` 对应的是旧主题 ID，现在永远不会命中 | 已失效（`custom-tab-bar/index.wxss:57-70`） |

技术上有两个根因：
1. **页面拿不到主题身份。** `page-mixin` 已经把 `themeId` 放进 data，但 27 个页面没有一个把它写进根节点的 class，WXSS 也就没法按主题写结构差异。
2. **注入串没有余量。** 四套主题的注入串现在分别是 1740 / 1740 / 1763 / 1827 字节（这次用 node 实测）。门禁上限是 2KB，最多只剩约 220 字节，放不下更多结构变量。

## 2. 设计原则

- **统一的**：信息架构、页面结构、间距阶梯、字阶尺寸、图片比例、图标语义、交互模式、文案。换主题后，同一个东西还在同一个位置。
- **可变的**：材质（软糖、纸、金属、玻璃）、形状（圆角、切角、描边、倾斜）、装饰（胶带、邮戳、线框、齿孔）、配色、字体气质、动效、底栏形态，以及同一模块的**呈现方式**。例如首页「人类转生计划」在四套主题里分别是叠放卡、拍立得、扫描舱、海报墙。
- **不可变的**：
  - 用户照片和作品永远原色、完整显示，主题不给照片加滤镜。
  - 价格、错误、免责声明等信息区永远实底、可读。
  - 「该内容由AI生成」蒙层在四套主题下样式一致，不跟着主题变。
  - 纪念相关页面（`mood: "memorial"`）统一进入「安静模式」，关掉倾斜、贴纸、扫描线和弹跳。
- **可达性**：
  - 文字对比度 ≥ 4.5:1，大号数字和图标 ≥ 3:1。
  - 倾斜只用在装饰容器上，不用在正文段落上。
  - 遵守系统的「减少动态效果」设置。

## 3. 四套主题

主题 ID 保持 `pet / film / brand / night` 不变。这样 `LEGACY_THEME_IDS` 的迁移映射和用户本地缓存都不用动，只改名称和设计语言。

| | 橘子汽水（默认，`pet`） | 手账相册（`film`） | 赛博街机（`brand`） | 星夜影院（`night`） |
| --- | --- | --- | --- | --- |
| 空间隐喻 | 阳光很好的客厅 | 书桌上摊开的相册 | 深夜霓虹街区里的一台街机，宠物是主角 | 关灯后的家庭影院 |
| 设计语言 | 软糖 Pop：圆胖、明亮色块、墨蓝字 | 纸张拼贴：拍立得白边、胶带、邮戳、衬线标题 | 克制赛博：冷黑底、一种荧光主色、切角、网格、等宽数字 | 暗场影院：深紫黑、金色、胶片齿孔、玻璃 |

- 另外两个默认配色候选（蓝莓酸奶、蜜桃乌龙）不再推进，只在主评审文档第 5.1 节留档。

### 3.3 同一首页，四种呈现

四套主题的首页模块和顺序完全一样（见主评审文档第 6.1 节）：宠物名片 → 人类转生计划 → 麻麻精选 → 分类瀑布流。变化的是每个模块的呈现方式：

| 模块 | 橘子汽水 | 手账相册 | 赛博街机 | 星夜影院 |
| --- | --- | --- | --- | --- |
| 宠物名片 | 白色软卡，圆头像加浅橘环 | 档案页：拍立得头像、胶带、邮戳日期 | 角色面板：方形头像加青色线框，天数用等宽字体，右上角写「NO.0128 · 在线」 | 电影票根：虚线打孔、金色天数 |

### 3.4 为什么把「潮玩派对」改成「赛博街机」，以及赛博怎么做才不像 AI

「潮玩派对」显得 AI 味重，主要是因为同时用了生成式设计里最常见的几个套路：粗黑描边加实心硬投影、四五种撞色轮流用、每个元素都轻微倾斜、到处贴「NEW」贴纸。每一样单独看都没问题，堆在一起就成了模板感。

赛博风同样有一套常见套路：紫蓝渐变、大面积霓虹辉光、玻璃拟态、满屏英文 HUD 和故障字。赛博街机刻意避开这些，只保留四条规则：

1. **一种主色**。荧光柠檬 `#D4FF3A` 用在主按钮、选中、数字和竖条上。青和品红只做 1px 的分色线和状态点，不做大面积填充。
2. **不发光**。没有 `box-shadow` 辉光和文字发光，层次靠线框和明度差建立。唯一的动效是人类转生卡上的一条扫描线。
3. **形状优先**。直角、切角、网格底和等宽数字构成识别度，所以灰度下也能认出来。
4. **中文优先**。不加装饰性的英文 HUD 文案。只有编号、天数这类本来就是数字的内容用等宽字体。

另外，宠物照片和人像在冷黑底上会更突出，这正好适合人类转生和角色设定这类「变身」玩法。

## 4. 实现方案

### 4.1 分层

在现有四层主题系统之上加一层「皮肤」（skin），**不进注入串**：

| 层 | 内容 | 位置 | 体积影响 |
| --- | --- | --- | --- |
| L2 token（现有） | 57 个语义 token，只改取值 | `theme/themes/*.js` | 注入串基本不变 |
| **L2.5 skin 变量（新增）** | 约 22 个结构变量（下表） | `theme/tokens.js` 新增 `SKIN_SPEC`；各主题文件新增 `skin` 对象；`app.wxss` 按 `.skin-<id>{}` 逐字声明 | 不进注入串；`app.wxss` 约增加 3KB |
| **L3 skin 类（新增）** | 页面根节点加 `{{skinClass}}`（如 `skin-pet`；纪念页追加 `skin-quiet`） | `page-mixin.buildThemeData` 下发 `skinClass`；27 个页面的根节点各改一处 | 无 |
| L4 资源（新增） | 每套主题：底栏图标 10 张（5 项 × 选中 / 未选中）、空状态插画 1 张、主题预览图 1 张、可选底纹 1 张 | `assets/skins/<id>/` | 每套约 40KB 以内，合计约 160KB；当前包体 1.59MB，加上后仍在 2MB 以内（删掉互动星尘页后还能省约 60KB） |

CSS 自定义属性可以穿过组件边界继承，所以挂在页面根节点上的 `.skin-x{--skin-*}` 对页面里所有组件都生效，组件不需要知道当前是哪套主题。

底栏组件不在 page 节点下，拿不到这些变量。它改为由 JS 生成 skin 变量串，和现在的 `getConstantVars()` 一起写到自己根节点的 style 上。

切角用 `clip-path: polygon()`：基础库 2.19.2 的 iOS 和安卓 WebView 都支持。不支持时直接显示为直角，不影响使用，但需要真机确认。

## 5. 验收标准

- 同一页面在四套主题下并排截图，转成灰度后，仍能分辨出四种风格。
- 四套主题的注入串仍小于 2KB，skin 变量不进注入串。
- 所有文字对比度 ≥ 4.5:1；validate 第 5、6 项和新增的第 11、12 项全部通过。
- 用户照片、作品、候选图不被裁切、不加滤镜、不倾斜。倾斜只用于首页和列表里的装饰性卡片，详情页和结果页一律不倾斜。
- 「该内容由AI生成」蒙层在四套主题下外观一致，都能看清。
- 纪念空间、纪念分享页在四套主题下都没有贴纸、倾斜、扫描线和弹跳。
- 主题切换即时生效，不发网络请求，返回上级页面时不残留旧主题（沿用需求 6.3.3）。

## 6. 风险

- **维护成本上升。** 以后每新增一个组件都要考虑四种 skin。用 `var(--skin-*, 默认值)` 的回退写法可以降低成本：没有单独设计的组件，自动沿用默认样式。
- **小屏上可能显得拥挤。** 320px 下，赛博街机的切角要缩到 20rpx，手账相册的倾斜限制在 1° 以内，需要实测。
- **星夜影院的毛玻璃在低端安卓上会降级为实底。** 沿用现有的 `detectBlurSupport` 与 `degrade` 即可。
- **赛博街机的故障错位动效要克制。** 只在按压时出现约 120ms，不做常驻闪烁，并遵守「减少动态效果」设置。
- **默认主题换色后与官网不一致。** 官网现在是莓果色，而且 `site.css` 是原型文件的逐字节副本。官网是否同步换色需要单独决定，不在本次范围内。
