# 互动星尘页（PL-15）下线实施方案（2026-09-30）

用户已确认：互动星尘页在小程序里本来就没有入口，这次连同相关代码一起删除。本文只做清点和方案，没有改代码。清点方法是全仓 grep 加逐文件阅读，没有跑构建和测试。

## 1. 结论

- PL-15 的**页面、接口、后台、组件和 Worker 分支都可以删**。
- 有一处**不能删**：`plugins/registry.ts` 里的 PL-15 manifest 要保留，只把状态改成 `archived`。原因有两个：
  1. **纪念空间的「星尘纪念页」写的也是 `plugin_id='pl-15'`**（`memorial-service.ts:63`，`source_kind='memorial'`）。它不依赖互动会话，但显示名和计价都从 PL-15 的 `toneVariants.memorial` 取。
  2. **历史互动导出**会在 `works` 表里留下 `plugin_id='pl-15'`、`source_kind='interactive'` 的短片作品。`works` 表没有 `plugin_snapshot` 列，`hydrateWork` 每次都用 `getRuntimePlugin(work.pluginId)` 现查。manifest 一删，这两类作品都会抛 `WORK_INCOMPLETE`。又因为 `listWorks` 会逐行 hydrate，作品柜可能整列打不开。这一点是读代码推断的，没有实测。
- 这与 CLAUDE.md 对 PL-20/21/22 的约定一致：老 manifest 保留为 `archived`，不删除。
- 包体约减少 48KB（3 张互动样片加 1 张首页卡片图）。

### 2.3 让已部署环境的 PL-15 也变成 archived

`ensurePluginConfigs` 用 `ON CONFLICT DO NOTHING` 播种，之后 `listRuntimePlugins` 只读库，所以**只改 `registry.ts` 不会影响已经有 pl-15 行的环境**。需要新增一个 forward-only 迁移 `0036`（编号以实施时 `docs/README.md` 为准），把 `plugin_configs` 里 pl-15 的 `manifest.status` 改成 `archived`，并写一条 `plugin_config_versions` 记录，保持版本号自增和审计口径。不改历史迁移。

## 4. 分两步下线

**第一步（随本次改版，约 1.5 天）**
- 删除第 2 节列出的入口、页面、接口、后台和 Worker 分支。
- manifest 改为 archived，加迁移。
- 已分享出去的互动链接会失效。分享默认 7 天有效，最长 1 年。公开接口删除后，这些链接打开是 404。可以接受，但要在发布说明里写明。
- 数据表 `interactive_sessions` / `interactive_events` 先**保留不删**，作为回退余地。

**第二步（观察一个发布周期后，约 0.5 天）**

  - `server/annual/aggregate.ts:47,77,82,105,110,115`
