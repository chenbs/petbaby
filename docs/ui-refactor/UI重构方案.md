## 一、五个布局方向

### 共同前提

无论最终选用哪几个方向，有一条判断贯穿全部：

> **凡是描述视觉结果的地方，必须用视觉结果本身来描述。**

现有界面里，功能入口是纯文字卡片（编号 + 标题 + 一句话 + 「开始制作 →」），
风格选项是抽象渐变色块。用户在看不到产出的前提下做付费决策。
五个方向中有四个（A / C / E / J）都在解决这件事，只是解法不同。

另一条贯穿全部的：**除 J 外，所有方向共用同一套配色**。
效果图刻意统一了色彩，是为了让差异 100% 来自布局。
配色与主题人格是最后一步，不是第一步。

### A · 作品墙优先 (Showcase First)

#### 介绍

把「已产出的成品」放到第一屏。功能入口不再是文字卡片，而是**成品大图本身**——
图就是广告。采用杂志式 `1 大 + 2 列` 网格制造视觉节奏，标题压在图上的渐变遮罩里，
价格做成浮标。详情页大图顶到状态栏，白色面板上浮盖住图底，底部常驻 CTA。

这是五个方向里**通用性最强**的一个：它的网格结构可以复用到几乎所有列表与详情场景。

#### 优点

- **直接解决当前最致命的问题**：用户看不到成品就要付钱
- **通用性最强**：同一套网格规则能覆盖列表、详情、作品库、推荐位
- **落地成本最低**：常规布局，无特殊 API，无 3D 变换，无兼容风险
- **天然显精致**：图片主导的界面，质感由图片承担，UI 只需退让
- 悬浮胶囊 tabbar 顺带解决了现有的色块高亮问题

#### 缺点

- **强依赖样例图质量**。图不够好，方案的全部价值归零，且会被大图放大缺陷
- 纯网格浏览缺少情感钩子，留存靠内容而非结构
- 图片量大，对加载性能和 CDN 配置有实打实的要求
- 视觉记忆点弱于 J，「一眼记住」的能力不如卡牌或黏土形态

#### 适用页面类型

| 页面类型 | 适配度 | 说明 |
|---|---|---|
| 内容/功能列表页 | ★★★ | 本方向的主场 |
| 商品或服务详情页 | ★★★ | 沉浸详情 + 面板上浮是标准解 |
| 作品库 / 相册 | ★★★ | 换成 2 列等宽或瀑布流即可 |
| 推荐位 / 首屏 | ★★★ | Hero + 网格的节奏 |
| 多步表单 | ★ | 不适合，无图可用 |
| 信息密集页（对比 / 设置） | ★★ | 需去掉大图，只保留网格与卡片规则 |

#### 落地要点

- 图片比例严格固定：Hero `16:10`、网格卡 `3:4`、横滑小图 `3:4`
- 压图文字必须有渐变遮罩，遮罩基色用**暖褐** `rgba(20,10,4)` 而非纯黑
- Hero 位留给转化率最高的项，排序由数据驱动而非人工
- 必须配骨架屏，否则图片加载期的白屏会摧毁质感

### C · 沉浸故事流 (Immersive Feed)

#### 介绍

一屏一个焦点，图**全屏铺满**，上下滑切换。文字压在渐变遮罩上，右侧竖排轻交互，
底部常驻主 CTA。

它有一个常被忽略的第二用法：**把同一模式用在表单上**——背景虚化成目标产出图，
表单浮在半透明卡片里。用户填资料时始终看得见「我要做出来的东西」，
这对多步表单的完成率有直接影响。

#### 效果图

```

╰──────────────────────────────────╯   │  │       下一步                │  │
                                        ╰──╰────────────────────────────╯──╯
```

#### 优点

- **视觉冲击力最强**，无干扰，一屏只做一件事
- 天然适合分享传播，截图即海报
- 表单变体解决了「填表时看不见目标」的问题，对完成率有直接帮助
- 是五个方向里最容易做出「电影级」质感的

#### 缺点

- **信息密度最低**。项目数量一多就难以发现和比较
- 装不下列表、表格、对比、设置这类内容
- 依赖竖版高清图，横图或低质图会直接崩坏
- 半透明/毛玻璃层在部分安卓机型不支持或性能差，**必须准备降级方案**
- 全屏 swiper 的图片预加载策略不做好，滑动会卡

#### 适用页面类型

| 页面类型 | 适配度 | 说明 |
|---|---|---|
| 单项决策页 / 详情页 | ★★★ | 一屏一焦点正是决策所需 |
| 结果反馈页 | ★★★ | 情绪高潮，全屏呈现最有力 |
| 多步表单 | ★★★ | 用浮层变体，背景保持虚化目标图 |
| 内容浏览流 | ★★ | 项目数 ≤8 时可用，超过则难发现 |
| 功能列表页 | ★ | 不适合，可发现性差 |
| 信息密集页 | ✗ | 完全不适合 |

#### 落地要点

- 半透明层降级：
  ```css
  .glass{ background: rgba(255,255,255,.92); }         /* 降级：高不透明度纯色 */
  @supports (backdrop-filter: blur(20px)){
    .glass{ background: rgba(255,255,255,.78); backdrop-filter: blur(20px); }
  }
  ```
- 遮罩梯度要三段，不能只用两段线性渐变，否则中间会有明显断层
- 步骤条改为细线分段，弱化数字，减少视觉噪音
- 全屏图预加载相邻两屏，超出释放

### E · 宠物主页 (Pet-Centric Hub)

#### 介绍

五个方向里**唯一改变信息架构**的一个。把「功能优先」反转为「对象优先」：
进入页面看到的不是功能列表，而是**某一只宠物的主页**——封面照、陪伴天数、
统计数据、最近产出，然后才是「还可以为它做什么」。多对象用顶部头像横切换。

第二屏是同一套架构的**时间轴形态**，用于叙事和回溯。

「陪伴第 178 天」这类数字是成本最低的留存钩子——它每天都在变，且只属于这个用户。

#### 优点

- **情感联结最强**。用户第一眼看到的是自己的宠物，不是货架
- 天然契合档案、纪念、成长记录这类场景
- 多对象切换的架构清晰，比在功能里选宠物更符合直觉
- 「陪伴天数」「统计数字」是零成本的留存钩子
- 时间轴形态复用同一套数据结构，不需要额外建模

#### 缺点

- **无数据时页面是空的**。新用户首次进入必须有专门的引导态，否则体验断裂
- **功能入口曝光下沉**。用户要先经过宠物信息才能看到能做什么，会影响首次转化
- 改动涉及信息架构与路由，不是纯样式改造，工作量大于其他方向
- 单宠用户的顶部横切换区域会显得空

#### 适用页面类型

| 页面类型 | 适配度 | 说明 |
|---|---|---|
| 对象档案页 / 个人中心 | ★★★ | 本方向的主场 |
| 叙事 / 回溯 / 成长记录 | ★★★ | 时间轴形态 |
| 情感向内容页 | ★★★ | 沉静基调 + 时间轴 |
| 首屏 / 主入口 | ★★ | 老用户体验极好，新用户是空的 |
| 功能列表页 | ★★ | 作为「可做的事」区块嵌入，不能独立成页 |
| 多步表单 | ✗ | 不适合 |
| 信息密集页 | ★ | 统计条可复用，整体结构不适合 |

#### 落地要点

- **必须设计空态与首启引导**，这是本方向成败的关键，不是可选项
- 顶部对象切换：单对象时隐藏切换区，只显示当前对象
- 统计数字要真实且会变化，静态数字反而降低可信度
- 时间轴事件分两类：有图（大卡）与无图（窄条），避免全是大卡导致滚动过长

### F · 杂志封面 (Editorial Cover)

#### 介绍

刊物封面的表达方式：满版出血图 + 期数标识 + 巨大标题 + 一段引文 + 顶底细线框住版心。

它的质感**不来自装饰，来自排版纪律**——大留白、极端字重对比（700 的黑体标题配
300 的斜体）、精确负字距、一条 1px 的横线。整屏没有一个圆角卡片、没有一个阴影。

这是五个方向里**信息量最低但气质最高**的一个。适合「一屏定调」的场景，
不适合承载列表和操作。

#### 效果图

`layout-directions.html#dirF`（一屏：封面 + 排版参数说明）

```
┌──────────────────────────────────┐
│ PET LAB              ISSUE 07    │  ← 刊名 + 期数，字距 +0.3em
│ ──────────────────────────────── │  ← 1px 细线，透明度 .28
│                                   │
│                                   │
│        [ 满 版 出 血 图 ]         │
│         无边距、无圆角             │
│                                   │
│                                   │
│  本 期 封 面 故 事                 │  ← 20rpx，字距 +0.28em
│                                   │
│  夏天的                            │  ← 56rpx / 700 / 字距 -0.04em
│  它                                │  ← 同字号 / 300 / 斜体
│                                   │
│  │ 午后三点的窗台，光正好。        │  ← 引文，左侧 2px 竖线
│  │ 这一期，我们把六种方式留给夏天。 │
│  ──────────────────────────────── │
│  2026·07      6 个栏目   下滑 ↓   │
│      本期    往期    我的          │
╰──────────────────────────────────╯
```

**硬性约束**（破一条就失效）：

- 整屏不出现圆角卡片
- 整屏不出现阴影
- 图片满版出血，不留边距
- 遮罩用暖褐 `rgba(8,5,3)`，不用纯黑
- 最多两级字号，靠**字重和字距**拉开层级，不靠颜色
- 主标题不超过 8 个字

#### 优点

- **质感天花板**。五个方向里唯一能做到「一眼觉得贵」的
- **成本极低**。结构极简，无图片处理、无动效、无兼容问题
- 排版方法论可以**脱离本方向单独吸收**——即使不整屏采用，
  字重对比、负字距、留白纪律也应该应用到全站
- 与「精致有质感」的诉求命中度最高

#### 缺点

- **信息量极低**，一屏只能传达一件事
- 不能承载任何列表、操作、对比、表单
- **强依赖文案质量**。标题写得平庸，整屏立刻垮掉，且无从补救
- 与「可爱」是反方向，冷静克制，不走萌路线
- 如果做成「每期主题」的形态，需要持续的内容运营支撑

#### 适用页面类型

| 页面类型 | 适配度 | 说明 |
|---|---|---|
| 开篇 / 引导 / 定调页 | ★★★ | 本方向的主场 |
| 报告 / 总结 / 年度回顾 | ★★★ | 刊物形态天然契合 |
| 品牌介绍 / 关于页 | ★★★ | |
| 情感叙事页 | ★★ | 与 E 的时间轴组合使用 |
| 列表页 | ✗ | 承载不了 |
| 表单 / 操作页 | ✗ | 承载不了 |
| 信息密集页 | ✗ | 承载不了 |

#### 落地要点

- 版心边距比常规页面宽（`48rpx` vs `32rpx`），留白是这个方向的主要材料
- 中文负字距要谨慎，`-0.04em` 是上限，再大会粘连
- 字重 300 在部分安卓设备上会回退到 400，需实测；不可靠时改用透明度区分
- 文案必须先写好再做设计，反过来一定失败

### J · 黏土软萌 (Claymorphism)

#### 介绍

「可爱就要极致可爱」的极端解，五个方向里**唯一把可爱度拉满**的。

核心不是配色，是**体积感**：超大圆角（28px+）、内高光 + 内阴影 + 双层外投影
模拟「捏出来的」厚度，按钮像果冻，按下应有 Q 弹回弹。

**成本远低于看起来的样子**——黏土质感 100% 由 CSS 多层 `box-shadow` 实现，
不需要任何 3D 素材或图片。效果图里除成品图外没有一张位图。

**黏土质感的 CSS 配方**：

```css
.clay{
  background: #FFFDFB;
  border-radius: 56rpx;
  box-shadow:
    inset 0 -10rpx 20rpx rgba(255,255,255,.95),   /* 内下高光：制造凸起 */
    inset 0 10rpx 24rpx rgba(190,140,120,.13),    /* 内上阴影：制造厚度 */
    0 16rpx 32rpx -12rpx rgba(190,140,120,.34),   /* 近距外投影 */
    0 36rpx 68rpx -36rpx rgba(190,140,120,.50);   /* 远距外投影 */
}
```

四层缺一不可：去掉内高光就变扁，去掉内阴影就变塑料，只留单层外投影就没有悬浮感。

#### 优点

- **可爱度唯一拉满的方向**，在一堆扁平小程序里极其显眼
- **成本极低**：纯 CSS，零素材，不需要设计师产出 3D 资源
- 视觉记忆点最强，「一眼记住」的能力五向第一
- 果冻按压反馈天然有趣，微交互成本也低

#### 缺点

- **与「企业级质感」直接冲突**。可爱度拉满的代价就是专业感下降，这是结构性的，不能两全
- **强依赖配色**，是唯一不能用中性色演示的方向。色彩不到位，体积感立刻塌
- 多层阴影**在低端安卓会掉帧**，同屏元素数量必须限制
- **写实成品图与黏土 UI 可能割裂**——照片是写实的，容器是卡通的，需要用圆角内阴影过渡
- 趋势背书较弱：检索显示 Claymorphism 的资料多为断言，缺实例与实现指导

#### 适用页面类型

| 页面类型 | 适配度 | 说明 |
|---|---|---|
| 结果反馈 / 庆祝页 | ★★★ | 仪式感与可爱度都需要 |
| 功能入口网格 | ★★★ | 果冻格子 |
| 空状态 | ★★★ | 从敷衍变可爱的最快路径 |
| 引导 / 新手页 | ★★★ | |
| 内容浏览页 | ★★ | 可用，但会与成品图抢注意力 |
| 信息密集页 | ★ | 圆角和阴影会挤占空间 |
| 叙事 / 纪念类页面 | ✗ | 情绪不符 |

#### 落地要点

- **限制同屏黏土元素数量 ≤12**，超过在低端机会掉帧
- 滚动列表中的卡片用**单层**阴影，只在静态区域用完整四层
- 成品图容器加 `inset 0 6rpx 18rpx rgba(150,100,80,.28)`，
  让写实照片「嵌进」黏土表面，缓解割裂感
- 按压态：`transform: scale(.96)` + 阴影收紧，时长 `120ms`
- 若整站不采用本方向，可**只抽取质感层**——把黏土 box-shadow 用在按钮、
  图标容器、结果卡片上，骨架仍走 A 或 E

### 五向速查表

| 方向 | 类型 | 信息密度 | 抓眼球 | 可爱度 | 质感 | 成本 | 最强的一点 | 最大的限制 |
|---|---|---|---|---|---|---|---|---|
| **A 作品墙** | 骨架 | 中高 | 高 | 中 | 高 | 低 | 把结果放到最前 | 依赖样例图质量 |
| **C 沉浸流** | 局部 | 最低 | 最高 | 中 | 很高 | 中 | 一屏一个焦点 | 装不下列表 |
| **E 宠物主页** | 骨架 | 中 | 高 | 很高 | 高 | 中 | 情感联结最强 | 无数据时是空的 |
| **F 杂志封面** | 局部 | 最低 | 高 | 低 | 最高 | 低 | 气质最高 | 只能定调，不能操作 |
| **J 黏土软萌** | 局部 | 中 | 很高 | 最高 | 中 | 低 | 可爱度唯一拉满 | 与企业级直接冲突 |

**骨架型**（A / E）能支撑整个信息架构，只能选一个作为主结构。
**局部型**（C / F / J）适合注入到特定场景，可以并存。

#### 一个必须先回答的问题

你的原话是「可爱就要极致可爱，精致有质感就要极致有质感」。
但在同一个界面上，这两件事是**互相削弱**的：

- **J** 是「极致可爱」的极端
- **F** 是「极致精致」的极端
- 中间的折中（既有点可爱又有点高级）**恰恰就是现在最不满意的状态**

所以必须选一边作为主基调，另一边只能在局部出现。
两条路都可行，但不能同时作为主基调。

- 选**可爱**：主基调 J，骨架 A/E，F 只用在报告类页面
- 选**精致**：主基调 F 的排版方法论，骨架 A/E，J 只用在结果页和空状态

## 二、全局地基：Token 体系

### 2.2 圆角

```css
  --radius-xs: 8rpx;     /* badge、小标签 */
```

### 2.4 阴影

**这一节是「质感」最关键的部分。**

现有卡片靠 `1px 边框` 区分层级——这是典型的平面感来源。改为多层暖色阴影：

```css
  /* 阴影基色：暖褐，不是纯黑。这是廉价与高级最快的分水岭 */
  --shadow-hue: 60, 35, 20;

  --shadow-card:
    0 4rpx 16rpx -4rpx rgba(var(--shadow-hue), .10),
    0 32rpx 64rpx -36rpx rgba(var(--shadow-hue), .28);

  --shadow-image:
    0 8rpx 24rpx -8rpx rgba(var(--shadow-hue), .16),
    0 56rpx 96rpx -48rpx rgba(var(--shadow-hue), .42);

  --shadow-float:
    0 16rpx 40rpx -12rpx rgba(var(--shadow-hue), .18),
    0 64rpx 120rpx -40rpx rgba(var(--shadow-hue), .38);

  --shadow-press:
    0 2rpx 8rpx -2rpx rgba(var(--shadow-hue), .14);

  /* J 方向：黏土四层 */
  --shadow-clay:
    inset 0 -10rpx 20rpx rgba(255,255,255,.95),
    inset 0 10rpx 24rpx rgba(190,140,120,.13),
    0 16rpx 32rpx -12rpx rgba(190,140,120,.34),
    0 36rpx 68rpx -36rpx rgba(190,140,120,.50);

  --shadow-clay-inset:  /* 图片嵌入黏土表面 */
    inset 0 6rpx 18rpx rgba(150,100,80,.28);

  /* F 方向：无阴影 */
  --shadow-none: none;
```

暗色主题下把 `--shadow-hue` 改为 `0, 0, 0` 并提高不透明度，
同时改用**顶部高光边框**代替阴影建立层级：

```css
  --border-highlight: 1rpx solid rgba(255,255,255,.08);
```

### 2.5 图片

```css
  --ratio-hero: 16/10;      /* 大图入口 */
  --ratio-card: 3/4;        /* 网格卡、横滑小图 */
  --ratio-cover: 4/3;       /* 详情页封面 */
  --ratio-square: 1/1;      /* 头像、方形展示 */

  --overlay-img: 20, 10, 4; /* 图上遮罩基色，暖褐 */
```

**统一处理规则**：

```css
/* 压图文字必备的三段渐变遮罩 */
.veil{
  background: linear-gradient(to top,
    rgba(var(--overlay-img), .82) 0%,
    rgba(var(--overlay-img), .28) 45%,
    transparent 72%);
}
/* 所有图片的轻微暗角 */
.ph::after{
  background: radial-gradient(120% 90% at 50% 15%,
    transparent 35%, rgba(60,35,20,.34));
}
```

### 2.6 动效

```css
  --ease-out: cubic-bezier(.22, 1, .36, 1);
  --ease-in-out: cubic-bezier(.4, 0, .2, 1);
  --dur-fast: 120ms;      /* 按压反馈 */
  --dur-base: 240ms;      /* 卡片进场、切换 */
  --dur-slow: 400ms;      /* 页面转场 */
  --dur-reveal: 900ms;    /* 结果显影 */
  --stagger: 40ms;        /* 列表逐项延迟 */
```

**投入产出比最高的三个动效**：

1. **按压缩放**：所有可点卡片 `transform: scale(.97)` + 阴影收紧
2. **首屏 stagger 进场**：上移 20rpx + 淡入，每项延迟 40ms
3. **结果显影**：从模糊 + 低饱和渐变到清晰

### 2.7 语义色需补充的槽位

现有 Token 主要覆盖背景/文字/主色。以下槽位建议补齐：

```css
  --c-skeleton-shine: rgba(255,255,255,.6);
  --c-divider-soft: rgba(0,0,0,.06);   /* 替代现有 1px 实线分割 */
  --c-clay-base: #FFFDFB;              /* J 方向基底 */
  --c-clay-shadow: 190,140,120;        /* J 方向阴影色相 */
  --c-cover-overlay: 8,5,3;            /* F 方向遮罩，比常规更深 */
```

## 三、组件规范

跨方向共用。方向差异体现在参数取值，不体现在组件结构。

### 3.1 卡片

| 类型 | 圆角 | 阴影 | 内边距 | 用于 |
|---|---|---|---|---|
| `card-hero` | `--radius-lg` | `--shadow-image` | 0（图满） | A 大图入口 |
| `card-grid` | `--radius-md` | `--shadow-image` | 0（图满） | A 网格卡、作品 |
| `card-info` | `--radius-md` | `--shadow-card` | `--space-4` | 信息卡、对比卡 |
| `card-glass` | `--radius-lg` | `--shadow-float` | `--space-4` | C 浮层表单 |
| `card-clay` | `--radius-clay` | `--shadow-clay` | `--space-4` | J 果冻卡 |
| `card-flat` | `--radius-none` | `--shadow-none` | `--page-x-wide` | F 封面区块 |

**统一按压态**：`scale(.97)` + `--shadow-press` + `--dur-fast`

**统一删除**：卡片的 `1rpx solid border`（暗色主题除外，改用 `--border-highlight`）

### 3.2 按钮

| 类型 | 高度 | 圆角 | 样式 |
|---|---|---|---|
| 主按钮 | `96rpx` | `--radius-full` | 深色实底 + `--shadow-float` |
| 次按钮 | `88rpx` | `--radius-full` | 描边 1.5rpx，无底色 |
| 底部常驻 CTA | `100rpx` | `--radius-full` | 主按钮 + 右侧价格小字（透明度 .55） |
| 果冻按钮（J） | `96rpx` | `--radius-full` | 渐变 + 内高光 + 强投影 |
| 文字链 | — | — | 下划线 offset 4rpx |

**CTA 必带价格**，用 `.55` 透明度做次要处理——保持透明度的同时减少心理阻力。

### 3.3 输入

| 类型 | 形态 | 用于 |
|---|---|---|
| `input-box` | 圆角 `--radius-sm` + 浅底 | 常规文本输入 |
| `chip-group` | 胶囊组，选中反色 | **≤4 个选项的单选** |
| `card-select` | 缩略图卡片 + 对勾 | 视觉型选项 |
| `picker-row` | 右侧箭头 + 值 | >4 个选项 |

**两条硬规则**：

1. **选项 ≤4 个时禁止使用 picker**，一律用 chip 直选。
   现有界面里性别、日期类型这类少选项字段都用了 picker，多了一次无谓交互。
2. **凡是描述视觉结果的选项，必须用缩略图**。
   同一组对比图必须使用**同一个主体**，否则用户无法分辨差异来自风格还是来自主体。

### 3.4 tabbar

必须使用 `custom-tab-bar` 自定义组件（原生 tabBar 无法实现悬浮形态）。

| 方向 | 形态 |
|---|---|
| A / E | 悬浮胶囊，深色半透明底，选中态白色实心胶囊 |
| C / F | 半透明浮层，渐变遮罩融入背景 |
| J | 厚圆角块，选中态渐变凸起 |

**通用**：距底 `32rpx + env(safe-area-inset-bottom)`；
切换动画 240ms `--ease-out`；**取消现有的纯色方块高亮**。

### 3.5 步骤条

从「数字圆圈 + 全部文字标签」改为 **N 段细线**：

```
▬▬▬▬  ▬▬▬▬  ▬▬▬▬  ▬▬▬▬
      当前步骤名称
```

- 线高 `6rpx`，圆角 `--radius-full`
- 已完成/当前 = 强调色，未开始 = `rgba(0,0,0,.12)`
- **只显示当前步骤的文字**，不显示全部标签，减少视觉噪音

### 3.6 空状态

现有空状态是「灰圆圈 + emoji + 两行字」。统一改为：

- **单色线条 SVG 插画**，线宽 3rpx，尺寸 240×240rpx，颜色跟随 `--c-text-3`
- 一句话说明 + 单一 CTA
- **不用 emoji**（廉价感的最大来源之一）
- **不用彩色插画**（会与成品图抢注意力）
- 情感向场景的空态用弱化 CTA（文字链而非按钮），不催促

### 3.7 骨架屏

所有含图片的列表页必须有。图片加载期的白屏会直接摧毁质感。

- 形状与真实内容一致（图块 + 两行文字条）
- 底色 `--c-skeleton`，微光 `--c-skeleton-shine`，1400ms 循环
- 用 `image` 的 `bindload` / `binderror` 控制显隐

## 五、具体重构方案

### 5.1 素材需求（前置条件）

**这是方案能否成立的硬前提。** A / C / E 三个方向的价值都建立在样例图质量上。

| 素材 | 数量 | 要求 |
|---|---|---|
| 功能入口样例图 | 每个入口 5 张（1 张 16:10 + 4 张 3:4） | 覆盖猫/狗/异宠至少三个物种，覆盖不同毛色 |
| 风格对比图 | 每个风格选项 1 张 | **必须是同一只样板宠物**，否则无法对比 |
| 详情页封面 | 每个入口 1 张 4:3 | 通栏出血用 |
| 空状态插画 | 5-6 张 | 单色线条 SVG，240×240rpx |

**一条硬约束**：样例图必须是**真实用产品生成的**，不能用外部素材图。
否则用户实际生成后的落差感会比现在的纯文字更伤转化。

> 这部分工作量可能不亚于 UI 改造本身，需要单独排期。

### 5.2 分阶段落地

#### 阶段 0 · 读代码与分配（当前待办）

- [ ] 通读项目结构，产出**完整页面清单**（路由 + 页面职责 + 信息密度分级）
- [ ] 梳理现有 Token 定义位置、命名规范、主题切换机制
- [ ] 为每个页面**分配布局方向**，产出分配表
- [ ] 识别可复用组件与需要新建的组件
- [ ] 评估各页面改造工作量，排出优先级

> 这一阶段的产出是本文档的补充章节，不是替代。

#### 阶段 1 · 地基

> 与方向分配无关，可与阶段 0 并行

- [ ] 新建 `styles/tokens-structure.wxss`，落地第二章全部 Token
- [ ] 补齐语义色缺失槽位（2.7）
- [ ] 建立全局按压反馈规则
- [ ] 实现骨架屏组件
- [ ] 实现 `custom-tab-bar`

#### 阶段 2 · 组件层

- [ ] 按第三章重建卡片、按钮、输入、步骤条、空状态组件
- [ ] 少选项字段（≤4）从 picker 改为 chip
- [ ] 视觉型选项从色块改为缩略图
- [ ] 图片组件统一封装（固定比例 + 遮罩 + 暗角 + 懒加载 + 兜底）

#### 阶段 3 · 页面改造

按阶段 0 的分配表逐页执行。建议顺序：

1. 流量入口页（影响面最大）
2. 转化链路页（详情 → 表单 → 结果）
3. 留存相关页（档案、作品库）
4. 长尾页（设置、权益、订单）

#### 阶段 4 · 主题人格

- [ ] 先只做一套主题，把结构和组件全部验证完
- [ ] 再批量生成其余三套
- [ ] 主题切换时同步替换：语义色 Token、装饰性素材色、空状态插画线条色

> **主题是最后一步，不是第一步。** 结构没定就调色板，等于在毛坯房里挑窗帘。

### 5.3 技术落地要点

#### 自定义 tabbar

```json
// app.json
{ "tabBar": { "custom": true, "list": [ /* 必须保留，用于降级 */ ] } }
```

- 需在根目录建 `custom-tab-bar/` 组件
- 每个 tab 页 `onShow` 里手动 `this.getTabBar().setData({ selected: N })`
- 页面内容底部预留 `padding-bottom: calc(160rpx + env(safe-area-inset-bottom))`

#### 图片性能（最关键）

改版后图片量剧增，这是性能的最大风险点。

| 措施 | 做法 |
|---|---|
| 格式 | 优先 WebP，降级 JPEG |
| CDN | 用带图片处理能力的 CDN，URL 参数控制尺寸与质量 |
| 尺寸 | 按实际渲染尺寸 ×2 出图，禁止用原图缩放；列表缩略图 ≤100KB |
| 懒加载 | `<image lazy-load>`，仅对首屏外生效 |
| 裁切 | 统一 `mode="aspectFill"` + 固定比例容器 |
| 长列表 | 超过 50 项启用 `recycle-view` |

#### 阴影性能

多层 `box-shadow` 在低端安卓大量使用会掉帧。

- 单页同时可见的带阴影元素**控制在 12 个以内**
- 滚动列表中的卡片用**单层**阴影
- 禁止在 `transform` 动画元素上同时改变 `box-shadow`，改用 `opacity` 切换两个预设层

#### 半透明层兼容

`backdrop-filter` 在小程序中兼容不完整（iOS 较好，部分安卓不支持或性能差）。
统一按 [C 方向落地要点](#落地要点-1) 的 `@supports` 方案降级。
本方案中毛玻璃非必需，可作为渐进增强。

#### 自定义字体

```js
wx.loadFontFace({
  family: 'XXX',
  source: 'url("https://域名/fonts/xxx.woff2")',
  global: true,      // 基础库 2.10.0+
  fail(){}           // 必须处理，静默降级
})
```

- 域名需在小程序后台配置合法域名
- **中文字体必须子集化**（完整版可达 10MB，子集化后可压到 200KB 内）
- 只用于装饰性文字，**不做全局替换**（加载失败的 FOUT 闪动会严重伤害质感）

#### 安全区与小屏适配

```css
padding-bottom: calc(var(--space-4) + env(safe-area-inset-bottom));
padding-top: calc(var(--space-4) + env(safe-area-inset-top));  /* 沉浸式页面 */
```

- 小屏（320px）需回归测试，尤其是 J 方向的圆角与内边距会挤占空间
- 大图高度用 `vw` 而非固定 rpx

#### Skyline 渲染引擎（可选）

对本方案有直接收益（更好的 grid 支持、更流畅的动画和手势），
但部分组件与 API 不兼容，需大量回归测试。

**建议**：一期不上，先用 WebView 渲染完成改造，二期再评估。

## 六、读代码后待决策清单

以下问题需要在掌握真实代码后回答，届时会补充为本文档的新章节：

1. **主基调选可爱还是精致**（J 路线 vs F 路线）——这决定所有页面的参数取值
2. **骨架型选 A 还是 E**——A 通用性强、E 情感强，也可能按用户状态动态切换
3. **每个页面的方向分配**——需要完整页面清单
4. **现有 Token 的兼容策略**——新增结构 Token 与现有色彩 Token 如何共存
5. **样例图的生产方式与排期**——这是最大的前置依赖
6. **改造是渐进替换还是整体重做**——取决于现有代码的组件化程度

## 附：最关键的三件事

如果时间和资源都不够，只做这三件：

1. **功能入口换成真实成品图** —— 解决「看不见结果就要付钱」这个致命问题
2. **阴影从无/黑色改为暖褐多层** —— 单条改动对「质感」提升最大，成本极低
3. **少选项字段从 picker 改为 chip 直选** —— 交互成本最低的体验提升

其余都是在这三件之上的增益。
