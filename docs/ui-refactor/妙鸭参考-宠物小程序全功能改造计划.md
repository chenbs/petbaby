# 妙鸭参考：宠物小程序全功能视觉改造计划

制定日期：2026-09-27。范围：`apps/miniprogram/app.json` 注册的全部页面、共享组件、四套主题与自定义底栏。参考资料为用户提供的 8 张妙鸭相机 2026 年页面截图；只借鉴信息层级、图像比例和操作位置，不复制人物素材、品牌识别或业务规则。本文件先于本轮实现建立；逐页改造应保持原事件、接口、状态和权限。

## 从截图提炼的规则

| 截图 | 可迁移的版式 | 宠物产品的处理 |
| --- | --- | --- |
| 1、2 发现流 | 顶部横向分类，双列竖图，图下标题与辅助信息，底栏贴底 | 宠物及作品照片为主体；不引入公开社区、热度或“做同款”伪功能 |
| 3 入口首页 | 一幅有辨识度的主视觉、少量快捷入口、横向推荐 | 第一屏先呈现当前宠物和“收好照片”；玩法列表接在陪伴内容后 |
| 4 工具集合 | 分类紧贴内容，大图呈现效果，操作就近 | 仅显示真实开放的玩法，分类来自现有目录，不显示不可用能力 |
| 5 创作 | 单一效果示例、明确上传操作、次级推荐在后 | 宠物照选择、授权和计费说明紧靠生成按钮；不隐藏必要字段 |
| 6 模板目录 | 紧凑筛选、双列纵向样片、图下名称及价格 | 模板、场景用真实样片；价格只取服务端规则，不写死数字 |
| 7 结果 | 大图沉浸展示，底部集中候选与主操作 | 候选、解锁、保存、分享依实际状态切换；保留水印与授权边界 |
| 8 等待 | 留白、居中状态、底部相关内容 | 显示真实排队/生成状态和取消入口；推荐只用已开放玩法 |

默认“宠物主场”皮肤采用白色或微冷白底、深墨绿正文、珊瑚粉主操作、薄荷绿辅助及少量暖黄提示。可爱感来自宠物照片、轻巧标签和触达反馈，不靠满屏彩色卡片。其余三套主题保留独立调色；所有页面继续只引用主题 token。图片比例：宠物首页主图 4:3、作品与模板 3:4，详情/候选按原图完整展示。所有标题、价格、作者/来源、状态放在图片外的实底区域；仅已验证安全区的简短操作可浮在图上。

## 逐页功能与目标

下表列出每个注册页的功能覆盖、第一视觉层级和必须验收的状态。页面顺序对应 `app.json`。

| 页面 | 必须保留的功能 | 目标排版及验收点 |
| --- | --- | --- |
| `index` 陪伴首页 | 当前宠物与切换、收照片、时间线、最近记录、里程碑、去年今日、玩法入口、主题切换 | 宠物主图和名字先于玩法；收照片为唯一强主操作；记录为轻量图片行；玩法用图区与文案区分离的双列流；无宠物/无图/加载失败均有明确反馈 |
| `create` 普通创作 | 宠物、照片、场景/参数、免费预览、提交 | 先看真实样片，随后按选择顺序排表单；上传和费用说明紧邻主操作；长表单不被底栏遮住 |
| `works` 作品柜 | 宠物/玩法/状态筛选、任务进度、失败重试、作品打开 | 筛选压为一行；任务列表次于完成作品，双列 3:4 图和图下信息；空/进行中/失败互不混淆 |
| `work` 作品详情 | 大图、版本、解锁、保存、分享 | 先完整看作品，底部实底操作区按状态只突出一个主操作；水印、权限、订单提示可见 |
| `orders` 订单 | 支付、刷新、退款与查询 | 金额、状态、时间同一信息行；待支付操作明显，退款入口与进度保持可见 |
| `me` 我的 | 宠物、额度、通知、所有功能导航 | 身份照与名字在前，额度压缩为信息行；入口分组而非堆卡；所有既有链接保留 |
| `pets` 宠物档案 | 切换、创建、编辑、生命周期、删除 | 每只宠物用影像身份行；编辑字段和确认保留，危险操作独立收纳 |
| `photos` 照片库 | 上传、查看、元数据编辑、批量管理、分页、失败重试 | 图像网格先行；浏览与管理模式分层，原图详情完整展示；上传状态可见 |
| `account` 账户 | 显示名、数据导出、注销/删除、隐私 | 简洁实底表单；危险操作分区且确认链完整 |
| `timeline` 时间线 | 按日期回看、里程碑、年度短片 | 照片和日期先于统计工具；年份切换、分页和生成反馈保留 |
| `health` 健康助手 | 分诊、体重、免疫驱虫、提醒、文档 | 当前宠物和紧急度先行；医疗免责声明与结论同屏，记录与操作分段 |
| `ai-create` AI 模板创作 | 玩法分类、模板/场景、宠物照、主人授权/照片、提交 | 横向分类加双列真实样片；选中态不遮样片；选择路径和授权/计费紧靠提交 |
| `ai-run` AI 结果 | 排队、进度、取消、失败重试、候选选择、重抽、解锁、保存、分享 | 等待态居中留白；候选完整显示，选定后大图沉浸，底部只保留当前状态操作 |
| `interactive-create` 互动创作 | 选图、场景、文案、创建 | 场景预览在表单前，照片/文案/权限字段连贯，提交不被键盘遮挡 |
| `interactive` 互动页 | 体验、编辑、分享、撤销、导出 | 内容画布优先，作者管理操作收在实底次级区；访客权限不变 |
| `video-create` 短片创作 | 选图排序、时长、音乐、字幕、创建 | 照片序列先于参数，三档时长与张数限制清楚；主操作固定在完成选择后 |
| `video` 短片项目 | 封面/播放、字幕、渲染、失败重试 | 封面第一，状态与字幕次之，渲染操作按状态出现 |
| `memorials` 纪念空间 | 创建、浏览、编辑、分享 | 封面和故事优先、安静留白；隐私、隐藏/恢复及分享操作可达 |
| `memorial-share` 纪念分享 | 访客阅读、照片、故事、失效提示 | 原比例照片与段落交替；无强营销按钮，失效与私密态明确 |
| `commerce` 会员年报 | 权益、方案比较、提醒、年报、购买 | 当前权益与真实价格先呈现，方案横向可比较；提醒和年报另起实底区 |
| `physical` 实体纪念品 | 作品选择、收件信息、订单/履约 | 作品图先于表单；价格、地址和履约状态完整，错误反馈不吞没输入 |
| `login` 登录 | 微信/账号登录、注册、退出、错误反馈 | 品牌与输入集中，状态明确；既有身份验证路径不变 |
| `theme` 主题 | 四套皮肤预览、选择、本地偏好 | 真实界面预览与色彩并列，当前选择可辨，切换即时生效 |

## 实施顺序与验收

1. 固定四皮肤语义 token、共享按钮/卡片/弹层和贴底底栏；保证四主题对比度及注入预算。
2. 打通首页、AI 模板、普通创作、等待/结果、作品列表/详情的连续路径，再逐页核对其余 17 页的同一排版规则。
3. 对每页检查加载、空、错误、长文字、横/竖/方图、320/375/430px 宽度、底部安全区和所有原功能事件；保留既有服务端价格、支付、授权、私密和 AI 标识。
4. 运行 `apps/miniprogram` 的 `pnpm validate` 和变更检查；使用微信开发者工具模拟器截图核对关键页，记录无法在本机验证的真实设备、真实支付和供应商结果。代码检查不能替代截图验收。

实施记录应写在文末，标注实际完成范围和未验证条件；本计划本身不视为上线批准。宠物人化 V2 效果继续维持 `pending-review`，本轮不发布、上传或改动审核状态。

## 2026-09-28 真机反馈后的修订与实施

用户真机截图显示首页玩法列表有文字和价格，却没有任何样图。原因是公开玩法样片直接把 `/api/plugin-samples/...` 相对路径交给小程序 `<image>`，真机解析和模拟器不同；加载失败又把 `heroUrl` 清空，最终只剩文字卡。修订目标是：首屏公开样片不依赖开发机局域网地址；用户没有宠物或照片时以明确标注的示例作品引导上传，不冒充用户宠物；所有有样片的玩法用图卡直接进入制作。

本轮将首页 7 个玩法、AI 目录公开样片、12 套写真场景及创作示例压缩为小程序内置 JPEG；清单由 `scripts/build-sample-assets.js` 从仓库已有自有素材生成，所有图均存在于包内。首页新增 AI 玩法图片入口，点击可带 `entryId/templateId/petId` 进入对应模板；艺术分类里不属于 12 套写真的水墨等模板也作为独立图卡保留入口。写真页只呈现当前玩法的双列样片；12 套场景改回双列，不再横向滑动。电影海报 3 种风格和时光画册 4 个主题以双列样片选择，选中值沿用既有草稿、提交字段。互动页的 3 个场景和短片创作页也补了直观示例。样片是演示效果，最终作品仍由用户照片制作。

`npm.cmd run validate` 通过结构校验和 62 项测试；微信开发者工具模拟器已截图核对首页、电影、画册、写真、AI 模板、独立艺术模板、互动和短片页，控制台无错误。本地截图位于 `.data/sample-*-20260928.png`。由于本机不能读取用户手机上的真机运行日志和网络请求，真机扫码预览仍须在手机上复核；若宠物私有照片仍缺失，应另查其鉴权下载链路、API 域名和 HTTPS 配置。当前本机 `config.local.js` 使用局域网 HTTP，正式发布还必须改为已备案、已加入微信合法域名的 HTTPS 地址。本次未上传体验版或发布。

## 2026-09-28 图片比例、写真入口与选照流程复核

本节覆盖并更新上文关于“写真仍在 AI 创建页内展示 12 套”和“模板统一 3:4”的实施描述。微信开发者工具截图发现公开模板源图主要为 9:16，插件主图为 16:10，写真场景为 3:4；此前生成脚本将三者强行裁为不同固定比例，页面又按单一比例显示，导致“和我合照”主体被截断。现在重建内置样片时保留原始方向，模板按竖版 9:16、横版 16:9 分类；首页模板竖图占单列、横图占双列，插件卡按 16:10，写真场景按 3:4。电影/画册成品样片保留其设计好的封面比例。短片封面和无宠物示例也按素材比例展示。

写真成为第四个底栏入口，独立页面按“柔软日常 / 去看世界 / 奇妙时刻”展示 12 套场景。点样片即进入照片阶段；其他 AI 模板和电影/画册也在选定样片后回到页面顶部展示宠物照片，底部操作固定，换样片可返回目录。照片授权、草稿、价格与原提交字段仍沿用既有业务逻辑。该页仅使用公开 `live` 场景；待审核的宠物人化 V2 未发布或改动状态。

模拟器在 384×830 截图核对：首页首屏及玩法区、无宠物示例、写真首屏与下半屏、和我合照选样片与选照片、电影海报与时光画册的样片和选照阶段、互动页与短片页；本地证据为 `.data/audit-after-*.png`。小程序结构为 24 页、4 套主题；`npm.cmd run validate` 的 64 项测试和 `git diff --check` 通过。截图是模拟器证据，真机显示和扫码预览仍待设备复核。
